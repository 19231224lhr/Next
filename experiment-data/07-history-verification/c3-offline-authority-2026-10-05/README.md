# C3：离线历史授权收据与普通证明对照

2026-10-05 · Mac Studio 实测 · 分支 `fix/partial-approval-reclamation`

本轮把“本地副本能安全读取修订”扩展为**不运行副本的读者也能验证具体修订曾获公共授权**，并完成与精简普通证明的成本对照。结果清楚区分两件事：普通证明足以完成历史赔付核对；修复证明额外认证具体修订正文与原完整 BlockID 的兼容性，需要额外字节和验证工作。

本轮实现与四配置、三进程实验完成。它提供了新接口、拒绝测试和可复核成本，**没有测出 CH 对普通经济查询的净性能优势，也不证明实际客户必需该表示能力**。这是按[预先方案](../../paper/review-2026-10-02/c3-value-resolution-2026-10-05/DECISION.txt)得到的采用边界，不再以反复改变模拟评审等级作为结案标准。

## 1. 消费者任务与实现

拟评估工作流是向独立审计者交付历史资金解释。审计者预先固定网络、委员会、规则、组织配置及 CH 公钥，不信任文件提供者，不读取其数据库，也不向其联网查询。

| 路径 | 交付材料 | 可核验结果 |
| --- | --- | --- |
| N*-lean | 真实赔付命令及执行结果、认证结果根的后继签名头、匹配的父证书 | T1：原坐标、来源输出、消费交易、责任组织、金额、决定与扣减、执行高度 |
| B-lean | 同一赔付执行证据，加修订正文、原提交证据、精确修复命令及执行证据 | 同一 T1，加 T2：精确版本曾获授权，且修订正文匹配原完整 BlockID |

N* 不携带原始或修订大正文，不等待修复。B 不重复携带原始/基准正文，也不另附正文内已有的父证书。两方均依赖既定委员会正确执行规则；不会一方信任执行结果、另一方被强制重放全部历史。N* 的组织信息由匹配 `ParentFact`、OutputID 和金额的已验签父证书推导；B 复用其已认证正文中的证书。

新库在 [receipt.go](../../../internal/redaction/receipt.go)：`VerifyCompensationReceipt(s)`、`VerifyHistoricalAuthorization` 和带原文转换复核的 `VerifyHistoricalReceipt`。实验导出与序列化消费者在 [receipt_experiment_test.go](../../../internal/redaction/receipt_experiment_test.go)。这是可运行库和参考消费者，没有新 RPC、密钥、状态树或共识字段；付款热路径没有调用这些新增入口。

### 时间语义

收据证明“曾获授权”，不证明最新修订、当前尚未偿还或不存在后来事件。真实旧修订在后续修订、偿还后仍应作为历史证据通过。需要当前状态的查询仍使用已验证执行快照；不能从证据包省略某事件推断该事件不存在。若调用者要求“截至 H”，须另用自己的可信前缀约束后继签名头的高度。

## 2. 授权绑定与安全核查

认证链是：固定 Trust → 后继签名头 → 原交易与结果根 → 精确命令及成功应用结果 → `Next` 摘要指定的精确正文。完整 BlockID 相容性另由正文与授权 part openings 重建，再验证原提交证据；相容性本身不授予权限。

条件性论证：在已有固定委员会正确执行、签名不可伪造、命令/结果/正文摘要绑定假设下，接受 T2 意味着该精确命令确曾成功应用且其 `Next` 指定被检查的正文。若正文未经对应授权却被接受，必须破坏上述认证绑定或正确执行假设。原提交验证再建立其与原完整身份的兼容性。此推论不包含最新性，也不将精简包没有提供的原始可变字节称为已重新验证；带原文的审计模式单独提供转换复核。

核心测试由真实 Engine/App 的 `FinalizeBlock` 和 `Commit` 产生正向执行结果；未手工把正向结果写成 `Applied=true`。负向测试覆盖：

- 篡改命令、结果根、正文摘要、槽位、网络、规则与委员会；
- 实际失败命令、实际成功但 `Applied=false` 的重复命令、其他命令的结果；
- 相容但没有对应授权的正文、后来版本替换早期版本、缓存 Block.Hash 对象被修改；
- 错误父证书、签名、组织/金额绑定；请求 B 时把 N 包作为降级输入；
- 验证失败不得进入缓存，缓存返回行不可修改内部副本。

每个正式配置都启动独立接收进程：空工作目录，仅经标准输入传入公有配置、证据及测试期望值；父应用数据库先关闭。接收器重做验证，不以期望值替代验证。这是实际进程隔离和无数据库依赖测试，不宣称操作系统沙箱。

[绑定审计](binding-audit.txt)、[核心审查](core-review.txt)、[实验审查及修正复核](measurement-review.txt)记录检查范围。核心审查建议的 T1 专项拒绝测试和 API 范围说明均已补齐；实验审查发现的 B 父证书重复传输/验签已移除后重测。

## 3. 测量设置与版本

- Apple M4 Max，16 核、64 GiB，macOS Darwin 25.6.0，Go 1.27.1；`GOMAXPROCS=16`、`GOGC=100`。
- `n=32/256` 笔目标块交易，`m=1/8` 个已赔付输入；真实修复批次与门限适配。
- 3 个独立实验进程。每种方法/配置预热 5 次，随后交替执行 30 次导出与完整解码验证；另测 100 次验后缓存句柄查询，合计 720 次正式重新验证和 2,400 次缓存查询。独立接收子进程负责功能隔离检查；计时在实验进程内执行同一验证函数，不计子进程启动和管道传输。
- 下表是**三个进程内 P50 的中位数**，方括号是三个 P50 的最小/最大值。总时间直接测量，不由阶段中位数相加。
- “重新验证”使用新解码对象且不复用验签结果，运行时和 OS 已热；不称冷磁盘或网络时延。导出始于已生成的内存证据，不含数据库发现/扫描、网络传输或最初证据获取。
- 验后缓存为相同的连续不可变经济行，句柄绑定配置、模式、包；只有完整验证后才能入缓存。两边每个配置均缓存同一批行，查询复制行。B 只缓存经济行时不等于缓存其完整 T2 正文。
- 起点 HEAD `594d237136325fecdea003a4cfe0638fca307514`，另含本轮未提交代码；不能仅用 HEAD 标识二进制。[实际源码清单](results/source-manifest.json)冻结 1,011 个文件的 SHA-256；[二进制哈希](results/binary-sha256.txt)与[环境](results/environment.txt)一并保存。Mac 实际源码逐文件验证后构建。

## 5. 论文能据此写什么

可以写：系统支持离线核验精确历史授权；B 在有界修订下保留原完整身份，具有可测的传输、验证和适配成本。新能力将接收者从“必须持有已执行副本”扩展为“持有独立可信配置与公开证据”；它是普通经济证明与修复证明共有的服务。

普通经济对账选择 N* 即可；需要交付**精确授权修订正文并检查原完整身份**时才使用 B。实验确定了这项表示能力的实现及代价，没有测得它对普通经济任务更快，也没有验证外部部署需求、集成成本节省或市场采用。C3 应作为与经济闭合配合的授权表示贡献，不再以赔付必需、普通索引无能为力或通用性能收益作为论据。

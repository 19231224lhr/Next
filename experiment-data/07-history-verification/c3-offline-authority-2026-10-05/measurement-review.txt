Finding to address before describing B as the strongest lean implementation
[P2] Remove duplicate B parent certificates and authentication.
receipt_experiment_test.go:228-235 exports Parents for both methods, although
B's mandatory Body (line 239) already contains those same parent certificates.
offlineRows authenticates external Parents at line 265 before B invokes
VerifyHistoricalAuthorization at line 322. The latter authenticates each revised
payment and its parent certificates through receipt.go:115 and 418-431.
Thus B pays an avoidable second parent-certificate wire copy, decoding and QC
verification. This affects packet bytes and cold/export timings, particularly
for m=8, and overstates the cost required for B's extra T2 guarantee.
N needs its standalone parent certificates. B can omit standalone Parents,
derive parent identities/issuer/amount from its already authenticated revised
payments, and bind Output/ParentFact/ConsumerFact to the common compensation
effects; preserve the existing target/decision/debit/funding checks. Do not add
cache admission before those crosschecks. Update B tamper construction and the
component schema description accordingly. If unchanged, label the comparison
as the current common-T1-prefix implementation, not strongest B-lean.

Measurement/schema assessment
- Four declared configurations, 30 measured cold samples per method after five
  prewarm samples, alternating method order (experiment:627,642-691).
  Cold timing includes fresh config/packet decode and complete verification;
  export and verify are paired wall-clock intervals. Correctness/oracle checks
  are outside the measured interval (681-689). Source evidence is retained in
  memory; export reuses the already serialized canonical B Body, then serializes
  its outer transport. This is not cold disk or original body regeneration.
- One hundred cache lookups use the identical cache strategy and alternate order
  (702-715). Each individual lookup is very short, so clock/allocator noise may
  dominate; treat small method ratios as noise rather than a speedup result.
- Setup timers cover actual adaptation/command construction, repair FinalizeBlock,
  and Commit (receipt_test.go:116-179,219-235); they exclude fixture construction
  and block/committee signing. They are single setup observations per process,
  not 30 independent adaptation samples.
- Packet component lengths are actual compact JSON/base64 wire lengths with
  envelope overhead (610-617). Public config bytes are reported separately.
  Cache retention is encoded {Handle,Rows} length (661-665), not Go heap/RSS or
  whole DB footprint. B full-body reuse requires its separately retained packet.
- Schema c3-offline-receipt-v1 preserves all raw paired cold and cached samples,
  environment, contracts, expected rows, setup observations and component bytes
  (566-604,627-636). Root must require successful process exit and validate four
  configurations, per-method sample counts/iteration coverage and component sums
  before aggregating. Aggregate per-process P50 then median/min/max across three
  independent processes; repeated queries within one process are not runs.

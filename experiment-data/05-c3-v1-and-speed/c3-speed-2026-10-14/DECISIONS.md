## Decisions so far

- Keep canonical parent-certificate freeze. A direct slice-copy shortcut could change malformed-input rejection; this is unnecessary for the measured gain.
- Reject replacing the wallet's full DirectCoin decode with a Recovered-only projection. It would accept malformed known fields that the current decoder rejects; an exact-byte cache has little reuse in a chain that spends each coin once.
- Defer a new trusted quorum accumulator: final QC verification is approximately 0.11 ms, and a larger verification API is not yet justified. Keep the existing final check.
- Do not infer end-to-end improvement from microbenchmarks or CPU savings. Stage 1 lowered sampled gateway CPU, but its first three short-chain comparisons did not show consistent latency improvement.
- Initial exploratory runs generated fresh identities for every arm. Subsequent paired runs share a pre-service fixture, retaining the same modulus, identities, funding and configuration. Run order still alternates. This reduces initialization variance and makes configuration equality explicit.
- Traces and CPU profiles are diagnostic runs, excluded from headline latency comparisons. Local clock spans are never subtracted across processes; stage medians are not added to explain an end-to-end median.

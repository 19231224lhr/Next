# 钱包准备下一笔请求：优化与实测

本轮在 `d2a711a` 上完成两项优化。独立七轮、每轮 1000 笔连续付款的正式对照中，准备后续请求的累计耗时中位数由 **552.091 ms 降至 484.756 ms，减少 12.2%**。七轮均降低；整条付款链中位时间减少约 **1.6%**，六轮更快、一轮更慢。

## 实际改动

1. **避免重复解析收款记录。** 钱包读出完整记录后，保存其 Final/Recovered 状态及原始字节的副本。随后的请求保存、到账状态查询仍读取数据库；只有当前全部字节完全一致才复用结果。更新、删除、读取失败、损坏记录均按原逻辑处理。缓存每钱包最多 256 条、4 MiB 的键与原始字节，不共享可修改的证书对象。
2. **去掉交易生成中重复的一次大整数校验。** 原先随机开口在 Commit 中检查一次，在 value 中再次检查。现在统一由 value 完成同一个完整检查，不合法则重新抽样。熵源、抽样分布、2048 位参数、完整域哈希、承诺公式和外部校验路径均未改变。

原有请求先保存再发送、输入占用、签名验证及 C3 费用检查保持原位置。没有改变认证轮次、担保额度、账本或费用托管规则。缓存优化可用于所有通过该钱包保存请求/查询状态的付款；本轮没有将收益归为同组织独占优势。

## 正式结果

`final-confirm7triples`：三种实现交替顺序运行，各七次，使用同一 CPU 0–7 预算与真实签名和服务。表中为每轮指标的中位数，不混用旧批次。

| 指标 | 本轮修改前 Next | 本轮修改后 Next | FastPay |
|---|---:|---:|---:|
| 准备第 2–1000 笔请求累计时间 | 552.091 ms | **484.756 ms** | 89.140 ms |
| 1000 笔依赖付款链完成时间 | 5098.265 ms | **5015.935 ms** | 6325.225 ms |
| 每轮收款延迟 P50 的中位数 | 3.701 ms | 3.672 ms | 6.206 ms |
| 每轮收款延迟 P95 的中位数 | 7.342 ms | 7.463 ms | 6.744 ms |

本轮修改省下约 67 ms 的累计准备时间，即平均每笔后续请求约 67 微秒。它不会使整条链快 12.2%，因为大部分总时间仍花在发送后的收款阶段。最终链时间范围为 4997–5135 ms，原版为 4879–5432 ms。

在这个单机配置中，最终 Next 的链完成时间比同批 FastPay 少约 **20.7%**，七轮均更短。这是保留新 C3 的当前系统结果，不能把整个优势归给本轮两项改动。FastPay 的请求准备仍明显更短，而且其 P95 更低；本轮没有消除这些差距。

全部 21 次正式运行均完成 1000 笔付款。Next 收款后继续执行后台公开清偿，所有运行都记录为 closure complete；FastPay 完成原生收款、资金守恒检查和计时后的续付探针。

## 单项与采样

缓存单项的三对试跑中，准备中位数 547.189→495.885 ms；随后独立七轮为 545.618→520.922 ms。缓存单项的链时间基本持平。两批均保留，未选用较漂亮的试跑替代正式结果。

单独诊断采样中，保存阶段内部的校验与锁处理累计时间由约 82 ms 降至 35 ms，符合减少完整 JSON 解析的预期。最终诊断仍显示交易生成约 130 ms、读收款记录约 68 ms、保存请求约 242 ms；保存包含编码、排队和提交，不能全部当成磁盘写入。采样会扰动运行，以上数字只用于定位，不代替正式对照结果。

承诺微基准五次运行的中位数约 88.6→77.9 微秒，分配次数 35→30。该 Windows 微基准有明显运行波动，完整实验才是最终性能依据。没有将不同批次的缓存收益和密码学微基准收益相加。

## 环境与验证

- AMD Ryzen AI 9 HX 370，Ubuntu/WSL，Go 1.27.1；CPU 0–7 为同一 WSL 四核/八线程预算。Next GOMAXPROCS=1，FastPay 使用上一轮已选定的单工作线程运行时版本。
- 服务内存存储；Next 钱包使用既有 ext4/NoSync 设置，FastPay 钱包在内存中。这是相同资源预算下的原生实现对照，并非完全相同的软件/持久化语义或 WAN 结果。
- 两个 Next 分支使用完全相同的 member/gateway/committee 二进制，仅替换 payctl 钱包客户端。未改变工作负载及收款计时终点。
- 最终 `go test -tags=comet_v3 -count=1 ./...` 通过。
- 最终钱包和 chameleon 包 `-race` 测试通过。缓存并发替换、字节所有权、失效、损坏记录、删除、存储失败及原有请求提交边界测试通过。
- 承诺公式、上下文绑定、原有阈值修复和协议测试通过。两次独立代码审查无待修复问题，见 `REVIEW.md`。

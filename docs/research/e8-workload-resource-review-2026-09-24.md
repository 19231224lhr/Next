# E8 实施与计量复核

评审会话：[评审两版支付系统](https://chatgpt.com/c/6aa8b2d7-b6f8-83ec-8e23-ea9f3b634e90)。GPT 意见用于独立复核，原始实验记录和代码才是结果依据。

## 正式方案

沿用已批准的 A/B/C 三配置，各 300 秒、三次新创世；统一工作点、同钱包基础设施、同初始输入规模。C 的短突增作为补充，不增加网络与复杂交易结构矩阵。方案见 [E8 计划](e8-workload-resource-plan-2026-09-24.md)。

## 预跑后的第二轮复核

向 GPT 提供了代码提交 `5389f43`、A/B/C 的 500 TPS 短预跑、计数开关对照、审计结果和计时边界。GPT 支持继续正式矩阵，并指出三处必须写清的地方：

1. **预热连续切换。** 实际是 10.24 秒预热后改变速率，并非恰好 2048 笔全部收尾之后才开始正式期；实际预热量、跨边界父子关系保留。
2. **闭环包含钱包公共观察。** 最初离线脚本的 Closed 仅取四成员观察时间最大值；已改为钱包公共观察与四成员观察的共同最大值，并补分析测试。原始时间戳不变；正式数据统一用修订后的脚本重建。
3. **截止不新发，已有请求可以重试。** 10 秒有界重试可以跨过输入截止，需区分逻辑付款与 HTTP 尝试。`QUORUM_UNAVAILABLE` 只说明尚未取得法定认证，不足以单独判定成员跟块滞后。

另确认：高比例后继在父 Commit 前发送，而委员会执行时缺失父输出很少，是一致的。父可以在两者之间提交，或在同一区块内先执行。该结果不能替代 E3 的高缺父比例或赔付压力测试。

A/B 是共享客户端设施下身份数量的比较；B/C 同时改变依赖关系、输入证据和处理路径，不把全部差额归给单一验签步骤。资源指标保留 HTTP 应用载荷、逻辑 KV 与 RSS 的不同边界。

## 新链根付款人修正

长序列离线检查发现：初版 C 使用“轮换收款人前一身份”作为每条新链根付款人，在 64 lane × 10 跳的周期中会造成部分身份多付费用；152,048 笔理想调度下，部分钱包需 89–90 个费用输入，而每钱包预备 82 个。这是驱动分配问题，不是系统总资金不足。

修正为每条 lane 沿用刚结束链的末收款人身份，从其另一笔最终 CAL 重开链；`Parent=-1`、`Hop=1`，原链末保持未花。GPT 确认输入依赖仍独立，并建议补入实际收款人避让与不同完成顺序回归；已补测试。A1/B1 的负载路径未变，可以保留，但须明确逐轮驱动哈希差异，不再声称全部正式轮同一二进制。正式 C 只使用修正版；旧 C 是预跑。

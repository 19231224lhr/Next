# E3：直接责任、赔付与历史输入修订

状态：经 GPT 讨论收敛的待执行方案，尚未实施或运行 E3。代码基线 `4838dcb`；保持 wire 4、用户自付 FUEL 和既定迟到规则。E1 已检验续花，E2 已检验有限资金周转；本实验检验异常时的担保兑现及额外处理成本。见[讨论记录](e3-liability-repair-review-2026-09-23.json)。

## 研究问题

使用未确认输出的付款已经成立后，前置交易仍未到达，系统能否正确确定直接责任、扣款一次、修订历史输入，并保持后继付款有效？异常处理对正常付款和后台收尾增加多少开销？

不改共识、责任归属、赔付期限或迟到政策。关闭 E2 自动补资与串行取证，初始 CAL 和工作权限固定且充足，用户 FUEL 充足。本轮不研究数据库恢复、资金最小化或最大 TPS。

## 已有基础与新增证据

已有 E2 用户自付控制验证了正常父子费用188 FUEL、赔付父子193 FUEL、CAL净赔付100及重复投递不重复收费。这些是历史结果，不能标成 E3 新测量。

现有 `TestPaymentRepairMonetaryReplay` 覆盖真实业务命令、磁盘 BlockStore 改写、原始历史重放、逐高度 AppHash/账本一致及迟到不恢复已赔本金；`TestRealBlockStoreRewriteAndOriginalReplay` 覆盖跨分片改写、标识保持和混版本拒绝。后者含测试授权回调，不能单独替代端到端业务授权证据。

E3 新增重点：真实多节点时间线、两组织直接责任归属、异常混合负载及成本。已有确定性测试复用，缺少的关键排列再补小测试，不为控制顺序修改共识。

## 第一层：少量可控序列

| 序列 | 核对内容 |
|---|---|
| 父在期限内到达 | 确认曾有缺失输入责任，随后正常解除；不赔付、不改写 |
| 父不到、后继继续付款 | 子及后继可用；到期仅从缺失输出对应 TXCer 的发行组织扣款；后继不回滚、不再次到账 |
| 赔付后父合法迟到 | 旧责任保持已赔、净支出保留；合法迟到实例按现行规则使用；旧 TXCer 不能重新消费 |
| 两组织三跳、孙先公共到达 | 当前缺失输出由其直接发行组织承担；父到达后，父自己的缺失输入另记责任，不追溯整条链作为一个赔付单位 |

每类网络序列独立运行三次。永不到达另保留一个有界观察案例，不强行清理未提交父交易留下的本地记录。针对父与 Repair 同块两种顺序、重复 Repair、同一旧块多次修订，以及未经授权修改金额/收款人，使用确定性夹具核对并保留断言；不以 sleep 假定同块顺序。

两组织案例中，G0签T0、G1签T1、T2先公共到达：缺T1输出的责任归G1；让T1在这项责任赔付前到达，则该项正常解除，T1仍缺T0输入时另建归G0的责任。这是两项独立责任，不是责任由G1转给G0。若T1在已赔后才到达，原项保持已赔，按迟到规则处理。

四节点核对：真实交易输入字节改变，稳定交易身份、DataHash 与完整 BlockID 保持；原付款授权和原区块 Commit 仍可验证；修订由后续已确认 RepairInput 授权，仅允许指定输入字段改变。原历史 AppHash 不回改。

重放按 `LoadOriginalBlock` 恢复初始版本，顺序执行到修复高度，再应用修订。比较逐高度状态和终态，不能把最新正文直接按普通交易重执行旧高度。独立轻客户端“最新修订证明”仍不属于本轮已实现能力。

## 第二层：异常混合负载

候选主矩阵为单组织四成员、一网关、四委员，三钱包独立两跳，每跳100 CAL。父通过真实成员取证并交给钱包，子收到父证书后走正常网关。受控父投递复用 E2 驱动，不产生可绕过门控的父 outbox 或其他补投者。

| 参数 | 计划值 |
|---|---|
| 输入率与时长 | 20两跳单位/秒，300秒；每轮计划6,000单位、12,000付款 |
| 异常比例 | 0%、1%、5%，按计划父交易分母，分别选0、60、300个 |
| 正常父 | 取得完整证书后约1秒投递；实际时刻记录，不假定一定形成缺口 |
| 异常父 | 保持不投递，待赔付和四节点物化均观察完成后再投递原父；永不到达单列小序列 |
| 期限 | 沿用现有30秒共识时间规则，不为实验缩短 |
| 收尾 | 输入结束后最多90秒；未完成按阶段列出，不删除失败样本 |
| 重复 | 三个固定种子，每个种子配对三档，共九轮；轮间重新创世，三档运行顺序轮换 |
| 存储 | 三档均采用现有磁盘 Comet＋委员会应用 bbolt，组织保持内存；验签、缓存和同步参数保持一致并记录 |

异常集合在运行前冻结，可在每个100单位分组内用种子选择1或5个，同种子的1%集合为5%子集，避免全挤到同一时间；这是人为设定的传播缺失，不称为拜占庭故障率。实际启动数、实际缺口数、实际赔付数分别报告。发生赔付后才放父，是验证异常闭环的受控注入，不代表随机网络迟到分布。

主矩阵释放迟到父，使其正常结算和本地状态有机会收尾；若修复未完成则不释放，并把失败保留。不能用迟到父抢先解决缺口后声称赔付成功。后继可用性必须在父释放前验证。

先对0%和5%档分别做约60秒输入的预跑并完成收尾，确认正常容量、确实触发修复、负载未被驱动窗口或资金限制；再冻结全部参数。128在途单位为起始候选，所需量估算包含正常周转和 `异常到达率×责任持续时间`，还需容纳修订与观察时间。窗口满须记录未启动数；正式轮不悄悄加窗口或资金。

CAL预置须覆盖最多300笔×100 CAL的30,000净损失。成员各只有组织Grant的2/3权限，保守按每人都签过全部受影响父付款估算，仅覆盖净支出残余就需45,000组织Grant，还须加正常及异常在途余量。各档用相同充分的初始配置，Execution/Bytes同样覆盖较长占用，具体值在预跑后、正式轮前记录，不能直接沿用E2的14,400高档。

磁盘主矩阵用于覆盖真实存储改写成本，不与已有内存模式2000 TPS结果直接横比。当前 `openCommitteeStore` 不支持磁盘BlockStore搭配应用Ephemeral；本轮使用已有磁盘配置，不放宽启动规则或增加新组合。若预跑显示20单位/秒已受其他资源限制，在正式轮前统一降低速率或调整一次统一配置并说明原因，不单独为异常组调参。

## 观测与验收

每个受影响单位记录四个独立终点：钱包可续花、公共付款成功、责任终结、四节点历史字节物化完成。到期依据缺口接受后的H+1锚定共识时间，不用钱包发送时间或本机30秒定时替代。

异常路径拆分：缺口建立→期限、到期→修复命令提交、提交→修复公共执行、执行→各节点物化。可记录输入/分片份额准备的子阶段；跨阶段采用同一采集机时钟与区块高度关联，协议期限仍以共识时间裁决。没有精确事件的阶段注明采样误差。

- 业务：计划/实际发送/READY/唯一公共成功/责任终结/物化数量；普通与异常付款的到账分位数分别统计；报告未启动与未完成原因。
- 责任：按唯一缺失 OutputID 与 RepairID 审计；一条链可有多项直接责任，同一责任不能重复扣款或重复收费。
- 资金：CAL余额、Reserved和净赔付；赔付不额外增加收款余额，迟到不恢复已损失本金。FUEL最大预留、实际费用、退款、报酬、销毁和组织代付分别核对。
- 开销：修复命令及修订字节数、修复成功次数/重试次数、CPU秒、后台待办数与最老年龄。CPU按完成付款及完成修复分别解释，不能简单将进程总CPU当作纯修复成本。
- 一致性：四委员相同高度状态一致，四份历史当前版本/正文摘要一致，未处理修订待办排空。主矩阵父最终释放后应无未解释临时占用，但保留Paid/Spent对应净支出，不要求含净支出残余的成员Reserved字段全部归零；永不到达案例的父本地残余单列。

若6,000单位全部完成、每项100 CAL且实际赔付R项，按当前费用规则核对 `CAL净赔付=100R`、`用户FUEL总费=188×6000+5R`。R使用实际成功赔付数，不用计划异常数量替代；小序列的额外后继/迟到实例消费另列，不混入此两跳公式。

成功判据是指定案例的账务与授权断言成立，混合负载中的已接纳业务按规则收尾，并完整报告对正常付款的影响。若部分组未完成，这是需定位的实验结果，不通过补资、清锁、删样本把它改成全绿。

## 1. 本文要回答的问题

诚实收款人尚未看到公共确认，只获得输出正文和 TXCer，就可以申请下一笔付款。需要论证的不是“签名看起来合法”，而是：该凭证绑定什么权利；同一输出是否可能被冲突消费；隐藏凭证是否仍有真实备付；来源缺失、赔付和迟到是否导致重复支付；历史输入替换是否改变原有所有权；何种条件下这些权利最终能够落实。

本轮采用三个层次：**协议层给条件定理，实现层给入口与状态转移对应，实验层给有限轨迹证据。** 三者相互支持，但不能互相冒充。吞吐、延迟、样本中的成功率，以及 GPT 的认可都不作为安全定理的前提。

## 3. 系统模型与审查边界

### 3.1 主体、权利与身份

每个组织固定四名独立验证成员，三份不同成员的有效签名构成 QC。每个组织在整次执行期间至多一名成员拜占庭，采用静态腐化；委员会另有独立的四成员、三票故障假设。不能把“同时最多一个恶意成员”解释成攻击者可先后取得所有人的密钥。网关和收集器可以失联、隐瞒、重复或重排材料，不能自行授予消费权或释放额度。用户、网络和未受信任 RPC 端点均可以恶意。

稳定交易核心由 `Body + Claims + Commitments` 构成，绑定网络、输入声明、确切输出、费用计划、组织和准入信息。`OwnerAuth` 对稳定身份签名，但不参与 TxID 的计算；它与组织认证、直接输入证书同属不可修订的固定提交材料。TXCer 绑定该事实与输出摘要，本身不额外增加一份资产。消费身份为 `SpendKey=(OutputID, Instance)`；普通凭证只授权实例 0。先赔付后合法来源到达时，实例 1 是另外创建的最终输出，旧凭证不能授权它。

输出指定唯一消费路由；正常跨组织付款通过新输出指定收款组织实现，不需要转移原发行责任。当前一笔快速付款的输入必须归同一消费组织裁决。任意组织自由抢签同一输入、跨不同路由原子合并，以及未经核查的历史慢速兼容路径不纳入本定理。

### 3.2 假设、实现要求与开放义务分列

| 类别 | 具体条件 | 为什么需要 |
| --- | --- | --- |
| 配置与初始状态 | 各诚实节点共享一致的可信固定注册表、规则和合法创世；按真实账户聚合的授权不超过资金；组织与委员会密钥身份明确 | 仅每份配置各自格式合法不够，不能同时信任同组织的冲突配置或一份资金的多套授权 |
| 标准密码假设 | 所有者／成员签名不可伪造；所用摘要和规范身份具有所需绑定性 | 将接受的认证绑定到诚实参与者实际批准的内容 |
| 运行期状态 | 诚实成员在签票前原子提交占用；不遗忘、不回滚、不擅自清锁；存储失败不发布半笔效果 | 保证两份冲突批准不能因并发或状态丢失同时产生 |
| 公共执行接口 | 委员会对同一原始命令序列提供一致、最终的顺序；应用确定执行；可信结果按连续块前缀观察 | 将公共 Paid、Settled、授权增量与本地释放对应 |
| 闭合资金入口 | 只有初始化、合法外部补资和规定的赔付可改变 CAL 备付；ProtectedCAL 配置覆盖所有备付账户 | 保持真实账户与剩余授权同源 |
| 修订接口 | 公共修复先认证精确范围和版本；物化只消费已提交授权；原始执行材料可获得 | 历史表示改变不能重新执行资金转移 |
| 尚未完成 | 自适应门限适配的完整安全游戏和归约；修改后 Comet 全路径精化；全 Go 机械证明 | 明确当前证据的缺口，不能用“已测试”消除 |

安全推导允许消息任意迟到、重复或不送达；完成性另外要求网络与调度进展。有限整数范围、固定配置和运行期原子性属于具体实现边界，不能把数学上的任意有限前缀解释成机器具有无限容量。实验内存／NoSync 配置不保证断电后恢复；丢状态后以同一成员身份继续签票不属于诚实执行。

### 3.3 四种时点不能混淆

1. **批准**：某成员占用输入和预算后产生一票，未必形成 QC。
2. **快速接收**：收款钱包验证输出与完整 TXCer，并在本地保存；尚非公共提交。
3. **公共执行**：委员会提交付款及其实际结果；来源可缺失，但必须建立对应直接义务。
4. **责任关闭／观察**：来源成立或赔付关闭义务，成员再按认证连续前缀恢复其原先占用的权限。

INSTALL 和重复投递是材料传播，不能直接触发本金释放。HTTP 接收成功、预检成功、提案准备成功均不等于公共执行成功。钱包重复收到同一凭证不能重新计一笔收入；请求和消费记录必须保持原有去重身份。

## 4. 状态机与安全目标

采用公共经济状态、各成员本地状态、证书签名集合、钱包状态及历史物理表示的联合状态。已产生三份签名即视为有效认证事实，是否组装、公开或写入委员会均不影响风险计入。

| 事件 | 必要前置检查 | 原子经济或权限效果 |
| --- | --- | --- |
| Approve / Sign | 用户授权、路由、输入／费用、父证书和 Worker 可用权限 | 输入锁、Approval、CAL／其他权限同事务；成功后签票 |
| Certify / Receive | 三个不同成员、相同 Fact、输出及收款人绑定 | 形成或保存凭证；公共资产不变 |
| Install / Submit | 完整材料与固定身份；重复幂等 | 传播及待办变化；不恢复预算 |
| Execute | 当前公共输入消费状态、组织授权、直接输入证书、费用与金额 | 消费输入、建立必要缺口、产生输出、收取阶段费、关闭已到来源义务 |
| Anchor | 确定的公共高度和时间 | 形成共同截止时间，不转移资产 |
| Repair | 到期且仍 Open；精确输入、版本、资金和费用检查 | 扣原发行组织备付、关闭缺口、记录 Paid、提交修订授权和 Task |
| Follow | 认证结果及连续前缀；必须存在本成员原 Approval | 按累计差额恢复原 Worker 权限，实际 Paid 不返还 |
| TopUp | 签名、旧额度、外部来源、ProtectedCAL 隔离、余额 | 来源扣款、目标增资及授权增加同事务 |
| Materialize | 已提交 Task、精确正文、版本与稳定根 | 只改变物理历史表示，公共经济投影不变 |

所有被拒绝的操作均不得留下部分业务修改；重复已生效操作不得再次产生经济效果。本模型不包含任意提现、授权缩减、成员迁移或清理未决锁；新增这些操作时必须补充归纳分支。

目标分别为：认证与所有权绑定、同实例唯一消费、潜在责任覆盖、CAL/FUEL 会计一致、修订范围与执行一致。最终完成属于独立进度命题，不嵌入这些不变量。

## 5. 核心论证

### 5.1 认证与唯一消费

诚实成员在签名前验证用户对稳定交易身份的授权，并核对输入路由、父证书、输出金额及费用。QC 至少包含两名诚实成员；排除签名伪造和绑定碰撞，接受的凭证对应诚实成员批准过的相同事实，不能把金额、收款人、网络或准入重新解释。

同一固定消费组织的两个三票集合至少交叠两人，其中至少一人诚实。该成员不能在保留 Candidate/Consumed 的情况下对同一实例批准两个冲突事实，故两个冲突有效 QC 不可能同时形成。公共 Execute 还按同一个实例身份串行检查消费。释放预算不删除消费记录；最终输入与证书输入不能绕开同一消费锁。

该性质不是“持有一份旧证书就一定还有余额”。合法持有人已经授权消费后的旧凭证仍可验证，但不再代表未消费权利；钱包和公共状态按实例去重。诚实收款人没有授权的消费则不能仅凭复制 TXCer 取得其所有权。

### 5.2 重叠权限与动态风险覆盖

定义 $g(c)$ 为事实 $c$ 唯一 `ResourceCAL` allocation 所绑定的 Grant；该对应由规范向量、认证摘要及 Grant 验证共同建立，不能将一张凭证重复归入多个 Grant。对 Grant $g$，设总授权为 $B_g$；成员总权限为 $s(B_g)=\lfloor2B_g/3\rfloor$，再排他分给 Worker。对证书事实 $c$ 定义 $a_c$ 为所有 CAL 输出金额之和，$p_c$ 为该证书自身输出已经发生的赔付，$z_c$ 表示该证书对应的原付款已经公共成立。父输入的赔付不能算成当前证书自身的 $p_c$。

**接口引理（认证先行）。** 任何令 $z_c$ 成立或 $p_c$ 增加的公共转移，在提交前都已存在 $c$ 的三份不同成员有效签名。自身成立路径经 `VerifyDirectSubmission` 检查本交易组织认证；赔付路径读取由此前后继付款验证直接输入证书后建立的 Open 义务。`InputTarget` 和修复执行不允许凭空创建该义务。这个性质是从实现到抽象事件的连接，不能仅把 `QC=true` 写成模型初始值而略过入口认证。

每个已登记输出仅从 Open 关闭为 Fulfilled 或 Repaired 一次，因此 $0\le p_c\le a_c$。令 $d_c$ 为由正常来源成立而解除的输出金额，$R_c$ 为剩余覆盖；已登记覆盖满足 $a_c=p_c+d_c+R_c$，未登记时公共三项为零。这个引理先由唯一输出关闭得到，不使用“资金充足”，从而避免循环论证。

自身付款原子成功执行完毕后，未赔输出创建最终实例 0，已消费实例仍保持 Consumed；已赔输出只创建最终实例 1，已有 Promise 全部关闭。因此 $z_c\Rightarrow R_c=0$，且此后 $p_c$ 不再增加。设诚实成员对该批准的残余为 $r_{m,c}=a_c-\mathrm{Applied}_{m,c}$，并定义：

$$w_c=\begin{cases}a_c,&z_c=0,\\p_c,&z_c=1.\end{cases}$$

在尊重因果与原子提交的执行序列中，对每个事实固定最早凑齐三名不同签署者时的见证集合 $W_c$；并发事件以固定成员索引打破平局。它是证明中的辅助量，不要求在线节点识别。公共成立需要自身组织认证，输出赔付需要后继输入携带其证书；两条入口分别建立认证先于经济变化。因此见证集合中的诚实批准早于该事实任何赔付或成立。原付款未成立时不释放 CAL，故 $r=a$；跟块落后仍保留 $a\ge p$；见证成员观察成立后，其连续前缀包含批准之后的全部相关赔付，释放 $a-p$ 后保留 $p$。于是对 $m\in W_c\cap H$ 有 $r_{m,c}\ge w_c$。各批准 CAL 残余之和等于相应 Worker Reserved；Available 与 Reserved 之和等于已观察授权的成员份额。补资只增加新旧份额差，不抹去旧占用。全部量在同一有限执行前缀上取值；公共成立指整笔应用转移成功提交，不是 CheckTx 接纳。

**本轮修正了此前的一个过强量词。** “任一后来签过该事实的诚实成员均满足 $r\ge w$”并不成立：未批准成员可先跟过赔付块，再补签父交易，随后只按本地 Paid=0 释放自身占用。真实代码已经复现该轨迹。见证集合不包含这名迟到签署者；原始两名诚实签署者仍保留对应赔款，整体上界无需依赖迟到者。这是证明范围修正，不是已经发现备付不足，也不需要为修正文字在快速路径增加历史查询。

令 $C_g=\{c:g(c)=g,\ c\text{已有三份不同成员有效签名}\}$，包括隐藏及尚未组装的凭证。固定选择三名诚实成员集合 $H$，每个三票证书至少由其中两人签过。对同一前缀 $t$，本地批准残余和 $L_{m,g}(t)\le s(B_{m,g}(t))\le s(B_g(t))$；后一个比较使用连续跟块及授权只增不减。省略共同时间下标，得到：

$$2Q_g:=2\sum_{c\in C_g}w_c
\le\sum_{m\in H}\sum_{c\in C_g:m\in W_c}r_{m,c}
\le\sum_{m\in H}\sum_{c:m\text{批准}c}r_{m,c}
\le3\lfloor2B_g/3\rfloor\le2B_g.$$

故 $Q_g\le B_g$。只有一票或两票的候选不进入左侧，但仍占用右侧，可能阻塞进度。即使已赔完而父交易仍未成立，成员也继续保留原残余；风险界不是一个自动释放算法。

### 5.3 从授权连接到真实备付

设 $S_g=\sum_{c\in C_g}p_c$ 为真实已支出，$V_g=\sum_{c\in C_g}R_c$ 为已登记剩余覆盖，$E_g=Q_g-S_g$ 为保守剩余风险。`register` 与 `completeOutput` 的增量分别维持 `Usage.Spent=ΣPaid`、`Usage.Reserved=ΣRemaining`，这是代码精化引理，不以字段名当作已经证明的定义。未成立时 $R_c\le a_c-p_c$；成立后 $R_c=0=w_c-p_c$。逐项求和得到 $V_g\le E_g\le B_g-S_g$。每个 Open 义务关联唯一仍 Open 的 Promise。对真实账户 $x$，必须将其支持的所有 Grant 聚合，不能各自引用整份余额：

$$\sum_{g:\,backing(g)=x}(B_g-S_g)\le A_x.$$

创世聚合检查建立此式；TopUp 从不属于任何受保护备付的外部来源转入，同时增加目标余额与授权；Repair 等额增加 $S_g$、减少 $A_x$；其他本模型入口不扣 CAL 备付。因此该式归纳保持。令 $D_x$ 为由账户 $x$ 负责的 Open 实际缺口，则：

$$\boxed{D_x\le\sum_{g\mapsto x}V_g\le\sum_{g\mapsto x}E_g
\le\sum_{g\mapsto x}(B_g-S_g)\le A_x.}$$

这同时覆盖公开缺口与尚未公开的潜在责任。实际损失 $S_g$ 不能因核销清零，也不能依靠增加抽象额度伪造补资。充足 CAL 只排除这一项余额不足；修复仍需要费用、材料、门限贡献和公共推进。

### 5.4 直接义务、迟到来源与资产守恒

令 $U$ 为最终且未消费的 CAL 实例总额，$A$ 为所有真实 CAL 账户余额，$D$ 为 Open 缺失输入金额。合法初始值为 $C_0$。一次付款消耗最终输入 $F$、缺失输入 $M$，输出合计 $O=F+M$；其中 $J$ 是本次来源到达正常关闭、此前已被后继消费且尚未赔付的输出金额。于是：

$$\Delta U=O-J-F=M-J,\quad\Delta D=M-J,\quad\Delta A=0.$$

金额 $a$ 的 Repair 满足 $\Delta A=\Delta D=-a,\Delta U=0$；TopUp 只在真实账户之间转资；其余传播、观察和物化不改变公共资产。因此：

$$\boxed{U+A-D=C_0.}$$

赔付补足已经执行的子付款来源，不再给子收款人增加一次余额。赔付后合法父交易迟到，实例 0 保持消费终态，实例 1 由父交易自己的输入执行支持；若父又依赖证书，则同一规则建立其直接缺口。该归纳不要求递归遍历完整祖先链。必须将守恒式与真实覆盖不等式合用，不能仅靠减去一个无资金支持的负债项宣称安全。

FUEL 单独核算。每项托管满足 $M=Held+Rewards+Burned+Refunded$。用户自付消费最终 FUEL 输入，找零与托管之和等于输入；可选代付从真实 FUEL 账户等额扣除预留，退款回到该账户。各费用阶段及每项直接义务的修复费用均防重。全局只计实际未消费输出、普通真实账户、Held、实际奖励账户和销毁计数，不重复加入累计 Refunded/Rewards。实际手续费是支出，不会通过核销恢复成用户或组织的新资产。

### 5.5 受限修订与共识接口

经济修复与物理修订是不同事件。Repair 在新块检查仍 Open、到期、原位置、基础版本及精确的新正文，将扣款、义务关闭和 Task 原子提交。`nextBody` 只替换指定 Funding/opening，并要求其余完整编码不变。Materialize 随后按已提交 Task 改写历史表示，不再次扣款；原始交易和后续 Repair 事件用于经济重放。

变色龙等式 $C=H(ctx,m)r^e=H(ctx,m')r'^e$ 只证明承诺一致。已公开的 $r'/r$ 可以对同上下文、同消息对复用，不能解释成新的三成员业务授权。授权必须来自公共修复状态及精确 Task。门限适配的完整自适应安全归约仍未完成。

实时共识分片固定 `revision=0, opening=1`，并验证对应已投票 PartSetHeader 的 Merkle 证明。固定 opening 后叶承诺为 $SHA256(H(ctx,bytes))$；排除相应绑定碰撞，同一根不能接纳不同原始分片正文。历史修订使用另一条受授权路径。该接口论证及已复现的重标记回归，不等同于对修改后 Comet 全部状态机路径的机器证明。

普通钱包／成员跟块验证的是已认证的公共交易身份与执行结果。它不能仅凭稳定交易哈希证明任意可变 Funding 字节是最新授权历史表示；独立“最新修订证明”需要额外的版本／授权接口，不应混入当前快速收款保证。

**经济投影非干扰引理。** 对固定部分与认证执行结果相同、且均能成功解码的两份普通付款表示，钱包和成员的跟块经济效果相同。钱包读取固定输出、所有者及结果中的 LateOutputs/FeeOutputs；成员读取固定 Fact、原批准、输入 Evidence、输出，以及结果中的 MissingInputs/FeeOutputs。两者不以可变 Funding/opening 决定经济变化。Repair 命令本身按完整字节进入共识，不属于这个普通付款投影。

这是一项经济安全边界，不是任意数据源下的可用性保证：不可解码的可变内容仍可能让跟块停止。新增 `TestBlockProofAuthenticatesProjectionNotMutableHistory` 用真实签名头确认普通证明的认证范围；`projection_source` 和 `projection_repair` 使用真实付款、成员批准、公共结果和钱包跟块，检查改变 opening 后的经济效果，并确认同样材料不能作为新付款通过验证。测试支持该接口事实，不代替对所有编码的非干扰证明。

门限文献还有一个参数范围需要明确。[Shoup](https://www.iacr.org/archive/eurocrypt2000/1807/18070209-new.pdf) 的 Protocol 1 定理以 $k=t+1$ 为条件；Protocol 2 才分析一般双参数授权目标。[CIRCL v1.6.5](https://raw.githubusercontent.com/cloudflare/circl/v1.6.5/tss/rsa/rsa_threshold.go) 明确实现 Protocol 1。本项目 $k=3,t=1$，且调用对象为群元素比值，因此不能直接引用前一定理来声称每个有效 opening 证明两名诚实成员新批准。这里只确认引用不充分，未据此复现攻击。**业务赔付授权由独立的公共 Repair 验证与提交承担；适配正确性、原始表示绑定和新目标适配不可伪造性是不同命题。**


**修订性质的依赖分离。** 不能把未完成的门限适配归约写成所有经济命题的共同缺口，也不能把经济守恒当作门限密码学已安全的证据。

| 性质 | 实际依赖 | 本轮结论 |
| --- | --- | --- |
| CAL/FUEL 守恒、义务至多赔付一次 | 一致公共顺序、当前状态守卫、原子提交、闭合资金入口 | 条件归纳；不依赖“每个 opening 都证明新的诚实份额参与” |
| 只替换目标 Funding、物化不重复扣款 | 精确正文检查、已提交 Revision/Task、可信存储接口 | 已审查并有回归支持 |
| 同一实时分片根绑定原始字节 | 固定 opening=1、FDH/SHA-256/Merkle 绑定及入口闭包 | 局部绑定引理；不等于整个共识状态机精化 |
| 新目标适配必须取得门限参与 | 明确的腐化与适配查询游戏，以及适用参数的密码学归约 | 尚未完成，不由正确合成测试替代 |
| 独立认证最新修订历史 | 公共 Repair 最终性、版本和数据可得性证明 | 普通跟块证明不提供此能力 |
| 修复最终完成 | 适配正确性、材料及份额可得、费用、公共推进与公平服务 | 进度前提，不是守恒结论 |

经济执行／重放使用原始付款和有序 Repair，Canonical 取已提交版本，物化只读取已提交 Task；这些是经济与表示隔离的接口。钱包／成员则采用前述投影非干扰条件，不能误写成它们验证了所有可变字节的修订授权。完整 Comet 精化另需核对 Block.Hash 与 PartSetHeader 的组合身份；本轮组件探针及其有限结论见[共识身份边界](security-redaction-consensus-wire4.md#44-稳定哈希与完整提交身份的边界)。

### 5.6 从内部不变量到收款权利

定义 `AuthRecv(w,o,c,j)` 为证书、输出及所有者验证后的本地保存。进一步以 `FreshRecv` 表示诚实所有者此前没有授权消费该实例的接收；它是执行历史条件，不是从 `ReceiveDirect` 返回值推导的全局新鲜性检查。仅首次写入某个钱包数据库不能排除同一私钥曾在别处合法签过消费。

**保护性使用命题。** 在本报告的模型与接口条件下，FreshRecv 接收的对象只能绑定同一输出和发行责任，未经所有者授权不能被合法消费。若后继付款获得新的有效认证并成功公共执行，则其输入要么引用已成立输出，要么在同一转移中消费实例 0、建立唯一直接义务和等额缺口，同时产生子输出。§5.2–5.3 保障责任覆盖；正常来源到达、赔付和修订不能篡改已认证输出或已执行子输出的所有者字段，不能未经所有者授权消费该实例，也不重复支付。用户自行授权后继转账仍可正常改变资产归属。

证明将绑定／所有者授权、唯一消费、原子责任建立、潜在覆盖和守恒按同一轨迹组合；不把“后继成功”偷偷写成无条件进度。它补上用户对象与内部账目之间的连接，但仍不是“任意已接收凭证最终可取回余额”的完整理想支付功能精化。

**直接证据局部化推论。** 在其他动态守卫满足时，后继公共执行只验证直接输入证据，不要求祖先交易预先成立。每项执行时仍缺失的输入分别建立唯一原发行责任。这解释了无需等待祖先确认的设计收益，不免除费用、额度、消费状态和调度条件。


**条件自转为最终输出路径。** 收款人持有金额 $v$ 的输出正文、完整 TXCer 及索引和所有者密钥，可以构造一笔普通后继付款，把同额 CAL 付给自己。这不需要新增“兑现”接口。前提是固定消费组织、配置、规则和 Grant 有效；本人未授权冲突消费；费用来自足够且已被相关节点观察到的最终 FUEL，并路由至该消费组织；三个诚实成员批准时指定 Worker 的 CAL、Execution、Bytes 权限充足；公共 Grant/Usage 与其他动态守卫通过；完整子交易得到传播及公平执行。公开成功后生成的是**新的子交易最终输出**，不是把原快速输出改成已确认。父尚未成立时，同次转移消费原实例 0 并建立原发行组织的唯一直接义务。

该构造只需直接输出证书，不需父交易完整 DirectSubmission 或祖先正文。它给出明确服务条件下的可达路径，不证明资源在任意恶意负载下始终可用、父交易必然提交或用户无需付 FUEL。已有 `TestDirectOwnerFeeRefundAfterParentArrives` 的自付场景补充断言：父未提交时，同所有者的新 CAL 输出已经 Final，直接义务为 Open，组织 FUEL 未扣；之后父到达关闭义务并退款。此规则级回归使用真实证书验证，未运行成员取证服务与网络 BFT，不能替代这些进度前提。

## 6. 条件终结性与已知停滞

新付款取证要求足够诚实响应者、无永久冲突的合法输入、所选 Worker 各维可用额度和可用费用。已有完整付款正常上链还要求材料可得、至少一名持续投递者以及委员会公平纳入。缺失输入终结要求父来源合法到达，或者共同时间推进至到期后有修复构造者、足够门限贡献、费用和公平执行。跟块观察是其后的独立进度条件。

这些是各条路径的进度前提，还需相应任务得到公平调度与持续重试；本文不据此声称已经证明真实调度器的全程序活性。异步网络下不提供统一的完成时间上界。公平处理不能替代资金、材料或可执行条件。仅收到输出与证书可用于申请后继付款，但不保证能够重建原付款的全部提交材料。

截止时间先由公共高度／时间锚定。修复工作器发现公共时间尚未到期时，可投递 ClockTick 推进公共时间；本地墙钟超时不会直接扣款。该命令仍须进入公共顺序。当前修复扫描和并发均有界，不能仅因存在重试循环就推出每项任务必获服务；坏任务阻塞前段扫描、公平性及缺失材料都属于进度审查范围。

当前已知限制包括局部票长期占用、Worker 份额不自动调配、未使用 Promise 不自动过期、网关在完整材料传播前失联、历史随运行增长，以及实验状态丢失后的恢复。它们需要作为限制出现，而非用更宽泛的“正常情况下安全”掩盖。

| E3 | 正常、缺失、赔付和迟到顺序；原始经济重放 | 门限原语安全或任意历史同步路径正确 |
| E4、E5 | 指定冲突、防重和单成员故障；材料可得性窗口 | 所有拜占庭攻击、任意恢复，或两种交付门槛安全保证等价 |
| E6 | 指定环境的外部实现延迟参考 | 与 Lightning 的保障等价或安全性优势 |
| E8 | 实际负载下的工作、网络及历史成本 | 无限期资源有界或一般活性 |
| 有限模型 | 原 16 个配置合计 268,965 状态、1,227,450 转移；七类错误规则产生反例。本轮另增迟到批准配置，393,718 状态、1,848,009 转移 | 任意参数、各模块自动组合或全程序证明；两组统计不能冒充一个整体模型 |
| 真实规则与跨层回归 | 18 个三跳账务配置、部分输出、10 个成员组合场景及修订回归；新增迟到补签、普通块证明的经济投影边界 | 这些测试本身覆盖完整网络、BFT 与全部密码学行为 |

详细数据沿用 [E1–E8 索引](../experiments/README.md)、[有限模型报告](security-model-validation-2026-09-26.md)和[组合验证记录](security-composition-wire4.md)。补资隔离修复与原 E2 正常配置实验属于不同证据，不能用后者替代前者的反例和回归。

本轮新增记录见[本轮验证清单](security-analysis-validation-2026-09-27/README.md)。E3 的“CAL 临时残余为零”也不等于本金占用全部清零：测量代码定义临时残余为 `Charged − Released − NetSpent`，而批准保留的总残余为 `Charged − Released`。永不到达且已经赔款的父交易可同时满足临时残余为零、真实 Paid 仍占用。各组实验使用当时版本及各自存储配置，不统一改写为当前安全分支或全部持久化实验。

### 7.3 尚不完善的地方与适度改进顺序

| 优先级 | 问题 | 最小后续工作 | 对快速路径的影响 |
| --- | --- | --- | --- |
| 论文必需 | 保护性使用已论证，但不能等同最终可取回 | 保留接收／授权／消费／终结定义及当前连接引理；若主张最终可兑现，另给理想支付精化和明确进度条件 | 纯分析，无在线开销 |
| 论文必需 | 修订密码学与修改后共识仍有未证接口 | 完成适配查询游戏和授权闭包说明，逐入口精化原始表示、公共授权和物化；不得用稳定哈希代替授权证据 | 优先离线证明；发现具体缺口才作最小修复 |
| 可用性改进 | 局部票可长期占用，共享组织受合法但中止的候选拖累 | 先定义安全的“尚未形成证书”证明或有序取消协议，再考虑回收；不能按本地超时直接解锁 | 可能需要异常路径协议，不作为本轮新增机制 |
| 可用性改进 | 完整材料传播前交付，网关失联可阻断原付款自主提交 | 比较由钱包保留完整提交材料，或采用 E5 已有的副本门槛；先确定希望保证哪一种故障行为 | 前者增加材料体积；后者可能增加交付等待，不能承诺免费 |
| 经济设计 | 先赔后迟到可使原输出所有者获益，组织承担真实损失 | 单列延迟策略与追偿问题；若要宣称抗套利或盈利，需要另外建模和规则设计 | 不为本轮论文擅自改变已采用的迟到语义 |
| 部署扩展 | 状态不耐久、静态成员、历史增长、Worker 份额不自动调配 | 按实际部署需求分别处理；当前实验模型明确排除恢复和无限运行 | 不把产品级恢复工程塞入正常付款路径 |

两项曾实际复现的问题已有专门修复：补资账户重合／挪用受保护备付，以及修订分片重标记为原始分片的入口缺口。它们说明为什么需要实现级回归，也说明实验全部成功不等于没有安全缺陷。本轮不将已知可用性限制自动升级成新协议改造，不为“完整分析”强行增加在线检查。

# 安全模型与实现回归：第一轮验证

> 2026-09-26 · `security-analysis` · 生产基线 `re@8d1590b`。本轮只增加 `_test.go` 和文档，没有修改节点、协议、配置或依赖。模型采用标准库 Go 确定性广度优先搜索。

**结论：** 所声明的 16 个有限模型配置均完成可达状态穷尽，未发现不变量违例；七种刻意错误规则均产生反例。实际规则新增的账务交错和受限修订回归通过。本结果补强[条件安全论证](security-argument-wire4.md)，不是全系统形式化安全证明。

## 1. 模型与结果

搜索保存已见状态和父边，遇到违例输出最短轨迹；达到状态上限会明确失败，不报告“穷尽”。搜索器自身测试核对最短路径、穷尽与截断。各模型独立，不导入生产规则作为转移或判定器。

| 模型 | 有限配置与转移范围 | 状态数 | 转移数 | 检查内容 |
| --- | --- | ---: | ---: | --- |
| 签署与隐藏 QC | 四成员、至多一恶意、三票；两个 Fact，每笔 cap=2；B=2/3/4/6，分别共享或不共享输入，8 配置 | 合计 6,632 | 合计 27,788 | 诚实成员批准后签票、不遗忘冲突锁；已存在三票即计入 QC，不依赖公开；按 Fact 计风险不超 B |
| 责任与本地释放 | 一个有效但可未公开的 QC、两个单位输出；批准/签名掩码 `0011/1011`、`0111/0111`、`0111/1011` | 每配置 87,423 | 每配置 399,829 | Promise 与已消费义务分离；先消费、赔付、来源成立、迟到实例、最终输出再消费、一次真实补资、三个成员任意速度连续跟块 |
| 账户覆盖 | 两 Grant 分别或共同指向备付账户；外部资金 1/2；各有一次补资及一次支出，4 配置 | 12/16/12/16 | 32/48/32/48 | 总额守恒；按真实账户聚合 `Σ(B−Spent)≤余额`；资金不足不补资，备付不可作来源 |
| 用户 FUEL | 一个最终输入 10、预留 4、找零 6；正常或一次赔付；收费、销毁、退款 | 8 | 15 | 输入、找零、退款、Held、实际奖励及销毁守恒；关闭后不再收费或退款 |

共 **268,965 个状态、1,227,450 条转移**，是各配置检查量之和，不是一个组合模型的状态数。完整输出见[模型日志](security-model-validation-2026-09-26/model.txt)。重复事件在模型中是同身份的无状态变化转移，具体编码、防重键及数据库行为另由实现测试检查。

生命周期初始账务为最终原输入 2、备付 3、外部补资来源 3；检查 `最终未消费 CAL + 账户资金 − Open 缺口 = 8`。原来源成立前输入仍计为真实资产；后继先成立增加输出和缺口；赔付减少备付与缺口；迟到来源消耗原输入并依规则产生实例 1。实际赔付不会因释放被恢复成未损失本金。

局部模型显式区分批准与签名：掩码 bit 0–2 是诚实成员，bit 3 是恶意成员；只有恶意成员允许未经批准直接签名，诚实成员始终满足 `Signed ⇒ Approved`。两名诚实成员加一名恶意成员即可成证；第三名诚实成员可能没有批准，也可能已批准但未进入 QC。只返还成员自己确实占用的额度。跟块严格读取同一公共序列的前缀，可以落后，不能跳到未来状态。未使用输出也可能已有 Promise，不能仅因当前 Open 义务数量为零便释放整张证书。

## 2. 反向校验

这些错误只存在于测试模型开关中，未加入生产代码。

| 故意破坏的规则 | 检查器发现 |
| --- | --- |
| 允许诚实成员遗忘已签冲突锁 | 同输入形成两个三票 QC |
| 绕过诚实成员签署预算 | 已存在 QC 的合计风险超过真实初始预算 |
| 自身成立后返还已赔 Paid | 局部残余小于仍必须保留的实际支出 |
| 赔付后、来源成立前提前释放 | 尚未解除的证书风险失去残余覆盖 |
| 允许其他受保护备付成为补资来源 | 总钱数未变，但来源账户的授权覆盖不足 |
| 自转账使用两次旧余额，后写覆盖先写 | 凭空增加账户余额 |
| 关闭后再次退款 | FUEL 总额增加 |

还固定了隐藏 QC 与局部票残留的场景：证书已经存在，其他候选仍可能占住成员额度。这是已知进度边界，不能因为模型没有双花就宣称任意并发都不会卡住。

## 3. 与真实代码连接

新增 [security_projection_test.go](../../internal/rules/security_projection_test.go) 直接执行现有 Go 规则：

- **18 个三跳场景：** 父 P、子 C、孙 G 的六种到达顺序，加三种含赔付与真实补资的交错，各对照用户自付／账户付费；每个成功操作再执行一次。
- **部分输出场景：** 父分为两个 50 CAL 输出；左侧先消费并赔付，右侧尚未使用时 Promise 仍保留 50；父迟到后 Paid=50、Discharged=50、Remaining=0，左侧实例 1 成立；右侧随后按最终输入消费，不再允许为旧证书新增赔付。
- **独立资产投影：** 从一次一致读取中的真实 Creation/Spend、账户、Open 义务、费用 Held、实际奖励及销毁累计守恒量。找零和退款计入真实未消费输出，不把累计 Refunded/Rewards 字段再当一份钱。逐次核对存储的 Gap 与实际 Open 金额。

这些测试调用真实规则与 Store，但并非完整网络／BFT 实验，也不替代全部错误分支、账户别名和并发实现的精化证明。

扩充 [payment_test.go](../../internal/redaction/payment_test.go) 的受限修订拒绝用例：即使合法替换的 Funding opening 仍验证通过，篡改 owner 授权、组织授权或输入 TXCer 仍必须整体拒绝且无状态变更。原有输出、版本、目标交易、分片、同高度规则、经济重放及物化幂等测试继续通过。测试不赋予“哈希碰撞有效即可任意改交易”的权限。

## 4. 模型之间尚未证明的连接

| 连接 | 本轮做到了什么 | 尚需论证 |
| --- | --- | --- |
| 投票模型 → 生命周期 | 区分 Fact、cap、批准集合和签名集合；测试有效三票起点 | 对任意批准／公开／释放交错建立统一精化与归纳关系 |
| 生命周期 → 账户 | 区分 Paid、Spent、剩余责任和真实支出；真实规则交错检查总资产 | 完整枚举所有入口，证明每项经济支出恰好对应正确 Grant 与真实账户 |
| 公共状态 → 成员 | 模拟不同连续前缀、实际占用者累计释放；运行既有成员测试 | Store 后端、错误返回、并发和完整状态投影的对应 |
| 经济授权 → 历史物化 | 合法 Funding 替换与非目标字段拒绝；重放与幂等回归 | 门限原语、初始化、公开适配的密码学归约；修改后 Comet 的同步／历史验证性质 |

四个模型不能直接拼成一个完整证明。没有覆盖任意成员数、多 Worker 调配、动态成员、崩溃恢复、任意故障公平性和一般活性。金额及对象数有界；模型中的原子转移也是待映射到实现的假设。内存实验节点状态不回滚的前提与既有文档一致。

## 6. 可用于论文的结论

> 我们对固定四成员三票配置下的签署预算、直接责任、本地权限释放、备付隔离及费用守恒建立分解的有限状态模型。在所声明的有界范围内穷尽检查未发现违例，并通过七类错误规则验证检查器能够给出反例。真实状态机的三跳账务、部分输出与受限修订测试进一步核对了关键实现路径。模型组合、完整实现精化及修订密码学仍作为独立证明义务。

侧边栏 GPT 的本轮评审促成了 Promise/义务分离、两诚实加一恶意签票、未批准成员不返还、迟到实例与费用资产分列等补充。它是交叉讨论输入，不是同行评审或形式证明。后续应完善一般参数下的归纳推导与接口映射，不通过无限追加成功实验替代证明。

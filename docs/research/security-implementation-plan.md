# wire 4 安全分析与最小修正计划

> 分支：`security-analysis`；起点：`re@8d1590b`。本分支用于模型、回归和必要的业务修正，暂不合并到 `re`。执行方式为当前会话逐项推进，不启动子代理。

**目标：** 将[条件安全论证](security-argument-wire4.md)转化为可复查的状态模型、关键代码对应及反例回归；只有发现实际违例才修改业务逻辑。

**实现方式：** 使用现有 Go 工具链及测试设施。离线模型与测试不进入节点二进制；生产修复留在实际负责该状态转换的函数中，不引入新的在线安全检查框架。

## 1. 方案选择与性能约束

采用“离线模型 → 实现回归 → 最小修复 → 必要的性能对照”。仅扩写文档不足以检查交错；先重构运行时或到处增加检查，会改变尚未充分理解的行为并增加验证成本。

- 保留一轮取证、后台 INSTALL、钱包与成员自行跟块的现行流程。
- 不为分析新增正常付款的网络轮次、全局锁、同步写盘、逐笔全历史扫描或重复验签。
- 不增设持久化恢复、动态成员或通用模型框架。
- 安全检查不能为了维持旧成绩被绕过；如果正确性确实需要热路径成本，应明确报告并测量。
- 测试、模型及文档本身不改变生产运行时。业务修正不能事先承诺零性能损失，也不能以“未发现统计差异”声称严格零开销。

## 3. 第一模块：签署预算与真实备付模型

**新增位置：** `tools/securitymodel/model_test.go`。仅使用 Go 标准库，模型不导入生产规则作为转移或判定器；与生产代码的关系写入论证文档。

先采用固定四成员、至多一个恶意成员、三票、一个 Grant、一个 Worker 的小模型；把“两个 Grant 共用账户”作为独立场景，避免一次展开整个系统。小模型不证明 Worker 自动调配或任意规模活性。

模型必须分开保存：

- 每成员的 Candidate、Approval、cap、Applied、Available/Reserved，以及已观察的公共前缀。
- 已存在签名与是否公开提交：三份票已存在就计入有效证书，不以公开登记为准。
- 证书自身的 Settled/Paid 与每输出直接责任；不把父输入赔付算成当前证书的 Paid。
- 真实外部余额、备付余额、Grant 总额、Spent，以及消息／跟块进度。

转移覆盖批准、形成或隐藏证书、登记、正常来源到达、赔付、连续跟块、真实补资及重复事件。消息允许迟到与重复；跟块可以落后，但不能把认证前缀之外的未来状态当作当前状态。

独立检查四条关系：

1. 同实例不出现冲突有效 QC，失败批准不改变任何余额或锁。
2. 所有局部批准残余与 Worker Reserved 对应，诚实签署者残余 `r >= w`。
3. 按 Fact 去重的有效证书风险不超过 Grant；隐藏证书和局部票不能漏计。
4. 对同一真实账户，所有 Grant 的 `B-Spent` 总和不超过真实余额；补资不得使用任何受保护备付作为来源。

- [ ] 增加刻意错误规则作反向检查，例如提前释放已赔残余、允许补资挪用其他备付；检查器必须找出对应反例。
- [ ] 检查合法规则在所声明有限范围内是否保持不变量；达到资源或深度限制时明确标为未穷尽。
- [ ] 将反例或通过范围写回论证，不将有限检查称为一般证明。

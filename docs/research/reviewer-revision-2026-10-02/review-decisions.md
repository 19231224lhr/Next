# 评审意见的核验与最终裁决

本轮与用户指定的 Claude Sonnet 5.5 Medium 完成十轮集中讨论。逐轮提供实际规则、反例、代码守卫、构建配置和原始测量，再核对反馈。讨论用于发现和审查问题；论文证据来自规则推导、代码测试与实验记录，不来自模型对论文的认可。

## 三项实质修改

### 1. 从总量守恒推进到条件延迟中性

旧规则在已赔付来源迟到时另建用户实例。它可以保持总量守恒，却让用户与发行者的最终本金分配依赖提交时机。本轮实现 `Open → Repaired → Recovered`：来源成功执行时偿还实际赔付者，不再向用户生成第二份本金。

对同一有限付款集合，在全部相关来源最终成功执行、合法输入选择和输出保持一致的条件下，证明最终用户 CAL 分配及各组织备付与来源到达顺序无关。费用及修订元数据不要求相同；永久缺失来源仍造成真实备付损失。

该性质有 192 条账本交错轨迹、三组成对分配实验、九轮恢复矩阵和两项缺失/跨组织控制支持。它们分别检验不同层次，不合并成“整套实现机械证明”。

### 2. 明确经济责任与历史表示的分工

直接责任使已授权的后继能够推进；变色龙适配支持受限资金来源表示在完整 BlockID 下更新。追加赔付也可以完成经济补足，因此不能把所有非级联经济效果都归功于变色龙哈希。

当前代码在赔付前验证逻辑修订及门限适配材料，赔付与 Task 在同一公共事务提交，物理安装随后执行。论文保留这一实际依赖，不写成“当前赔付完全独立于适配”。普通钱包与重放读取原始命令；Canonical、后续修复构造和物化是已实现的修订历史读者。

### 3. 补充存储匹配的连续续花证据

除新的内存配置 100 跳链外，新增九轮全磁盘部署的连续链控制。保留成员同步提交时，续花中位 4.471 秒，逐跳等待中位 65.013 秒；两者的付款集合、钱包配置和共识参数相同。该对照直接展示跳间等待被移出付款关键路径的效果。它与成员 NoSync、内存配置分别列出，不用部署差异冒充协议收益。

## 经核对未采纳的意见

| 意见 | 最终处理 |
| --- | --- |
| 修订正文的真实性必须依赖适配算法的自适应不可伪造性 | 不采用该因果表述。公共守卫导出允许修改的字节及完整身份，安装要求与已提交 Task 正文逐字节相等。兼容 opening 本身不授予修改权。Claude 在获得安装代码后撤回原判断。原始绑定、签名与公共认证假设仍明确保留。 |
| 第三项贡献必须在标题上标为“实现贡献” | 不强制贴标签。正文准确写出完整身份下的授权表示更新、合批和直达物化，不宣称新的密码学原语。 |
| 为本轮建立独立追加式实现、外部历史读者和新的恢复系统 | 不扩大范围。能力对照写清楚，代码尚未实现的模式不作为实验对手。 |
| 当前评审认可可以视作录用或完全安全证明 | 不采用。投稿仍由期刊评审判断，当前安全结论依赖论文明确的模型条件。 |

## 数据与文字校准

- 当前回收/续花为用户自付 FUEL；存储负载、正常/修复背景负载与短 TPS 轮采用组织代付。
- 历史 E1–E8 数据标为归档构建；本轮新规则成绩单列。
- 30,000 笔短轮的含排空速率为 1,750–1,887 TPS，并列发送滞后；不改写为持续均匀承接 2,000 TPS。
- 修复背景下 P95 增长保留，不能用相近 P50 推出无干扰。
- 补充表已替换为当前九轮恢复数据，费用表统一单位和小数位。
- 中文为对应阅读版；英文主稿采用 IEEEtran。作者单位沿用用户要求的占位，投稿前应填写真实单位及作者联系信息。

## 本轮完成后优先事项

先由作者通读最终主稿与补充材料，核实贡献定位、模型条件及单位信息。若继续增强第三项研究论证，最有针对性的工作是为一个真实修订历史读取任务实现匹配的追加式对照；这属于后续研究选择，不冒充本轮已完成的实验证据。无需为了评审过程继续扩展无关负载矩阵。

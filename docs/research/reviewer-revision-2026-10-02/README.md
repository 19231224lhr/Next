## 新规则核心

`Open → Fulfilled`，或者 `Open → Repaired → Recovered`。赔付扣实际原发行组织账户；迟到来源成功执行时，偿还同一发行者。账户增加与对应授权净支出减少原子提交，Grant 不增加。未最终来源的直接责任不向后代递归展开。

成员只根据自己的批准与扣额恢复权限：观察自身付款成功后，累计恢复目标为 `cap−(local Paid−local Recovered)`。钱包保存不可消费的 Recovered 终态，旧 TXCer 不会复活它。历史修订和原始命令重放不重复经济效果。

## 验证口径

复现步骤及脚本依赖见 [复现入口](reproduce.md)。

- 有限模型：单证书、两个输出及迟到补签者等有限状态；不是全实现机械证明。
- Go 回归：普通/部分输出、跨组织、同块先后、批修复、回款防重、钱包终态、原始历史重放。
- Mac 网络验证：真实四委员、成员与网关进程，独立钱包状态；逐轮新创世。
- 延迟中性：比较相同付款集合的最终用户 CAL 分配和组织备付；不要求 FUEL 费用相同，不把永久失踪来源纳入“最终全回款”前提。
- 对修复并发造成的尾延迟变化如实给出，不把中位延迟稳定写成无干扰。

# 独立评审修订：实验报告

本报告验证 `d99ec92` 的迟到来源回收语义，并记录与论文相关的配置对照。它不改写 E1–E8 的历史原始数据。所有 Mac 轮次在 M4 Max / 16 核 / 64 GiB 的同一台主机上运行，每轮重新创世，四委员使用独立进程。当前分支为 `feat/review-source-recovery`。

## 1. 这次解决了什么

旧规则在担保组织赔付后，允许迟到来源产生额外用户实例。虽然总量可以守恒，但提交时机可以改变最终资金归属。新规则让迟到来源偿还实际赔付的组织：`Open → Repaired → Recovered`；来源及时执行则 `Open → Fulfilled`。回款与来源执行原子完成，已消费输出不复活，后继付款不重签、不重执行。

这不是免除担保人的全部风险。来源永久不执行时，组织承担真实赔付损失。新的“延迟中性”结论限定于同一有限无冲突付款集合最终全部成功执行的两条历史，比较最终 CAL 分配，不比较 FUEL 费用。

## 2. 有限预算下的真实回收矩阵

每轮 60 秒、20 个两跳单位/秒，共 1,200 单位 / 2,400 笔付款。种子 23、37、59，各测 0%、1%、5% 扣留父交易。9 服务：4 委员 + 4 成员 + 1 网关；委员会应用状态和 BlockStore 写盘，成员与网关内存，钱包 NoSync。用户自付充足 FUEL，固定 60,000 CAL 备付，不启用补资。

扣留父交易在 30 秒公共时间期限后触发真实赔付，等待四副本均观察到历史物化，再释放父交易。这样每项样本都实际走过赔付、物化和回收，而不是仅模拟状态。

| --- | ---: | ---: | ---: |
| 已完成付款 | 2,400 | 2,400 | 2,400 |
| 赔付 / 回收项数 | 0 / 0 | 12 / 12 | 60 / 60 |
| 实付 / 回收 CAL | 0 / 0 | 1,200 / 1,200 | 6,000 / 6,000 |
| 最终备付 CAL | 60,000 | 60,000 | 60,000 |
| 最终 Open / Repaired / 缺口 | 0 | 0 | 0 |
| CAL 净 Spent / Reserved | 0 | 0 | 0 |
| 预留费上限 FUEL | 2,400,000 | 2,400,000 | 2,400,000 |
| 节点报酬 FUEL | 201,600 | 201,660 | 201,900 |

九轮共 **21,600 笔付款、216 项赔付、216 项回收**，全部通过。正常子交易到账 P50 为 1.185–1.251 ms。期限到四副本物化被观察到的中位时间为 1.257–1.761 秒，P95 最高约 2.015 秒，含 250 ms 观察轮询。每笔普通付款实付 94 FUEL，修复另付 5 FUEL。

三条 5% 曲线的采样最低备付均为 59,600 CAL，最后回到 60,000。这是特定释放调度下的占用轨迹，不是通用的最低备付公式。

## 3. 最终分配的成对验证与修复干扰

三对 14 服务实验，各发送 4,000 笔独立付款（100 TPS，40 秒），并发四个两跳演示。A 正常交付来源；B 扣留来源、真实赔付、再释放并回收。委员会与成员磁盘库，成员/钱包 NoSync，独立背景负载采用组织代付 FUEL。顺序为 A/B、B/A、A/B。

| 轮对 | 正常 P50 / 修复 P50，ms | 正常 P95 / 修复 P95，ms |
| --- | ---: | ---: |
| 1 | 1.070 / 1.127 | 26.84 / 59.23 |
| 2 | 1.089 / 1.108 | 29.49 / 58.44 |
| 3 | 1.083 / 1.097 | 27.41 / 55.15 |

六轮均完成 4,000 笔负载，最终四委员状态相同、outbox 排空；修复组均实际支出并回收 400 CAL。按创世用户角色归一化后，两个用户角色最终分别持有 30,000 与 830,000 CAL，两组织备付均为 10^12 CAL，A/B 一致。

结论：这些有限配对支持最终本金分配与来源到达时机无关。修复期间到账 P95 上升，不能把中位数接近解释为完全没有并发开销。

## 4. 永久缺失与跨组织控制

两轮各 14 服务，委员会及 BlockStore 写盘，成员/网关内存，用户自付 FUEL：

| 场景 | 结果 |
| --- | --- |
| 父交易永久不提交 | 2 笔后继公共执行，孙输出 100 CAL 不变；原组织备付 60,000 → 59,900，Paid=100、Recovered=0、净 Spent=100 |
| 跨组织，孙先到、父到、根赔付后再到 | 3 笔公共执行；中间义务 Fulfilled、根义务 Recovered；两个备付最终均为 60,000，Paid=Recovered=100 |

两轮均完成实际历史修复，四委员状态一致，公共缺口为零。永久缺失组的净损失保留，不通过核销抹去。

## 7. 规则、模型与表示回归

- 144 条四跳链轨迹 + 48 条 40/60 分叉再汇合轨迹，每步独立检查 UTXO、账户、缺口的资产投影，终态检查各组织本金与 CAL 授权。
- 有限模型含迟到补签、所有诚实签名者：159,976 状态、667,535 转移通过；有限枚举不是全实现机械证明。
- 来源先到批修复必须整体拒绝；批修复先到则迟到来源逐笔真实回款。覆盖钱包旧 QC 不复活、部分输出、跨组织和防重。
- batch→single、batch→batch，同 part/跨 part，修订 0→1→2，验证安装直接推进到最新已提交版本且不重复经济效果。
- 当前代码重复五次结构对照：同块同分片 8 项，命令与 part 适配从 8 次降为 1 次，编码字节从 127,336 降为 2,752；输入适配仍为 8 次。分散目标块不会减少 part 次数。这里报告结构计数，不把命令大小当总网络量。
- `go test -tags=comet_v3 ./...`、`go vet -tags=comet_v3 ./...` 通过，早期相关包 race 测试通过；日志与脚本随目录保存。

## 8. 论文可以据此主张什么

1. 运行期间原子且不回滚的固定成员模型下，认证支持真实在线连续续花。
2. 来源缺失由直接发行者承担，已生效后继不因原来源等待而重做；迟到回收让最终本金分配在定理条件下与时序无关。
3. 经济赔付与历史表示更新分层：变色龙哈希用于受限表示及完整身份保持，不是资金覆盖不变量的依据；当前实现仍把赔付与有效逻辑修订一起提交，因此赔付进展依赖门限适配材料，物理安装随后执行。
4. 本轮实验实例化了这些路径，并明确给出了存储配置、负载、时间终点与实际开销。

它们不证明任意网络、动态成员、崩溃后无状态恢复、永久失踪来源无损、真实市场激励相容或无限时长吞吐。相应条件放在模型和方法中，正文主线围绕已证明、已测量的机制组织。

证据入口：`review-summary.json`、`evidence/`、`model-recovery.txt`、`repair-cost-current.log`、`full-tests-current.log`。完整逐笔日志保留在实验原始目录及本地压缩包；索引列出 SHA-256，避免把庞大日志加入 Git。

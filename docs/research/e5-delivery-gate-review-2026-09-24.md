# E5 方案讨论摘要

日期：2026-09-24。对象：[评审两版支付系统](https://chatgpt.com/c/6aa8b2d7-b6f8-83ec-8e23-ea9f3b634e90)。本记录是两轮交流的归纳，不是新增实验结果，也不是第三方独立复现实验。

## 第一轮：选定对照方法

发送了当前 `re/cb341ec` 的网关交付、后台 INSTALL、成员存储分类和跟块清理路径，以及拟定实验矩阵。比较“修改网关交付开关”和“测试代理暂扣下游响应”两种方案。

GPT 建议代理方案，保留真实网关 Flush 后才 Offer/Persist 的执行顺序；两组都完整读取并关闭上游响应，只对 B 暂扣给钱包的响应。接受此建议：它减少业务修改，也使比较集中在额外交付条件。但它不能模拟真实网关 handler 等待造成的槽位占用或最高容量。

B 的条件为三个不同成员实际保存完整材料，或同一付款经验证的公共成功先满足。已 Observed 的 INSTALL 空操作不能算材料副本；当前普通成功返回也不是签名复制证明。只增加实验分类观测，不能再发第二套 INSTALL。

认可 200/1000 计划 TPS、每轮 30 秒、各三次，以及 100 跳真实续花各三次。暂不注入安装延迟，不扫最高 TPS。要求报告公共先满足比例、发送背压、实际工作量和未确认输入比例，不预设收益。

## 第二轮：核对事件与身份边界

补充了共享块流在钱包 READY 前独立运行、本地 Commit 后通知、有界记录和预热容量，以及校准、超时和重试规则。GPT 认为可以定稿，并补充：

1. 公共完成必须匹配同一 Network/TxID、Fact 及经过认证的实际成功效果，不能以高度、202 或重复命令空成功替代。
2. Network+TxID 只是查找键；原签名请求及 Funding/Auth 等材料也要绑定。不同有效 QC 签名子集不要求字节一致。早到事件先认证再用于放行。
3. 单次 HTTP 取消不能清除逻辑付款的已完成位和首次时间；重试沿用已有记录。B 增加的重试和后台尝试必须统计，不能全部称为纯 INSTALL 等待。

这些意见已纳入[正式方案](e5-delivery-gate-ablation-design-2026-09-24.md)。最终范围为“同一后台实现下的交付门槛消融”，不声称完整两阶段协议等价、断电耐久性或相对外部系统性能优势。

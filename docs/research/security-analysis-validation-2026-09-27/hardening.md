# 安全分支加固：配置、完整共识身份与组合论证

本轮以 `37edf2a` 为代码对照点，在 `security-analysis` 分支继续修改。目标是修复会破坏论文模型的实际入口，而不是用更多测试代替证明。`re` 及 E1–E8 的实验版本不变。

## 1. 修复内容与反例

| 问题 | 修复前证据 | 最小修改 | 对正常路径的影响 |
| --- | --- | --- | --- |
| 同一组织可配置两套消费裁决权威 | 同 Org、不同 epoch／成员集的配置分别合法，但 Policy、成员和 Direct 委员会入口未拒绝；钱包入口随后也复现 | 共用 `ValidateOrganizations`，在建表／写状态前检查组织标识到配置的唯一映射和网络一致性；同一配置重复不产生新权威 | 启动时检查，不增加每笔交易工作 |
| 稳定块哈希不能单独识别原始执行数据 | 合法原始分片 A、B 的稳定哈希相同，分片根不同；本地 A 与 B 的提交票曾触发最终守卫 panic，错误分支也可保留／锁定 A | 八处票值比较使用完整 BlockID；保留最终独立核对；缺少正确正文时按提交根取回 | 常数次身份比较，无新增共识轮次、RPC 或写盘 |
| Proposal 与票证据的身份、到达顺序 | 不同完整身份被当成 Proposal 已到齐；只收紧 Proposal 又会使 B 的合法多数票受旧 Proposal 阻挡 | 普通 Proposal、历史 POL 精确匹配；当前轮多数票与正确正文可独立进入原预提交步骤；原轮次与步骤守卫保留 | 拒绝错配材料，同时保留证据驱动的推进 |

唯一性校验覆盖 `DirectSettings.Policy`、`NewEngine`、`member.New`、`wallet.New` 和 `Network.Trust`。Engine 原有重复配置拒绝保留；其他入口允许完全相同的重复项，用于 Peers 包含自身的正常配置。检查不自动建立不同机器间的信任：诚实节点共享同一可信静态注册表仍是模型前提。

组件反例使用真实委员签名及有效原始分片，但应用为 Comet 的测试 KV 应用。它证明了身份判断缺陷，不冒充已构造出合法 Next 付款的全网资产分叉。

## 2. 共识回归覆盖

`third_party/cometbft/consensus/block_identity_test.go` 随 overlay 复制到固定 Comet 版本，纳入 CI。测试通过独立子进程隔离启动时全局修订密钥，避免污染上游普通链测试。

| 场景 | 应保持的行为 |
| --- | --- |
| 已提交 B，本地及锁定为同哈希异根 A | 清除 A，获取 B；不提前调用 Finalize；B 到齐后真实执行一次 B |
| 迟到 A 分片／重复 B 分片 | A 不能混入 B；B 的重复分片不产生新效果 |
| Finalize 前身份不一致 | 继续等候，不执行 A，也不依靠 panic 作为常规处理 |
| B 的 prevote 多数，本地 A | 不锁定哈希别名；缺少 B 时预提交 nil |
| Valid 更新 | 不把 A 标为 B 的有效候选 |
| 旧轮／同锁轮／更新轮 POL | 只有满足原轮次守卫的更新证据才能解锁；身份比较覆盖完整值 |
| Proposal／历史 POL 不匹配 | 普通提案不被当成就绪，未锁定超时不为错误提案投票 |
| 多数票先到／分片先到，Proposal 缺失或不同 | 正确当前轮证据及正文到齐后可按原规则锁定并预提交 |
| 已经预提交 nil，正确分片随后到齐 | 不再签第二份同轮预提交，不重写已完成的步骤 |
| 重复 commit | 不第二次调用 Finalize |

连接回归实际检查传给 `FinalizeBlock` 的交易字节和 BlockStore 的完整身份，不只检查函数返回。原 `TestState*` 与 `TestProposalBatch*` 也纳入专项回归。

## 3. 适配计算能力与业务授权分离

新增赔付测试使用全部测试份额，故意合成错误 `ReserveDebitIdentity` 的**有效** opening；密码学等式成立，业务执行仍因目标不合法而拒绝且无状态修改。合法替换在到期前也被拒绝。测试证明这些拒绝由业务守卫触发，而不是仅因签名或 opening 格式错误。

相应的一般命题允许适配器返回任意候选，甚至拥有全部适配计算能力，但不允许写公共状态、修改验证程序或伪造委员会认证。普通入口、Repair 和 Materialize 各自重新限制原始引用、到期义务／精确版本／唯一扣款身份、已提交 Task。逐转移分类得到授权和会计不变量，不依赖“每个有效 opening 都有一次新的三方业务批准”。

这关闭了经济安全论证中对过强门限主张的依赖，**没有证明陷门保密、新目标适配不可伪造或任意外部历史读者的最新版本认证**。论文不以未证明的原语性质推出资金安全。

## 4. 从组件到系统的论证

本轮把抽象值域固定为完整 BlockID，并给出三层连接：

1. 原始正文与分片集合成对维护，同一可接纳原始分片根绑定同一正文。
2. Proposal、Votes、Locked、Valid、Commit 使用同一完整身份；保留原有投票、锁和轮次守卫。
3. 生产首次 Finalize、同高度重试、blocksync 和原始重放取得一致原始材料；物化不改变活跃候选或公共经济状态。

应用有效性不能由“存在多数票”循环定义：诚实未锁定投票来自真实验证，锁定投票的依据沿更早因果链回溯到真实验证。跨轮安全也需要锁定论证，不能只计算两个 commit 的交集。

系统投影保留批准、消费锁、潜在责任、真实账户、费用和连续跟块；隐藏三票事实计入风险；公共转移原子创建缺口或关闭责任。INSTALL 会记录本地 Consumed，不能作为整个本地状态的空操作擦除。只有网络重传、无业务变化的重试及已授权物化在对应经济投影中无变化。

第五章给出固定四成员／三票、静态故障和不可回滚运行期状态下的手工条件证明。有限搜索和实际回归支持实现映射，但不是整个 Go 程序的证明助手机械验证。

## 5. 验证与复现

先运行 `python3 third_party/cometbft/overlay.py`，再执行：

```sh
go test -count=1 ./...
go test -count=1 -tags=comet_v3 ./...
go vet -tags=comet_v3 ./...
go test -count=1 github.com/cometbft/cometbft/consensus \

go test -count=1 github.com/cometbft/cometbft/consensus
```

### 5.1 Mac 正常路径性能对照

按 `A1 → B1 → A2 → B2 → A3 → B3` 运行，A 为 `37edf2a`，B 为本次生产补丁。每轮从新创世开始，单组织四成员、一网关、四委员；预热 100 笔后，以 500 TPS 输入 10 秒，共 5,000 笔独立最终 UTXO 付款。用户自付 FUEL，沿用 E5 `direct` 负载器，无交付代理或故障注入。委员会、成员、网关与区块库为实验内存配置；钱包使用原有 bbolt NoSync＋Group，不把它描述为同步耐久保存。

快速到账从实际调用网关前的 `SentNS` 到 `ReceiveDirect` 验证及本地事务完成后的 `ReadyNS`，不包含事先生成、编码和保存发送请求；收款钱包位于同机负载器内。公共与成员时间为各自**观察完成**时间，不能改称共识内部纯执行时长。保持同一工具、Go 版本和配置，以评估本补丁的正常路径代价。

| 指标 | A：修复前 | B：加固后 |
| --- | ---: | ---: |
| 正式交易数（三轮合计） | 15,000 | 15,000 |
| 快速接收／公共成功／成员完成 | 各 15,000 | 各 15,000 |
| 快速到账 P50，三轮均值 | 0.896 ms | 0.896 ms |
| 快速到账 P95，三轮均值 | 7.459 ms | 7.456 ms |
| 公共观察 P50，三轮均值 | 798.280 ms | 805.276 ms |
| 成员完成观察 P50，三轮均值 | 839.997 ms | 843.326 ms |
| 负载器结束计时，三轮均值 | 10.706 s | 10.735 s |
| 最后发送至最后成员完成记录，三轮范围 | 0.600–0.720 s | 0.605–0.682 s |

每轮实际首末发送跨度约 9.998 秒，全部正式交易发送并完成，没有把未发送请求算成功。六轮的四委员状态一致、全部待办排空，费用审计通过。P50／P95 的均值是**先逐轮求分位数、再平均三轮**，不是把三轮样本混为一组的分位数。

计时端点不同，不能直接用总时间减发送跨度替代最后一行：`FinishedNS` 在主循环以 100 ms 间隔确认全部结果、取消并等待观察器和跟块器结束后记录；最后成员时间来自逐笔 `MemberNS`。总时间还包含起点到首笔发送的偏移及负载器收尾。最后一行对应分析器的 `drain_from_last_send_s`，只表示最后成员完成记录的尾段，不是全部系统状态清理的独立计时。最终待办确实为零由审计另行确认。

在该负载和配置下，未观察到明显且一致的性能回退：快速路径几乎不变，总完成时间均值增加约 0.27%。这不是统计等效检验，也不证明峰值 TPS、WAN 延迟或任意负载性能不变。该对照隔离本轮补丁；A 已包含更早的原始分片接纳修复，因此不能用它独自证明整个安全分支相对 `re` 的总性能代价。E1–E8 原成绩不变，`re` 不自动合并。

## 6. 独立讨论的作用

侧边栏 GPT 参与五轮反驳式复核，指出钱包入口遗漏、Proposal 与 QC 的不同推进依据、首次 Finalize 的材料前提，以及有效性论证可能循环。最终跨轮证明采用“最小冲突轮＋该轮最早成证事件”，处理提交证据迟到和诚实节点已换轮的情况；按锁来源的递减轮次论证有效性。收尾复核还指出总计时与成员尾段的端点差异，已对照负载器源码写明。每项采用的建议都回到源码和回归确认。其意见不是独立执行测试，也不是安全证明证书。

本轮没有增加新的正常交易阶段、账本、持久恢复机制或门限算法。保留明确模型边界，修复实际违反模型的入口，并以组合论证连接已经实现的业务流程。

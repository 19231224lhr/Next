# C3 针对性安全审查与证明更新

2026-10-02 · 生产代码基线 `7a2517e`＋本轮无关输入证书校验补丁 · `feat/review-source-recovery`。

本轮将来源补交、公共赔付决定和历史表示修复纳入同一安全模型，核对关键状态写入及回归。范围是 C3 新增路径与其直接调用的账务、跟块、物化接口，不重新宣称整个 Go/Comet 实现已经机械化证明。网络实验沿用[冻结报告](../../experiments/c3-source-repair-2026-10-02/README.md)，没有新增性能测量。

## 2. 假设与状态

沿用固定组织四成员、三票认证、每组织至多一个静态拜占庭成员，以及独立委员会的相应 BFT 假设；合法创世、唯一配置与路由、签名不可伪造、摘要绑定、确定原子公共执行、诚实签署状态不遗忘或回滚、跟块认证连续前缀保持不变。实验 NoSync/内存配置不提供丢状态后的原身份安全重启。

公共执行读取的原始历史和原始 BlockID 必须在正确委员会副本之间一致可用。当前实验保留原始块；本论证不覆盖缺少所需历史的裁剪或快照启动。至少在义务决定、待表示、重放仍需访问期间，不能删除相应原始块及元数据。

将状态拆为：

| 分量 | 内容 |
| --- | --- |
| `L` 本地签署状态 | 原批准、输入锁、实际占用与成员额度进度 |
| `Q` 材料队列 | 本地 outbox、重试提示；不是新批准 |
| `E` 公共经济状态 | 最终输出与消费、账户、Open 缺口、覆盖、Grant 使用、费用、义务状态 |
| `D` 不可变赔付决定 | 精确网络／输出／历史槽位、实际扣款身份及决定高度 |
| `R` 规范表示 | 公开批准的修订、精确正文、分片证明、Task 与索引 |
| `M` 物理表示 | 本地 BlockStore 已物化版本；保留原始执行材料 |

`Repaired` 是代码中的**已经经济赔付**状态，不代表历史字节已经物化。之后 `Recovered` 表示真实来源回款；`D` 不因回款消失。将这两个词误读为修复进度，会混淆本轮最重要的解耦。

在合法 V5 初态和生产入口可达状态中，义务处于 `Repaired` 或 `Recovered` 时均有完整赔付决定；不能写成 `Repaired ⇔ D 存在`。规则层辅助函数的中间 overlay 还不是生产提交边界。

## 3. 联合状态转换

| 事件 | 前提 | 原子效果／不变部分 |
| --- | --- | --- |
| `ExposeSource` | 成功公开后继携带直接父证书；本组织有匹配原批准；无 Observed/outbox；正常验证器通过 | 只添加原付款 outbox；不签新票，不改原批准、锁或额度 |
| `ExecuteSource` | 原付款满足正常公共执行规则 | 关闭 Open，或使 Repaired→Recovered 并回款；不复活已消费用户输出 |
| `DecideCompensation` | 义务 Open、公共时间到期、历史目标与金额正确、替换等长、备付与费用可用 | 原子扣备付、关闭缺口、更新费用及覆盖、记录 `D` 与待表示项 |
| `RepeatDecision` | 完整决定与已存 `D` 相同 | `Applied=false`，零 Changes、Effects、FeeOutputs；字段冲突拒绝 |
| `Represent` | 对每个槽存在成功 `D`，规范 Base/Previous 匹配，允许范围及两层承诺验证通过 | 原子增加 `R`，移除相应待表示项；`E` 与 `L` 不变 |
| `InstallRepresentation` | 精确已提交 Task、完整身份及版本规则满足 | 更新 `M` 与物化游标；不重复执行付款、决定或回款 |

以上对应实际原子边界，不把网络发送与数据库提交当作同一步。先发布子付款的成功块，才能产生 ExposeSource；本地跟块事务提交后才由现有中继发送。

## 4. 引理一：来源补交保持原授权

**命题。** 在上述假设下，由 `recoverExposedSources` 产生的任务是原已授权付款的重提交，不扩大付款人授权、组织签署权限或输出权利。

**证明。** 本地查找使用父 QC 的 Fact；`Approval.Fact`、保存的 `Direct`/`Admission` 和公开 Summary 必须绑定同一事实。构造器只取原正文、原签名、保留的直接输入证书和公开完整 QC，随后调用正常 `VerifyDirectPayment`。该验证器重新计算准入向量，验证用户授权、组织 QC、输入证书及输出绑定。由签名不可伪造与摘要绑定，重建不能产生不同的合法付款核心。唯一新增写入是 `KeyOutbox`；没有批准、扣额度或解锁操作。缺少批准则跳过，已观察成功或已有任务也跳过。重复暴露不会推迟已存任务的重试时点。证毕。

补交可能使原本扣留的合法交易后来执行；这会产生该交易本来授权的公共效果。命题不是“补交前后全局账本永远不变”，而是“没有新增授权”。保留任意多层完整祖先正文不是条件：每步用原成员保存的本笔正文及直接证书，逐步恢复缺失来源。

存在公开直接义务意味着其父 QC 已随成功后继公开。三名不同签名者中至少两位诚实，且在签名前已保存原批准材料。因此，固定配置和材料不遗忘条件下，原客户端扣留完整 QC 本身不再足以阻止补交；实际完成仍依赖诚实成员跟块、投递及原付款满足执行规则。

## 5. 引理二：赔付决定至多生效一次

**命题。** 对一个直接缺口输出，成功赔付至多扣一次备付并产生一次对应费用／额度效果；重复决定与后续表示不能再次产生这些效果。

**证明。** 按公共命令顺序归纳。初态没有成功决定。首次决定检查 Open、到期与精确历史槽，执行账务后将义务转为 Repaired，并在同一状态转移中记录不可变 `D`。失败不发布部分变更。后续完整相同命令先命中 `D`，只返回无效果结果；不同位置等字段与 `D` 不同则拒绝。若来源先成功，则义务已非 Open，首次决定拒绝。若决定先成功而来源后来执行，回收路径只允许 Repaired→Recovered，并保留 `D`；因此回款不使决定再次可扣。`Represent` 没有调用赔付账务函数。证毕。

成员与钱包只接受已认证区块中的绑定结果。415 携带经济效果；416 绑定表示命令身份，却被 `DecodePublicExecution` 投影成零经济效果。连续游标与状态原子推进防止重复跟块恢复额度。这里只恢复成员实际记录过的占用，不能将另一成员的 Paid 当成本成员的损失恢复。

## 6. 引理三：表示与物化不重复经济效果

定义投影 `πE(S)=E`，省略 outbox、决定授权元数据、修订和物化任务。每个成功 `Represent` 和合法 `InstallRepresentation` 满足 `πE(S')=πE(S)`。

**证明。** 单项表示写集合仅含待表示删除、Revision、保存的表示命令、Task 和 Queue。批表示另外保存逐项 batchReference；不写账户、消费、覆盖、Grant 或费用记录。跟块器对 416 跳过经济应用。物化使用已提交 Task，不调用支付执行器；其版本锁和精确字节检查只作用于历史存储。故一步投影相等，按步数归纳得到任意合法表示／物化调度的投影相等。对于同一原始公共命令历史，使用保留原始块逐高度重放，应用哈希与经济状态相同。证毕。

不再使用旧命题“一个表示批次等价于顺序执行多个赔付步骤”。当前赔付已单独发生；表示批次仅合并对已决定槽位的表示工作。不同批次包装会留下不同命令、版本和应用哈希，不能从经济投影相等推出整个状态相等。

跨历史比较必须固定经济命令、公共时间及历史目标坐标（或给出显式映射）。不能直接删除包含表示命令的区块、改变时间或交易位置，再宣称经济轨迹无条件相同。

## 7. 引理四：受限表示保持后继与完整共识身份

**命题。** 依法提交并物化的修订只改变已决定输入槽的资金引用及 opening，保留既有所有者授权、交易／输出身份、后继引用及完整 BlockID。

**证明。** `InputTarget` 从不可变决定推导目标，并经 `targetSlot` 核对当前规范消费者、Fact、输入、金额和原资金 opening。单项验证固定字段；批构造从规范正文复制并仅写列明的唯一槽位。Base/Previous 排除陈旧规范版本，Next 绑定确切新正文，长度检查保持分片布局。输入承诺兼容性保持固定交易身份；全部分片验证后再比较原 BlockID 的哈希和 PartSetHeader。公共 Task 绑定全部允许物化的字节。已有后继的付款授权和引用不需要修改，也不调用后继重新执行。回款保留决定，故赔付事实的历史表示在回款后仍合法。证毕。

适配 opening 证明承诺兼容性，不单独证明新授权或新一轮门限参与。公共决定和表示命令验证承担授权约束。门限原语本身的自适应安全归约、修改后 Comet 的全路径机械精化仍须与上述接口层论证区分。

## 8. CAL 不变量的继承与事件替换

对公共状态，令 `U` 为最终未花 CAL，`A` 为全部 CAL 账户余额，`Dopen` 为 Open 缺口，则原投影 `U+A−Dopen` 继续成立：

- 付款与迟到回款的规则未改，沿用来源回收分析中的 `ΔU=M−J−K, ΔDopen=M−J, ΔA=K`。
- 成功决定调用同一经济转移，`ΔA=ΔDopen=−a`，不增加收款输出。
- 补交队列、表示和物化对这三个量的增量均为零。
- 重复决定与失败命令也为零。

覆盖证明中每个诚实原批准者保留的残余、`Paid−Recovered` 净支出和真实备付约束保持；把旧证明的“赔付修复”原子事件换成 `DecideCompensation` 即可。补交不释放额度，表示也不释放额度，不增加一个能绕过覆盖界的转移。FUEL 按实际消费与退回审计，不能从 CAL 投影推出手续费可循环恢复。

## 9. 完成性分开陈述

1. **来源补交完成**：至少一位原签名成员保留可验证材料、观察公开后继并继续服务；其 outbox 得到公平调度，委员会接纳并执行仍合法的原付款。没有这些条件则不能保证来源恢复。
2. **经济关闭完成**：仍 Open 的义务到期，公共时间推进，真实备付／费用满足规则，决定工作器和共识公平推进。此路径不调用适配端点；不依赖门限适配可用性。共享 CPU、数据库和公共队列仍可能影响时延，不能称资源完全隔离或给出无条件时间界。
3. **表示完成**：另需正确适配贡献可得、候选版本更新及公共表示命令／本地物化得到公平推进。表示暂不可用不撤销已完成的赔付与回款。

这三个条件是进度论证，不从“有备付”推导任意负载下立即完成。当前实验展示具体暂停轨迹；尚未做旧耦合版相同暂停条件下的成对网络测量。

另已核对：INSTALL 不重置已有 outbox 的重试期限；RepairBatch 编码同时排除重复输出与重复槽位；`EvaluateDirectCompensation` 的生产调用只来自 `ExecuteDecision`，后者在同一 overlay 中补足不可变决定才返回。已修正该辅助函数仍提及旧 RepairInput 耦合语义的注释。

外部英文草稿中的“回款后所有决定均报错”“三诚实适配者响应当且仅当可完成”等过强句子未采纳。准确条件分别是：重复相同决定无效果、冲突决定拒绝；三个正确响应足以推进，拜占庭参与者也可能返回合法贡献。

### 第二轮发现并修复：额外证书可触发无关补交

`ApproveDirectBytes` 原本要求 `len(used)==len(parents)`，而 `VerifyDirectSubmission` 只要求每个证书输入都找到合法证书，没有排除多余的合法证书。中继可在不改交易及 QC 的情况下附加另一张同网合法 TXCer；原公共验证接纳后，跟块补交会检查这张无关证书，可能触发原本不应由该付款触发的后台任务。这不等于伪造付款授权或重复扣款，但与“实际消费后继触发补交”的规则不一致。

新增 `TestPublicSubmissionRejectsUnusedInputCertificates`，分别对最终输入付款和证书输入付款附加合法无关证书。修复前两例均以“未拒绝”失败，见 [unused-cert-before.log](unused-cert-before.log)。修复在现有输入循环计数，末尾要求证书输入数等于已验证证书映射大小；输入唯一性已由交易基础验证保证，无需新 map。公共提交与内部安装复用该检查，与成员原批准规则一致。

修复后，两种无关证书均返回 `ErrRule`，正常两类付款继续通过，见 [unused-cert-after.log](unused-cert-after.log)。不改变消息编码、经济规则或 RPC 数量；本轮没有重新测量性能，不能将旧性能成绩归到这个补丁。

这是公共验证规则收紧，后续实验须全部委员统一构建并重新创世，不能混用旧／新二进制。本轮未在线切换已有节点，也未改变规则 ID 或状态 schema。正常已批准材料本来就不带额外证书，仍满足新检查。

补充核对：`OutputCertificate.Verify` 将网络绑定到组织配置，`Member.New` 验证全部组织与创世同网；批准和公共验证没有跨网差异。`AnchorDirectDeadlines` 重读义务，只为仍 Open 且未锚定的项设期限，并删除已处理锚定索引；来源先到不会重新开启已关闭责任。

第三轮 Claude 复核未提出新的阻塞问题。其对计数前提的提醒已按代码确认：`Transaction.Validate` 在 `PrepareDirectVector` 内先拒绝重复输出输入；计数条件是 `CertificateInput`，不取决于执行时父输出是否已经成立。外部复核用于发现遗漏，结论仍以本页的源码路径和测试为依据。

## 2. 成员预算、真实备付和守恒

**提供内容：** `ApproveDirectBytes`、`finishLocal`、`ApplyReserveIncrease`、`NewEngine`、Coverage/Promise/Obligation、`EvaluateDirectPaymentAt`、`EvaluateDirectCompensation` 及 `nextBody` 的实际语义；提交 A–D 四组候选推导，请求寻找反例。

**答复要点：** 推导可发展为条件数学证明，不能因此宣布代码已证明安全。关键连接是：诚实签署者残余不小于证书风险；自身 Settled 后 Paid 不再增加；公开 Spent 等于真实赔付；多个 Grant 按同一备付账户聚合。

对 Execute 的一般情况，答复接受“新增缺失输入 M，同时关闭既有下游缺口 H，则最终未消费资产和 OpenGap 都变化 M−H”的推导方向。它覆盖中间交易同时关闭下游责任、引入上游责任的情况，无需把整条依赖链递归归结到一个根。

**采纳与修正：**

- 有效 QC 集合按 Fact 去重，包括未公开及尚未组装但已有三份有效签名的事实。
- 局部批准只消耗成员容量，不能冒充左侧的有效证书；不会凭空提高已认证风险，但可能堵塞活性。
- 全部共享账户公式的求和范围统一限定为该账户支持的 Grant，避免把任意账户混加。
- Paid 留在风险权重内，不重复计算；已经赔付的损失不得因核销恢复成新资金。
- FUEL 退款和奖励按真实资产位置计数，历史累计字段不重复加入全局资产。
- CAL 守恒与抗战略延迟分开：合法迟到父可以让用户得到实例 1、组织承担真实损失，不能声称激励相容。

## 3. E1–E8 的论文证据边界

**提供内容：** 八项实验的设计、样本、实际负载、故障控制、存储及确认终点差异；明确本研究关注便捷快速续花，而非扩容或任意拜占庭活性。

**答复要点：** 当前重点应转为协议证明与代码对应，不再依赖增加 TPS 实验回答一般安全问题。

| 实验 | 讨论后保留的结论 |
| --- | --- |
| E1 | 展示真实连续续花；固定结构凭证不携带祖先链，不等于全部系统成本恒定 |
| E2 | 展示预算周转、低预算阻塞与真实外部补资；旧结果不证明后续补资修复已安全 |
| E3 | 展示唯一赔付、账务、迟到实例、磁盘修订与原始重放轨迹；不证明门限原语或全部 Comet 路径 |
| E4 | 指定冲突与单成员故障支持实现行为；材料未扩散和局部票残留是必须披露的活性边界 |
| E5 | 量化交付门槛取舍；不能把快速交付与三副本等待说成保障完全相同 |
| E6 | 是不同明确配置下的同机延迟参考，不是等保障协议速度或安全优劣结论 |
| E7 | 支持静态预信任下的跨组织互操作与指定 HTTP RTT；不支持自动发现、真实 WAN 共识或多机扩展 |
| E8 | 支持已测负载的运行和资源成本；不支持无限状态稳定或把身份数量当独立客户端数量 |

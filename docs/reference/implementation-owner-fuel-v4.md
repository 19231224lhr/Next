# 快速付款的用户自付 FUEL

2026-09-23，`e2-owner-fuel`。本修订补齐原有 `OwnerFinalUTXO` 费用来源在快速路径中的实现；组织代付 `OrgReserve` 保留为可选分支。E2 本轮使用用户自付，旧 TPS、E1 和原 E2 数据仍属于其原实验配置，不能据此宣称用户自付已经复测了同样的最高 TPS。

## 扣谁的钱

用户在签名交易的 `Fee.Inputs` 中引用已最终成立的 FUEL UTXO，并签署最大费用 `Maximum` 和退款地址 `Refund`。费用输入必须属于有效签名者，资产为 FUEL，消费路由属于当前服务组织，创建证据匹配且没有被消费。费用输入和 CAL 输入统一检查重复、在同一成员事务锁定；任一验证或预算检查失败，整笔回滚。

组织只占用 CAL、Execution、Bytes 三类权限。用户自付不要求组织 FUEL 余额，不占用 FUEL 或代付 Policy 授权。CAL 担保规则、三票认证、后台 INSTALL 和公共提交方式不变。费用输入验证使用当前账本，不能由静态验签缓存代替。

## 扣款、找零和退款

委员会接纳执行后，原子消费用户费用输入，将 `Maximum` 放入本笔费用托管，超出部分立即生成最终 FUEL 找零。按原费用计划兑现报酬、销毁和必要赔付处理费；责任收尾后，未使用预留生成最终 FUEL 退款。

例如费用输入 10,000、最大预留 1,000：先找零 9,000；普通付款实际消耗 94，最后退回 906。用户净付 94，组织净付 FUEL 为零。若触发当前费用计划中的一次赔付处理，额外消耗 5，退款为 901；赔付本金仍来自原责任组织的 CAL 账户。

父交易到账或赔付可能触发较早子交易的退款，所以退款身份绑定**原付费交易**，与触发它的交易、高度或到达顺序无关：

| 输出 | 身份 | 可用时点 |
| --- | --- | --- |
| 费用找零 | `OutputIdentity(network, payerTxID, MaxOutputs)` | 公共确认 |
| 费用退款 | `OutputIdentity(network, payerTxID, MaxOutputs+1)` | 公共确认 |

这两个索引不占用 CAL 输出的索引范围。它们都是最终 FUEL UTXO，不签发 TXCer，也不参与提前续花。退款可作为后续付款的最终费用输入。

## 自行跟块

普通公开执行结果增加有界 `FeeOutputs`，每项包含原付费 TxID、固定用途索引和真实输出正文。委员会同时写入这些 UTXO 的账本状态；结果不是给钱包发的私有通知。成员按输出路由、钱包按所有者导入，包括由 `RepairInput` 触发、以及成员没有本地批准记录的退款。

列表按 TxID、索引排序且不得重复，最多 `MaxOutputs+2` 项：本笔最多两个费用输出，外加本笔 CAL 输出可能关闭的既有子付款退款。失败结果、重复公共提交和重复跟块不重复扣费或生成退款。

## 版本与资源口径

交易仍复用 wire 4 已有的费用字段。含费用输出的执行结果使用新 tag **411**；无费用输出的结果保持 tag **410**。规则域更新为 `DIRECT_ACCOUNTING_V4_OWNER_FUEL`。所有参与者统一使用新二进制、新创世；不混用旧库或提供在线迁移。

Execution 计入费用输入验证，并预留两个费用输出的处理成本；Bytes 计入费用字段本身和有界费用输出记录。自付分支的授权版本直接绑定签署的 AdmissionRef 与真实 Grant，不与为零的 `Fee.Version` 耦合。旧代付分支的版本检查保持。

## 验证与实验

测试覆盖用户扣费与找零、错误资产/所有者/路由/非最终来源、输入不足、费用双花、事务回滚、正常关闭、父触发退款、赔付退款、同块父子、重复提交、无本地批准的跟块和退款再消费。账本审计分别累计 CAL 与 FUEL UTXO，核对用户未花余额、托管、报酬和销毁的总量。

本轮 E2 在创世时为付款用户准备充足且独立的最终 FUEL 输入，删除组织 FUEL/Policy 授权，不创建组织 FUEL 资金账户。运行中不充值、不清锁。结果见[用户自付 E2 复测](../experiments/owner-fuel-2026-09-23/README.md)。

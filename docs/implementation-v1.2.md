# v1.2 直接担保实现与实验记录

日期：2026-09-19。协议/线格式版本 3，独立创世网络。开发分支：`implementation/direct-liability-v3`。Mac 工作目录：`/Users/richz/lab/man/utxo-fastpay-v12`。原 v1.1 节点、数据库和实验数据保留。

## 已实现的闭环

付款钱包提交 → 组织成员验证当前交易、直接父 TXCer、消费锁和额度，同步持久化后签票 → 三票形成分离的输出证书 → 收款钱包验证并保存，可继续付款。完整证书的 INSTALL、公共提交和累计核销在后台进行。

委员会收到子交易时，合法直接 TXCer 可以支持尚未成立的输入。委员会在同一事务中登记唯一消费和缺口，并创建子交易输出；不等待整条祖先链。本次签发按全部 CAL 输出占用直接担保额度。父交易到达后解除对应责任；到期仍缺失时，由原发行组织承担本金。

赔付通过新区块里的不可变 `RepairInput` 扣账户一次，并产生已提交的历史改写待办。后台实际修改 Comet BlockStore 中的历史交易和 Part 字节，保留 TxID、OutputID、DataHash、完整 BlockID 和原提交签名。只改资金引用和相应开口，不改收款输出、金额、所有者授权或历史 AppHash。

迟到的合法父交易按已批准的“不追偿”规则给原用户创建实例 1；原 TXCer 只支持实例 0。旧消费记录不删除，实际赔付的 CAL 不核销成可复用额度。专用 ReserveDebit 是已经分配给该历史输入的唯一扣款身份，不再创造一份钱包可花余额。

## 代码分工

| 模块 | 实现职责 |
|---|---|
| `protocol/v3.go`、`direct_payment.go`、`repair.go` | 分离 TXCer、固定核心、输入开口、稳定身份及规范编码 |
| `crypto/chameleon` | RSA-2048 全域哈希、四成员三份门限适配、固定宽度开口 |
| `internal/rules/direct*.go` | 直接责任、输出覆盖、迟到实例、期限、费用、累计核销 |
| `internal/member/direct.go` | 持久签票、Worker 预算、后台 INSTALL、批量核销 |
| `internal/gateway/direct.go`、`internal/transport` | 三票收集、持久中继、连接复用、合并核销查询 |
| `internal/committee`、`cmd/committee/repair_runtime.go` | 单写者执行、期限唤醒、独立份额 RPC、修订物化 |
| `internal/redaction`、`third_party/cometbft` | 受限历史改写、分片承诺、原始执行材料重放 |
| `internal/wallet/direct.go`、`cmd/payctl` | 接收/持久钱包、单笔实验、闭环负载、账目和历史审计 |

复用现有 Go、bbolt、HTTP、Worker、Overlay、outbox 和 Comet 共识轮次；未增加根责任服务、事件总线或另一套业务数据库。修复工作游标保存在委员会本地的小型数据库中，不修改共识状态。

Comet 固定为 v0.38.26。补丁只涉及交易叶哈希、Part 承诺和编码、受限 BlockStore 修订、重放/同步读取原始字节、启动前绑定块存储。初始分片开口与修订开口均在 Part 负载外，避免自引用。普通共识提案拒绝非零修订标签；历史当前版本由已提交修复命令授权。

`RepairInput` 执行依据应用已提交的修订正文，不能依据后台写盘进度。物化队列按提交高度、目标旧块和修订号排列；重复旧待办不能覆盖已经合法完成的新修订。原始块为重放保留，实际查询块为改写版本。

## 构建与运行

需要 Go 1.27.1 和 Python 3。Mac 非交互 SSH 使用以下 PATH；网络受限时单次设置 `GOPROXY=https://goproxy.cn,direct`。

```sh
export PATH=/usr/local/go/bin:$PATH
python3 third_party/cometbft/overlay.py
go test ./...
go test -tags=comet_v3 ./...
go test -race -tags=comet_v3 ./...
go vet -tags=comet_v3 ./...
go build -tags=comet_v3 -o bin/ ./cmd/member ./cmd/committee ./cmd/gateway ./cmd/payctl

bin/payctl init-lab -v3 -dir experiments/direct-lab -outputs 1024 -port 24000
bin/payctl lab-run -dir "$PWD/experiments/direct-lab" -bin "$PWD/bin"
```

首次构建必须运行 overlay：它从锁定的上游模块生成 `.scratch/comet-src`，不修改 Go 模块缓存。`go.mod` 的本地 replace 指向该目录；已验证无该目录的新副本可以完成生成和测试。省略 `comet_v3` 标签不能运行真实历史改写网络。新网络不能使用旧链的创世配置和数据库。

另开终端：

```sh
bin/payctl demo-v3 -dir experiments/direct-lab -input 0 -withhold-parent
bin/payctl demo-v3 -dir experiments/direct-lab -input 1
bin/payctl bench-v3 -dir experiments/direct-lab -start 100 -count 128 -concurrency 64
```

每个独立实验用未消费的输入索引。`-withhold-parent` 故意只取得父证书、不投递父交易；子交易先确认，自动到期修复后才补交父交易。正常 demo 不隐藏父交易。初始化随机生成实验身份和 CH 份额，秘密文件不提交 Git。停止 lab-run 后执行 `bin/payctl audit -dir experiments/direct-lab`，核对真实数据库；不要在节点运行时强开同一 bbolt 文件。

## 验证结果

- 默认及 v3 全包测试、v3 全包 race、vet 和构建通过。
- 门限密码测试覆盖四种三人集合、多次公开适配、不足/重复/错误份额和不同上下文。
- 真实 LevelDB 改写测试检查历史正文确实变化、所有者签名、交易证明、原 commit 和完整 BlockID 仍成立；重开存储、跨版本分片拒绝、连续修订及旧任务重做通过。
- 支付集成测试覆盖子先父后、孙交易继续处理、超时、迟到实例消费、旧证书重复消费拒绝；从原始历史重放每个高度的 AppHash 和单次账户扣款一致。错误修订目标、版本、替换内容和分片开口被拒绝。
- 14 个真实进程：两个四成员组织、四委员会、两个网关。故意隐藏父交易时，子交易钱包可续花 34.091 ms，公共证明观察 414.197 ms，自动赔付观察 31.385 s，迟到父输出实例为 1。它是一笔样本，不是分位数。
- 把委员会 0 应用库移到备份后，使用已经改写的真实 Comet 存储从创世重放，重新加入网络。最终四个委员会应用状态一致。
- 最终停止审计：588 笔已登记付款全部收尾，所有成员/网关 outbox 为零，缺口为零；四节点各有一项历史修订，CAL/FUEL 守恒检查通过。失败客户端请求中已有部分成功提交，所以审计付款总数与成功 benchmark 计数不能直接相加比较。

实际实验还发现并修正了空闲停块的时间问题：Comet 高度 H 的头时间可能来自很早的 H−1 提交。缺口在 H 接受后，改用 H+1 中反映 H 提交的共识时间锚定 30 秒期限；在锚定前不能赔付。本地时钟只触发唤醒请求，是否到期仍由共识时间判断。最初基于旧时间锚的约 0.79 秒结果不作为有效超时实验。

## 性能测量与结论

计时从付款钱包调用 HTTP Client.Do 前开始；收款验证并同步保存完整证书后结束“快速到账”。付款准备、签名和发送前存储不计入这个延迟；连接建立和网络等待计入。钱包在同一压测进程模拟，没有额外手机到手机链路。

负载是有界闭环：一个 worker 等待本笔公共输出证明和全部累计核销证明后，才继续下一笔。总速率包含准备、查询、验证和等待，**不是共识最大 TPS，也不是逐笔纯上链时间**。成员核销排空另外通过停止审计确认。

| 报告 | 并发 | 成功/失败 | 总用时 | 闭环完成/秒 | 快速到账 p50/p95 |
|---|---:|---:|---:|---:|---:|
| bench-v3-100 | 16 | 128/0 | 13.204 s | 9.69 | 113.8/183.5 ms |
| bench-v3-300，连接修复前 | 64 | 74/54 | 32.285 s | 不用于性能结论 | 见原始报告 |
| bench-v3-500，连接复用 | 64 | 128/0 | 9.480 s | 13.50 | 124.4/159.0 ms |
| bench-v3-700，重复 | 64 | 128/0 | 9.630 s | 13.29 | 144.0/186.7 ms |
| bench-v3-850，合并核销 RPC | 64 | 128/0 | 9.964 s | 12.85 | 167.6/178.2 ms |

失败轮含 52 次本机临时端口分配失败和两次网关错误。修复包括复用标准库连接池、读取完 404/503 响应正文，再归还连接。合并核销 RPC 减少请求数，每份证明仍独立验证；单轮结果没有证明吞吐提升。委员会负载期间 CPU 采样显示 HTTP 读写与调度开销明显，还不能断言最终瓶颈已经完全定位。

数据见 [experiments/direct-v3-2026-09-19](experiments/direct-v3-2026-09-19/)。这是单机短时实验，尚不能据此宣称高吞吐或长期无积压。下一步应分开测付款提交能力、证明服务能力和成员实际核销速度，在持续负载下观察待办斜率；不能只扩大并行度就宣称解决。

## 当前边界

当前可运行范围是预存真实 CAL/FUEL、组织快速付款、直接责任、自动赔付、迟到处理和后台核销。v3 散户入口、真实补资/奖励领取、物理历史归档和完整长期负载实验尚未完成；旧 v2 散户代码不等于已迁移到 v3。

当前修订接口提供节点观察和全节点已提交记录，**尚未提供相对于任意可信链头的“最新 FundingRevision”独立轻客户端证明接口**。普通钱包的付款/核销证明已验证，但不能把未认证的修订观察 JSON 当作这类证明。全节点通过共识重放校验授权。独立网络冷同步故障矩阵仍须补测，应用从创世重放已实测。

密码实现使用 CIRCL v1.6.5 门限 RSA 原语和 SHAKE256 全域映射。每节点仅持一份；在线不重组完整私钥。初始密钥由可信离线 dealer 生成；Go 大整数计算不承诺恒时，没有 DKG 或本协议的形式化安全证明。测试 PEM 是公开测试夹具，不能用于实际节点。

原始历史、修订和防重记录目前保留，磁盘仍增长；没有宣称已经完成长期裁剪。未形成完整证书的局部批准仍会占用额度，不因超时而擅自解锁。净赔付及 FUEL 消耗是实际成本，自动核销不会补回这些资金。

# 公共提交与新输出 TXCer 分离

> **用户自付修订（2026-09-23）：** 快速路径现支持最终用户 FUEL 输入。自付不占用组织 FUEL/Policy，费用找零和退款作为公开最终输出自行跟块；规则域与结果 tag 更新见[实现说明](implementation-owner-fuel-v4.md)。以下历史说明中的组织代付只适用于 `OrgReserve` 分支。

2026-09-19。用户明确保留组织认证，取消的是本笔新输出 TXCer 的上送。此前“直接删除组织批准会导致强制赔付”的反例不适用于本方案。

## 当前对象与路径

| 对象 | 接收方 | 内容 |
| --- | --- | --- |
| `OutputCertificate`（TXCer） | 收款钱包 | 输出承诺与组织三票，供输出上链前续花 |
| `DirectPayment`（内部编码 405） | 组织成员的 INSTALL、本地待投递保存 | 完整交易、本笔 TXCer、直接输入凭证 |
| `DirectSubmission`（公共编码 406） | 委员会、区块读取方、历史输入修复 | 交易、额度向量、组织消费授权 `SpendQC`、必要输入 TXCer |

网关正常投递和成员备用投递都从内部对象生成公共对象；两种解码器明确拒绝另一种格式。委员会不接收本笔 `OutputCertificate` 对象。它从交易和额度向量重建组织批准的摘要，验证已有三票，不新增签署轮次。钱包、成员、网关按成功区块自行处理状态；没有新增通知服务。

必须准确说明：原 405 编码已经复用交易中的输出信息；406 继续携带同一份必要的组织三票和额度向量。本次对象拆分不是删除三票，也不意味着报文缩短。签名摘要仍绑定交易与输出，不能把组织消费授权与被批准的效果脱离。

## 实际省去的处理

普通付款直接写入最终输出，不再先为本笔新输出创建 `directCoverage`、`directPromise`，然后在同一次执行中解除。CAL 授权身份与金额上限仍检查；费用、工作预算、所有者授权和输入消费检查保留。

只有消费尚未最终成立的输入，才依据该输入 TXCer 登记原组织责任。子交易先到时使用已有责任表；父交易到达时解除已有承诺，不会遗漏其他输出。已赔付后原交易迟到，Paid 保持真实支出，不返还已花的组织本金。

成员签票前的本地输入锁、预算占用与同步写盘保持；成员跟块仍只解除自己确实占用且已经履行的额度。普通交易不需要先建立公共覆盖记录才能返还本地额度。

## 兼容与验证

委员会对公共 406 材料使用本节点的有界静态验证缓存，供接纳、提案检查和执行复用。键为完整原始报文的普通 SHA-256 摘要，包含 OwnerAuth 和 Funding/opening；不使用可保持不变的交易 ID 或变色龙哈希。每个 Engine 的配置快照固定，缓存仅保存已冻结的成功验证结果；输入消费、余额、授权和担保终态仍在每次执行中读取当前账本。

旧／新验证类型各有 2048 条、8 MiB 编码字节预算的 FIFO；超大条目不缓存，重启为空。这不改变编码、账本规则或同步持久化。实验可设置 `UTXO_EXPERIMENT_DISABLE_DIRECT_CACHE=1` 绕过新缓存作同二进制对照，所有验证仍执行。详见 [验证缓存实验](experiments/committee-verification-cache-2026-09-19/README.md)。

公开负载版本由 405 分离为 406，资金规则标识更新为 `DIRECT_ACCOUNTING_V4_INPUT_GUARANTEES`。交易、事实与输出身份的计算算法不变；规则标识本身参与签名，因此新旧规则下生成的交易值不能混为一笔。仅在新创世实验网启用，不把旧数据库与新执行规则混用，不提供在线迁移。

覆盖：公共/内部编码隔离、组织授权缺失/篡改/挪用、普通付款无新担保记录、多输出按需登记、子先父后、超时赔付、迟到、重复投递、成员核销，以及真实 BlockStore/Part 改写与原始执行重放。实测数据见 [本轮验证记录](experiments/committee-input-only-2026-09-19/README.md)。

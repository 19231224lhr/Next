# UTXO＋TXCer 直接担保与输入替换方案

> **历史材料，不是当前规范。** 保留设计来源与旧版行为，勿用于覆盖当前 wire 4 实现。当前入口：[系统设计](../../design/system.md)。

> **当前工程修订（2026-09-19，wire 4）：** 采用[按块处理规范与验证记录](../../reference/implementation-block-following-v4.md)。委员会不生成或提供逐笔到账、核销证明；钱包与成员读取普通区块和执行结果，自行更新币和原签署额度。公共交易只保留直接输入 TXCer 及必要组织费用授权，本次新输出 TXCer 留在钱包与组织内部使用。三票持久签署、后台 INSTALL、原发行组织责任和真实历史输入替换保留。本文下方旧版的证明查询、专用核销接口及 wire 3 启动方式以此修订为准。


日期：2026-09-19。设计版本 v1.2；使用独立创世网络 `ProtocolVersion=3 / WireVersion=3`。

状态：直接责任支付、自动赔付、真实 Comet 历史改写及重放已在隔离原型实现并通过实验；详细证据和未完成项见 [实现记录](../development/implementation-v1.2.md)。v1.1 / wire v2 仍保留为独立基线。本文定义目标规范，不能把尚未完成的最新修订轻客户端证明、散户迁移、归档或持续高 TPS 验收视为已经实现。

## 1. 范围与取舍

采用输出正文与 TXCer 分离、一轮取证、后台 INSTALL。持有人可以使用尚未上链的输出；委员会按担保输入规则确认后继付款，不再因父交易缺失而整体等待。只认当前输入 TXCer 的直接发行组织，不维护 RootFundingID、祖先金额谱系或全局根责任。

采用真实的变色龙哈希开口替换：修改已存交易的当前输入资金引用，交易身份、输出身份及区块身份保持稳定。不能用一个普通数据库查询视图冒充已实现历史交易改写。保留原始执行材料是为了验证、重放与共识传输，不用于撤销用户已经获得的付款结果。

不提前挑选或锁定具体担保 UTXO。沿用组织 CAL 账户、长期预算、成员有界签署权限与 Worker 私有额度；赔付时扣款。首版不做迟到追偿，来源迟到且交易合法时仍给原输出所有者，赔付组织的支出不恢复。本版不研究这一选择的经济激励，但必须计量实际损失。

保留 Go、bbolt、固定四成员及三票门槛、SpendOrg 排他、一轮持久签票、HTTP、中继 outbox、批量提交和已有后台优化。散户仍只能使用已最终输出，不签发或消费 TXCer。FUEL 继续使用已有已落实费用来源，不新增未确认 FUEL 递归担保。

本文对三份主文档中以下旧规则具有替代效力：根资金整体落实、纯转手零新增 CAL、缺父 DEFERRED、TXCer 内嵌完整父交易、迟到回款归组织、普通交易/区块字节完全不可改。其余规则继续使用原规范。旧实验只作为 v1.1 基线。

## 2. 最小对象

| 对象 | 内容与作用 |
|---|---|
| Output | 资产、金额、OwnerLock、SpendOrg；OutputID 由稳定 TxID 和索引派生 |
| TxCore | 原输入权利及描述摘要、输出、组织/网络/版本、费用、预算引用、允许替换规则；不可修改 |
| InputFunding | 每个输入的当前资金引用、变色龙开口；初始指向原输出，赔付后指向专用担保扣款输出 |
| TXCer | 本次认证摘要、输出承诺、预算向量和三票 QC；不含完整父交易或祖先证据 |
| PaymentEnvelope | 当前交易正文、所有者授权、本交易输入所需的直接 TXCer 或最终证明；只携带一层证据 |
| DirectObligation | 缺失 OutputID、原发行组织与配置、金额、唯一消费位置、首次接受时间、到期时间、处置状态 |
| RepairInput | 责任身份、目标交易/输入位置、原/新资金引用及开口、扣款身份、触发依据；通过委员会最终确认 |

本版只有 CAL 快速输出承担本金承诺，金额等于该输出金额。其他资产不能隐式套用 CAL 扣款。

TXCer 的认证摘要绑定本交易 TxID、组织配置、规则、AdmissionVector、确定效果摘要及有界的输出承诺列表；列表每项绑定索引、输出正文摘要、资产与金额。复用一个 QC 认证全部输出，不增加逐输出签名往返。钱包收到 Output 正文、输出索引及 TXCer，校验正文与承诺匹配即可。输出列表沿用现有大小上限，不引入新的祖先 Merkle 证明体系。

组织验证父 TXCer 时不重验其完整父交易业务，但仍验证本次所有者授权、输入唯一消费、金额守恒、费用和本次签署预算。父组织负责自己签发的输出，当前组织负责自己的认证。

## 3. 身份与修改范围

先对不含派生身份、CH 承诺和开口的固定付款内容计算 `CoreHash`，再建立每个输入的变色龙承诺：

```text
Context_i = H(Network, ProtocolVersion, CoreHash, InputIndex, CHKeyID)
C_i       = CH(PK, Encode(Context_i, FundingRef_i), r_i)
TxID      = H("TX_V3", LengthPrefixed(CoreBytes), C_0, ..., C_n)
OutputID  = H("OUTPUT", Network, TxID, OutputIndex)
```

输入原始权利、原描述、金额、资产、所有者、消费路由、收款输出、费用、规则和修改授权均在固定内容中。所有者签名覆盖稳定 TxID；SpendQC 覆盖包含 TxID 与完整资源向量的认证摘要。不得把自己的 TxID 写进 CoreHash 或 CH 上下文形成循环。

赔付只允许 `OriginalOutput → ReserveDebitOutput` 一次替换，金额和资产严格相等。原权利身份继续作为审计和旧承诺防重身份。当前资金引用必须真实变化，不能只改显示文案；CH 等式、修订权限和公共扣款事实分别校验。

修订附件不进入原区块的身份承诺，但修订内容必须进入新区块的 RepairInput 命令，受正常最终性认证保护。仅有一个满足 CH 等式的新开口不构成合法修改。

## 4. 直接责任与正常结算

责任身份使用 `ObligationID=H(Network, OriginalOutputID)`，不使用 QC 字节、重试次数或可变收集器身份。发行组织与完整输出描述一旦绑定就不可更换；多个组织给同一输出提供不一致证明必须拒绝，不能建立两次赔付。

接受当前交易时，所有输入按以下规则在同一 Overlay 内处理：

1. 输出已经最终成立：核对正文、当前消费实例和授权，按普通输入执行。
2. 输出尚未成立且有有效直接 TXCer：验证该证书与输出、预算授权的绑定，记录唯一消费及 DirectObligation，继续创建本交易输出。
3. 已被不同付款消费、证明无效或资金承诺超出准入规则：拒绝整笔交易，不留下部分输入消费或部分责任。

验签可以预先并行；唯一消费、责任准入、创建输出必须在同一次确定性提交中成立。不能以“后台以后检查”为理由跳过这些条件。

本交易入块之后，它的输出已经合法成立。委员会同时处理这些输出对应的既有等待：未赔付的等待终结并解除直接承诺，输出保持已经消费；尚无人消费的输出正常可用。本交易自己的缺失输入责任继续保留。整个过程只访问当前输入、当前输出和对应记录，不遍历祖先。

交易被拒绝或只是存在于区块字节中，不算输出成立。父交易与到期命令同块竞争时，按委员会命令顺序裁决；后到的命令依据更新后的状态处理，不重复结算。

## 5. 预算、费用和责任终态

每次快速签发按其全部 CAL 输出金额（含找零）建立直接承诺：`c_CAL(T)=Σ CAL Outputs(T)`。即使交易输入全部最终成立，只要其输出在未上链时可凭本次 TXCer 使用，仍需该覆盖。不能沿用旧的“纯转手 c_CAL=0”。这是取消祖先责任追踪的明确资金代价。

原成员在现有同一持久事务中占用 CAL、FUEL 和工作额度后签票。委员会首次看见完整证书时可以登记该证书的 CAL 承诺，不要求先收到父交易正文，也不重复注册同一向量。认证摘要必须携带核对 CAL 授权所需的引用与向量，不能只留一个无法解析的摘要。后续完整交易到达复用该登记，不重复占用或收费；CAL 登记不冒充已处理父交易其他业务。

每项输出承诺只有三类资金状态：尚未解除、来源合法成立而解除、已经担保支出。正常来源成立只释放未赔付部分。已赔付输出随后迟到，仍保持 Paid，不能改成 Discharged。

DirectObligation 的状态为 `OPEN → SOURCE_FULFILLED` 或 `OPEN → REPAIRED`；`REPAIRED` 后的迟到创建是独立事实，不重开责任。不需要为每个钱包转手增加责任路径列表。

按原批准事实累计汇总并复用原信用证明：

```text
c_CAL = Remaining + Discharged + Paid
Returned = 0                 // 首版不追偿
Credit = Discharged
Residual = Remaining + Paid
```

未登记的完整证书和局部批准仍可能占用组织成员预算，不因本地超时或委员会暂未观察到就释放。公共赔付终态须保存，旧证书再提交不得重新产生赔付权。只有实际签过的成员按累计差额恢复相应权限。

FUEL 与执行预算沿用生命周期费用计划。当前交易使用证书输入时，在自己的费用计划中以真实 FUEL 预留每个输入最多一次到期履行及修复的成本，覆盖扣款、CH 适配、受影响分片写入及有界修订材料传播，避免等待尚未收到的父交易缴费；未使用部分在来源落实时释放。每项动作按事实身份只收费一次，失败重试不另收一份修复费用，父证书 CAL 登记不重复收取父交易服务费。公共付款完成与全部担保收尾分别计量，不能在付款入块时把尚未完成的修复工作额度或费用一并退回。

公共审计同时统计可花 UTXO、全部真实 CAL 账户余额和未落实缺口。忽略另列的本金增减政策时，`可花CAL＋真实账户CAL－未落实缺口 = 初始CAL＋净外部入款`。待创建的输入描述不另计资产；赔付扣账户并消除等额缺口，不再创建第二份收款余额；迟到交易仍消耗其合法输入。该恒等式是参考模型和集成实验要验证的目标，不代替资金覆盖证明。

## 6. 到期与实际扣款

默认实验参数 `GuaranteeTimeout=30s`，写入创世配置和规则摘要；这是起始实验参数，不是性能承诺。缺口在 H 接受，先记 `AnchorHeight=H+1`，在 H+1 开始执行时用该头中反映 H 提交的共识时间加超时值确定期限。锚定前不能赔付。这样避免空闲停块后 H 的旧头时间让新交易立即到期；不使用本机时钟裁决，重试不能重置期限。此规则已绑定当前 AccountingRuleID。

后台复用到期索引和 outbox，在本机观察到期后提交处理请求，以唤醒空闲停块。预检不能仅因上一个区块时间尚未到期就永久挡住唤醒；最终是否到期只由执行块的共识时间决定。过早请求为未生效、可重试，不能写成已完成业务事实，也不能靠刷新封装无限重复执行同一赔付。

修复操作原子完成：核对责任待决及到期 → 扣原组织 CAL 账户 → 生成唯一 ReserveDebitOutput → 将它分配给该历史输入 → 记录修订及责任 Paid → 写入历史块物理改写 outbox。ReserveDebitOutput 只服务这一项修复，生成即被指定输入占用，不进入钱包可选币池，不增加收款人余额。

先确定 `RepairID=H("REPAIR", Network, ObligationID)` 和 `ReserveDebitOutputID=H("RESERVE_DEBIT", RepairID)`，再生成新 FundingRef、输入开口、受影响分片开口，最后组成 RepairInput。扣款身份不依赖包含这些材料的命令哈希，避免引用自循环；同一责任的重试保持相同 RepairID。

扣款发生在修复高度，不能回写历史账户余额。ReserveDebitOutput 是显式系统输入种类，不能伪装成早在原高度已存在的普通 UTXO。保留组织账户而不建设一套选币/找零子系统，符合用户允许按账户总额履行的方向。

有效预算假设下应有足额资金。若实验注入余额不足，明确记录未履行并停止受影响组织新增承诺，不标记赔付成功、不回滚已经接受的用户付款。罚款不混入本金，首版不自动把超时当成作恶处罚。

## 7. 迟到输出与一次性使用

首版不追偿。原交易在赔付后到达，必须仍通过自身完整规则验证，真实输出才归原用户。无效交易不会因为迟到而自动获准。

原先凭证支持的消费与后来真实创建的可花实例必须区分，不能删除旧消费记录。付款前台仍显示同一输出身份；状态采用 `SpendKey=(OutputID, Incarnation)`：通常为 0，只有“该输出已完成赔付且原交易后来合法成立”才产生实例 1。实例 1 的创建事实绑定唯一 RepairID，不生成第二张原 TXCer，不再次占用或恢复旧赔付预算。

TXCer 只支持实例 0；实例 1 必须先取得公共最终创建证明才可消费。钱包在生成新付款前将实例号写入不可变输入授权内容，成员输入锁、委员会消费表都使用 SpendKey。实例 0 的消费、成员旧锁和赔付防重记录不删除，原旧付款仍是幂等；实例 1 可由原所有者正常支付，但至多创建、消费各一次。原交易只接纳一次，不能再产生实例 2。

这个额外位只区分用户明确允许的两次独立价值来源，不是责任链。历史已创建输出的 OutputID 不变。节点不能仅因一个过期最终创建证明声称输出仍未花费，最终消费检查继续按当前状态执行。

## 8. 真实历史改写与 CometBFT 边界

基线 CometBFT v0.38.26 对交易数据检查 DataHash，并对序列化区块生成 PartSet。变色龙输入替换不能绕过这些检查，也不能只替换 Header.Hash。使用受限兼容分支，不自行重写 BFT 轮次、投票或网络调度。

本版选择真实修改 BlockStore 内历史交易与受影响分片的字节，不采用“原始共识分片不变、只展示新来源”的替代方案。为保持整个 BlockID，创世起同时调整交易数据承诺和分片承诺；不重新签署历史 commit。

交易 DataHash 的叶绑定不可变编码、CH 承诺及不可变证据封装，排除允许修改的 FundingRef/开口；解码时必须校验实际资金引用确实打开该承诺。普通不可改命令（包括 RepairInput）仍对完整规范正文做普通哈希。不能只用 TxID 而遗漏原块中其他不可变内容的承诺。

Part 的叶采用以下构造，已通过密码和真实 Comet 存储/重放实验；不据此宣称完整密码安全证明：

```text
PartContext = H("BLOCK_PART_V3", ChainID, Height, PartIndex, CHKeyID)
PartLeaf    = H(CH(PK_part, Encode(PartContext, PartBytes), r_part))
PartSetHash = MerkleRoot(PartLeaf[])
```

FundingRef 及交易输入开口在所选密码套件下使用固定宽度编码；修复不改变交易/分片数量或长度。Part 开口和修订附件位于 PartBytes 外，不能把它们再编码进自己承诺的负载形成循环。修复受影响分片的新开口，使原 PartLeaf、PartSetHash、Total、DataHash 和区块头保持不变。头、LastCommit、交易顺序和不可变正文不允许修改。

限定适配面如下：

| 路径 | 规则 |
|---|---|
| 历史块存储 | 新增专用修订入口，原子更新目标历史块/Part 字节、开口、版本及缓存；不能拿只允许追加高度的 SaveBlock 覆盖旧高度 |
| 当前正文校验 | 检查稳定交易承诺、Part CH 开口与 Merkle 路径、原头/commit，以及委员会确认的修订；仅 CH 等式不足以认证合法修改 |
| 共识 PartSet | 调整 Part 生成、证明验证和消息编码；BlockID 仍绑定同一个 PartSetHeader，不改投票轮次/法定人数 |
| 区块同步 | 标记块高度和修订版本，禁止混装不同版本的分片；首版从初始版本重放，再按已确认修订改写，避免同步旧高度先依赖未来修复块 |
| 按高度执行与重放 | 原高度执行初始版本，遇到 RepairInput 才扣款、改变责任及物化当前正文 |
| 查询/交易证明 | 显式提供原高度身份、当前修订版本、稳定承诺/Part 证明及修复证明；普通 Comet 旧客户端不能自动验证新格式 |

保存初始输入及开口、原始 Part 开口和不可变其余字段，用于恢复唯一初始字节；不能因物理改写丢弃共识重放材料。对同一旧块的修复按版本顺序执行，多个输入分别修复也不能覆盖彼此。RepairInput 绑定目标旧块、前后版本、修改位置、旧新完整块正文的普通哈希摘要以及受影响 Part 的新开口，提交时基准不匹配则重新准备，不能部分应用。接收方组装后必须匹配该修订的普通正文摘要，并检查仅允许字段发生变化；所有分片都打开原 CH 根仍不足以排除跨版本混装。正文摘要不包含外置修订附件，PartContext 不包含自身 PartSetRoot。

改写版本号不能靠未认证附件自报。目标接口应对公共 FundingRevision 提供相对于已认证链头的最新修订摘要证明。当前全节点已通过共识命令与重放验证修订；独立轻客户端的最新修订证明接口尚未完成，节点观察 JSON 不充当该证明。低版本可以作为历史查询结果，不能伪称已证明是最新版本。不建设另一个历史修订共识网络。

这是 CometBFT 受限协议分支，不是原版客户端兼容补丁。实际改动量以隔离实验结果为准；最小修改指在满足真实改写要求下限定适配面，不能承诺一行完成。

原高度按当时版本执行，修复高度按 RepairInput 扣款；之后才更新历史当前正文。历史 AppHash 与执行结果不回改。新节点不能拿最新资金引用直接按普通 UTXO 规则重执行旧高度。历史修订与付款事实保留同样的可查询最终证明。

应用数据库与共识块存储不是一个事务库。先将 RepairInput 及块改写待办持久提交，再幂等执行物理替换；节点在两者之间退出，重启重做同一待办，不再次扣款。未物化完成时查询必须显式给出版本/待同步状态，不能把过时正文说成最新版本。

委员会固定配置，改写授权为三票；普通成员密钥与 CH 用途分离。实现使用 CIRCL v1.6.5 门限 RSA、SHAKE256 全域映射，每个节点独立持一份并计算适配份额，在线不重组完整私钥。四种三人集合、多次公开适配及真实 Comet 路径已验证。首版可信离线 dealer 生成密钥，未实现 DKG；Go 大整数计算不承诺恒时，也未完成本协议的形式化安全证明。KeyID 与网络创世绑定。

## 10. 实施顺序与验收

按三个功能增量进行，每一项都保持可运行：

1. **协议与改写可行性实验。** 独立新网络/隔离夹具验证 CH 正确构造、固定身份、所有者签名与 SpendQC、真实历史正文变化、DataHash/BlockID/PartSet、改写认证、原高度重放与状态承诺。通过前不替换现有实验节点。
2. **直接责任闭环。** 实现分离 TXCer、输出金额预算、缺父确认、到期扣款、迟到无追偿及同库重启；串接原有费用、核销、INSTALL 和中继。先单组织再双组织。
3. **集成与持续测量。** 四委员会节点、缺父/乱序/赔付/迟到/重启和重新同步；随后比较串行续花与持续负载，保留旧版基线。

必要场景：来源先到；孙交易先到；父交易含另一个缺失输入；同输出冲突消费；多输入多组织；部分输出赔付后父交易到达；父交易与修复同块两种顺序；重复修复；迟到输出合法新消费与旧证书重放；改写待办中断；从创世重放；一个恶意成员提供无效修改；同一旧块多个不同输入被修复；跨修订分片混装和旧版本冒充最新被拒绝。

计量：钱包发送至可续花、公共付款确认、责任解除/赔付、历史正文物化；公共付款 TPS、待决数量/金额/最老年龄、CAL 签署余额与净赔付、每笔验签/写盘/字节、修订量及总排空时间。关闭埋点成对复测。不将“等待交易减少”直接解释成总成本下降。

# 委员会提交与新输出 TXCer 分离

> **历史材料，不是当前规范。** 保留设计来源与旧版行为，勿用于覆盖当前 wire 4 实现。当前入口：[系统设计](../../design/system.md)。

用户已澄清：不删除组织认证，只取消本笔新 TXCer 的上送。按 writing-plans / TDD 执行，继续使用当前隔离工作区，不启动子 agent。

## 实现边界

- 内部 `DirectPayment` 仍保存完整 TXCer，供钱包、INSTALL 和故障补投使用。
- 新公共对象 `DirectSubmission` 包含交易、必要额度向量、已有组织 SpendQC 和输入 TXCer；不含本笔 `OutputCertificate`。复用已取得三票，不新增签署轮次。委员从交易推导签名摘要，验证组织授权。
- 新公共编码与内部编码明确区分。现有内部编码已消除输出摘要的重复传输；分离不会宣称省掉三票或大幅缩小字节。
- 普通新输出直接落账，不预先写本笔 CAL 担保登记。输入确实缺失时才沿用既有责任记录；已有记录仍在来源到达或赔付时正确完成。
- 输出身份、真实费用、输入防双花、成员本地预算与同步持久化保留。公共状态规则更新，实验使用新创世，不对已有实验数据库直接替换规则。

## 模块步骤

- [x] 公共编解码与组织授权验证；测试公共/内部格式隔离、签名不可挪用。
- [x] 网关、成员补投、委员会执行、钱包和成员跟块、历史输入修复切换公共对象；不改变内部 TXCer 交付。
- [x] 按需登记；测试正常付款无冗余记录、多输出/子先父后/赔付/迟到及本地核销。

## 先前反例的适用范围

测试中缺少本笔组织批准可造成强制赔付；本方案保留批准，不属于那个反例。先前将“取消新 TXCer 上送”解读为“删除组织认证”已纠正。

# 正常结算改为按块处理

> **历史材料，不是当前规范。** 保留设计来源与旧版行为，勿用于覆盖当前 wire 4 实现。当前入口：[系统设计](../../design/system.md)。

日期：2026-09-19。依据：用户明确要求取消委员会面向钱包、担保成员的逐笔通知与核销证明工作。本文是针对 `039374d` 的已执行修改方案；当前 wire v4 实现与实测见 [实现记录](../../reference/implementation-block-following-v4.md)。

## 目标路径

钱包发送 → 组织持久签票 → 钱包收到输出与 TXCer，可续花。

后台只做：提交交易 → 委员会执行并正常出块 → 钱包、成员和中继按高度获取已确认区块及执行结果，各自批量更新本地状态。

输入使用哪个 TXCer，就保留哪个 TXCer。委员会只检查该输入的直接责任，不取父交易正文、不递归取祖先证据。当前输出的新 TXCer 服务于快速交付，不作为正常上链必须附带的完整对象。

## 必要改动

| 模块 | 修改 |
|---|---|
| 协议提交格式 | 区分本地快速交付包与公共交易。公共交易包含固定交易、输入 TXCer、必要费用授权；去掉重复的本次输出证书正文。输入证书字段统一叫 InputCertificates，避免 Parents 被误解为祖先历史。 |
| 费用授权 | 当前组织 FUEL 代付依赖组织批准，不能删掉后允许任意钱包扣组织账户。复用已有三票作为最小组织授权，委员会从交易重建被签摘要；不增加第二轮签名，不再重复传输完整输出承诺列表。 |
| 委员会规则 | 保留唯一消费、输出创建、真实账户、公共责任、授权约束和实际费用。移除仅服务成员恢复额度的 CreditReceipt 生成与外部核销事实；成员签署额度由成员本地管理。公共资金覆盖计数不能作为“通知”一起删除。 |
| ABCI / finality | v3 后继版本取消专用事实证明树、逐事实位置索引和正常付款证明查询接口，保留确定性的应用状态承诺。使用正常区块与 Comet 执行结果；所需实际费用等数据来自正常执行结果或共享确定性规则，不生成面向收款人的通知。 |
| 按块读取模块 | 共用一个小型 BlockFollower：按高度拉取、验证最终确认和整批执行结果，交给钱包/成员/中继应用。只处理与本地索引相关的交易，不能给每笔付款启动独立轮询。可从普通节点或缓存取得相同公共数据。 |
| 钱包 | 根据成功交易创建的输出更新已有币记录，核对固定输出与实例，去掉 TXCer。无需每笔 FactOutputCreated 查询。 |
| 担保成员 | 根据本地原批准记录和区块结果计算额度变化，每块一次本地事务。正常已落实且未赔付的 CAL 释放；Paid 不恢复；FUEL 只释放未用部分，未完成修复的预留继续占用。不要求委员会知道哪些成员需要通知。 |
| 中继 | 后台 INSTALL 保留组织证据传播。公共投递与观察分开；按块观察到付款成功后停止补交，由块处理更新后续本地待办。未成功确认时继续复用原交易重试，不能仅凭“交易池已收到”停发。 |
| 测量 | 改为钱包发送至快速到账、节点成功提交、钱包跟块观察、成员实际应用额度与队列排空。删除“取得全部专门核销证明”作为实验完成门槛。 |

## 按块确认的准确含义

Comet 区块可能包含业务执行失败的交易，不能仅搜索交易哈希就恢复额度。读取模块一次验证区块及其对应的整批执行结果，按成功结果处理。采用现有 Comet 结果承诺时，H 的执行结果由 H+1 的 LastResultsHash 认证；这不需要委员会为每个用户另外签名或生成证明。仍保留协议必要的后续块，不能把取消逐笔证明误写成一定省掉一个出块间隔。

每次本地应用把块游标与余额/额度变化原子提交；重复块无额外效果，断线按高度补齐。失联节点在追上所需公共状态前不提前恢复额度。这里只做已有同库重启，不扩展损坏数据库恢复。

历史改写继续按原始共识执行顺序和后续 RepairInput 处理。不能从改写后的旧块显示内容倒推出赔付早已发生，更不能重复扣款。原始执行材料与改写授权继续保留。

## 实施与验收顺序

1. 实现区块/结果验证及本地按块应用，验证正常付款、失败交易、重复块、漏块补齐和原批准额度恢复。
2. 接入公共交易精简格式、钱包和中继，删除正常路径的旧证明生产与查询。旧代码仅保留为独立 v2/v3 实验基线，不让两套后台同时运行。
3. 验证缺失输入、父交易到达、先赔后到、费用收尾及历史改写；原组织责任不转移，实际赔付不返额度。
4. 在独立新创世实验网比较单笔、连续续花和持续负载。确认正常路径不调用逐笔证明接口，并分别报告提交 TPS、跟块处理能力、真实成员核销速度和待办斜率。

本次变更涉及线格式和应用状态承诺，需要新网络版本；不修改现有实验链历史来迁就新规则。正常前台仍保留三票、验签和同步持久化。

# 证据驱动的来源恢复与经济／表示分离

2026-10-02 · 分支 `feat/review-source-recovery` · 实现基线 `0e7bae5`。

本文定义当前分支对第三项贡献的补强。正常付款仍是一轮组织取证后可续花，委员会仍从区块公开结果驱动钱包和成员更新；新增工作只处理来源交付失败及到期责任。

## 1. 三个不同的问题

1. **来源材料交付失败**：用户已经取得并使用 TXCer，但原交易的完整证书未 INSTALL、未提交。原签名成员有正文，却缺完整 QC。
2. **适配服务暂时不可用**：来源超时，备付足够、委员会正常，但门限适配暂时无法凑齐。赔付不应因此等待。
3. **历史表示追平**：多个来源已经赔付，需要合并修复，且落后节点不必逐个安装中间版本。

对应流程为：公开后继暴露父 QC → 原签名成员合法重建／补交 → 未及时成立则公共决定赔付 → 后台适配及授权表示 → 本地物化。迟到来源仍按既有代位回收规则归还实际赔付组织。

## 2. S1：公开证据补交

`Approval` 在批准原事务中保留 `DirectParents`，保存当前直接输入证书，复用既有 `Direct` 正文与 `Admission`。跟块处理每笔成功付款时，对其直接输入证书依次检查：

- 属于本成员服务组织；
- 本地没有该事实的成功执行标记，也没有现存 outbox；
- 本地确实存在原批准及正文，正文、准入向量和公开证书摘要绑定同一 Fact；
- 重建的 `DirectPayment` 通过正常验证器。

随后在同一个跟块事务写入现有 outbox；中继在事务外提交同一已授权付款。重复暴露不重置已有重试时点。普通 INSTALL 成功的付款沿原备用路径；无需重新签名、重新收集 QC，也不对用户增加确认往返。来自另一组织的公开后继同样可以触发恢复。

每次处理当前直接来源。多层扣留时可能逐步触发更多补交，**总后台工作随实际缺失交易数量增长**。至少一位原诚实签名成员保留材料、可跟块并可服务，是恢复条件；没有可得材料时仍走责任赔付。实现保留原批准记录，不新增历史裁剪策略；内存模式的保留不表示掉电耐久。

## 3. S2：唯一经济入口

### 3.1 公共赔付决定

`CompensationDecision = (Network, Output, Height, Transaction, Input)`，规范编码 88 字节、魔数 `CMPDEC05`。它是无需提交者签名的维护命令，授权来自公共账本中已成立、已到期的直接义务。任何提交者对同一合法目标产生相同字节。

执行顺序：

1. 已有相同成功决定：返回无效果成功，不写状态；同 Output 但字段不同则拒绝。
2. 核对义务仍 Open、目标低于当前高度；位置、网络、输入槽先用小记录比较，错误请求不加载历史块。
3. 依公共块时间检查到期，核对规范历史中的消费者 TxID/Fact、金额、原 Funding 引用与 opening，以及固定长度可替换性。
4. 执行既有本金、费用和责任转移；只有实际 Applied 后才记录不可变决定与待表示索引。

一次原子提交完成：`扣备付 → Open→Repaired → 关闭直接缺口 → 推进费用／额度记录 → 保存表示授权`。不请求输入适配或分片适配，不生成第二份收款输出。

来源先成立时，决定被拒绝；决定先成立、来源随后执行时，义务进入 Recovered，真实回款归还原赔付组织。不可变决定保留实际发生过的扣款及表示授权，不因回款撤销。

### 3.2 表示与物化

`RepairInput`／`RepairBatch` 读取成功决定，核对当前规范槽仍为 OriginalFunding，收集输入与分片适配，验证固定字段、完整 BlockID 和精确新正文。公共表示执行只写修订、任务和索引，不再次扣本金，不推进费用、不增加收款输出、不释放额度。

成员和钱包只从公共决定的 415 结果应用经济效果。416 表示结果在公共跟块接口投影为零经济效果。物化沿已提交任务写入 BlockStore，不重新执行付款；落后节点仍能直接安装最新已授权版本。原始块继续保留用于执行重放。

### 3.3 对象与存储映射

| 对象／状态 | 实现 | 语义 |
| --- | --- | --- |
| 原批准中的直接输入材料 | `state.Approval.DirectParents` | 来源重建材料；不新增原批准 |
| 不可变赔付决定 | `DirectRepairTodo`，键 105 | 原责任快照、Debit、完整 Decision、DecisionHeight |
| 未完成到期义务 | 键 112 | 公共决定工作器扫描，经济关闭后移除 |
| 待表示决定 | 键 116，按历史高度索引 | 表示成功后移除，失败不丢任务 |
| 全部成功决定索引 | 键 117，按历史高度索引 | 保留规范结果研究／核查的决定集合 |
| 已提交修订及物化任务 | 既有 108/109/110/113/114/115 | 确切正文、版本、完整分片材料与物化游标 |
| 公共经济结果 | 415 `CompensationResult` | 单义务效果及费用输出，严格绑定决定身份 |
| 公共表示结果 | 416 `RepairResult` | Command、Applied，无经济效果 |

独立工作器每 2 秒扫描最多 64 条到期记录、每轮处理最多 32 条，游标跨失败条目推进；提交接收不等于删除待办。表示工作器独立扫描 116 并请求门限适配；物化工作器处理已授权任务。三者共享状态接口，不共享同步网络等待，不增加消息中间件。队列容量和轮询间隔是工程参数，不是协议的无条件完成时间界。

## 4. S3：本轮验证到哪里

已用真实门限 RSA、真实修改后 Comet 区块验证：同一组已决定槽位，从原始块一次合批、按顺序逐项、逆序按 1/2/3 项分组，得到相同规范正文和相同分片 opening；测试包含 1/2/4/8 个输入及跨两个真实分片。已提交中间版本可以不物化，直接准备最终物化。

这支持“固定目标集合的修复结果可收敛”，不表示任意普通节点可凭决定自行计算 opening。对正确生成、满足指数与群阶互素的 RSA 参数，固定承诺与新消息在相应群中有唯一 opening，规范固定宽度编码给出唯一字节表示。参数生成、消息域绑定及两层承诺仍是该论证的前提。

**本轮保留 Base/Previous 和公共表示命令。** 删除它们还需要确定 opening 的可得性、可信取回接口、冻结前缀及版本编号；目前没有为这项扩大改动提供网络收益证据。相同最终表示不意味着经济命令可无序执行，也不意味着最终应用状态哈希不包含不同修订命令的历史差异。

## 5. 不变量与代码证据

| 性质 | 边界及验证 |
| --- | --- |
| 补交不扩大授权 | 相同原 Tx／Admission＋有效公开 QC；使用原正常验证器，无新用户签名 |
| 一项直接义务至多扣一次 | 决定先检查不可变记录；相同重复零 effects；来源先到拒绝 |
| 无决定不得适配 | `InputTarget` 必须读到成功决定，原槽与决定位置严格一致 |
| 回收不撤销修复权限 | 表示读取决定快照而非当前 Open；已回收来源仍能表示 |
| 表示不重复信用 | `DecodePublicExecution` 将 416 投影为空；成员 Progress／Worker slices 字节不变测试 |
| 物化不影响账务 | 物化前后全账本比较；重放原始块逐高度 AppHash 和状态记录一致 |
| 后继保持 | 固定授权、TxID／OutputID、完整 BlockID／PartSetHeader、后继正文和预签后继消费检查 |
| 适配不阻塞经济关闭 | 独立决定循环；所有适配服务暂停的真实网络对照 |

主要测试：`internal/member/source_recovery_test.go`、`blocks_test.go`，`internal/redaction/decision_test.go`、`payment_test.go`、`batch_test.go`、`canonical_test.go`，以及 `protocol/compensation_test.go`。网络数据见[本轮实验报告](../experiments/c3-source-repair-2026-10-02/README.md)。这些回归和故障实验支撑明确场景的实现结论；一般条件证明与论文主张需保持相同假设。

## 6. 升级与实验控制

统一升级并重新创世。Accounting 域为 `DIRECT_ACCOUNTING_V5_DECISION_FIRST`，单项／批表示魔数为 `REPAIR5\0`／`RPBATCH5`，旧耦合 414 结果不在新路径接受；成员存储 schema 为 7。旧 E1–E8 数据保留原提交版本与语义，不能被解释为本次新功能实验。

- `UTXO_EXPERIMENT_DISABLE_SOURCE_RECOVERY=1`：关闭 S1 自动重建，仅用于消融；普通 INSTALL 备用中继仍存在。
- `UTXO_EXPERIMENT_ADAPTATION_PAUSE_FILE=<path>`：标记存在时，适配 HTTP 端点返回暂停；不暂停决定、共识和支付。用于故障注入。
- `demo-v4 -withhold-parent -recover-source`：原发布者不补交，等待自主恢复。
- `demo-v4 -withhold-parent -wait-repair`：观察赔付、实验性迟到来源回款，以及四委员物化。

本轮不宣称触发机制优于具有同等信息的周期扫描，不宣称无条件降低赔付率，也不把表示修复当作经济闭合的必要步骤。第三项的具体价值是：**公开后继证据可以帮助恢复其缺失来源；经济闭合不等待密码学适配；授权修复保持后继及完整共识身份。**

# 迟到来源的代位回收

> **2026-10-02 版本更新：** 当前分支的公共赔付与历史表示已拆分，新增公开证据来源补交；编码和状态映射以[本次规范](evidence-driven-source-repair.md)为准。本文原版本流程与实验记录保留用于对照。

本修订改变旧版“先赔付、迟到原来源再给用户创建 instance 1”的归属政策。适用于统一升级、重新创世的实验网络；新规则摘要和执行结果编码与旧政策分开。

## 规则

已消费的输出 x 有唯一直接义务。正常来源先执行，义务 Open→Fulfilled；赔付先执行，Open→Repaired，扣其原发行组织备付。此后合法来源执行时，Repaired→Recovered，将同额 CAL 归还**实际赔付的原发行组织**。不创建用户的第二份输出，不撤销或重签后继，也不重做赔付费用。

回款在原付款成功执行的同一事务内发生。该付款自己的输入仍按现有规则验证、消费或建立直接缺口；不存在独立的“申报已回款”入口。来源自身仍有缺口不阻止回收：其输入责任由对应直接发行者的独立备付覆盖，和普通付款产生的可用输出具有同样的公共执行语义。不增加祖先谱系或可撤销回款。

## 记账与认证

- `Paid` 保留累计真实赔付；`Recovered` 单调记录已执行来源追回额，且 `0 ≤ Recovered ≤ Paid`。
- 原覆盖恒等式 `Original = Paid + Discharged + Remaining` 保持；公共 `Spent = Σ(Paid−Recovered)`，授权 `Grant` 不因回款增加。
- 账户加回 a 与旧授权净支出减少 a 同时提交，因此 `Σ(Grant−Spent) ≤ reserve balance` 两边同增 a。回款不是外部补资，不能再走增加 Grant 的路径。
- `ExecutionResult.RecoveredOutputs` 是当前交易输出序号的规范有序列表；身份、金额、发行者由该已认证付款推导。它属于区块执行结果，不是额外委员会通知。
- 新付款结果编码 412/413 拒绝旧 410/411 的迟到实例语义，批修复结果使用独立标签 414；规则摘要改为 `DIRECT_ACCOUNTING_V4_SOURCE_RECOVERY`。

成员只恢复自己曾占用的额度。观察到自身付款成功后，累计目标为 `cap−(local Paid−local Recovered)`。此次源执行会偿还该付款所有已赔付输出；成员核对公共回款总额不少于本地记载的 Paid，然后仅令 local Recovered=local Paid。迟到补签者若未记载那次赔付，不凭公共金额获得额外额度。成员存储模式版本增至 6。

钱包将回收输出保存为 `Recovered` 终态标记，既无 TXCer，也无可花 final creation；`DirectFinal` 返回 false。`DirectRecovered` 单独报告来源执行后的回收观察。迟到重复证书不覆盖该标记，重新构造花费被拒绝。实验驱动分别观察正常最终输出和代位回收，不能把回收称为再次到账。

## 安全性质

1. **至多一次回收**：付款 Settled 防重与义务终态共同约束；重复来源、补投、跟块不改变账户和额度。
2. **归属守恒**：迟到付款的输出中，尚未赔付部分正常处理，已赔付部分只偿还实际赔付的发行组织。总 CAL 仍满足 `U+A−D=C0`。
3. **无延迟本金收益**：从无 Open/Repaired 义务及无历史净赔付的合法初态出发，固定同一有限、依赖无环、互不冲突且最终每笔恰好成功执行一次的付款集合，所有非创世来源均在集合内，并固定相同且均成功的外部补资；参考历史与实际历史中的该付款集合都恰好成功执行一次，实际历史只包含这些付款、补资及到期赔付。在这些条件下，在费用之外，任意来源/子付款/合法赔付交错后的用户 CAL 分配和各发行组织净本金，与无延迟执行一致。此命题不宣称无手续费、无占用成本，亦不保证永不到达的来源可回收。
4. **局部覆盖**：新缺口仍由新直接发行者独立准入，回收不削减其备付或解除其责任；旧赔付者的账户及净授权同步恢复。
5. **历史修复独立**：既有修订表述仍指向那次真实备付扣款；回收是随后发生的新经济事实，不抹除赔付记录。原始命令重放重新产生扣款与回款，物化不重复经济效果。

有限枚举与代码回归验证上述转移的实例；一般性结论仍依赖正文声明的固定配置、法定人数、诚实状态不回滚及正确公共执行假设。

当前网络赔付入口仍将经济扣款与经验证的逻辑修订联合提交：必须先通过目标正文、opening 与完整 BlockID 验证。资金安全不变量不依赖适配器的建议，但赔付进展需要可用适配贡献；后台物理安装不重复经济效果。这里没有新增独立的追加式赔付入口。

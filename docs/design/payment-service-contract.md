# 快速支付服务契约

本说明对应现有 wire4 实现。本轮澄清服务语义，不改变 Intent、签发、赔付或历史修复协议。

## 三个时点

| 时点 | 已成立的事实 | 下一步条件 |
|---|---|---|
| 钱包验证并记录 TXCer 与输出 | 三个不同成员对同一摘要签名；摘要绑定交易、输出、发行组织及资源授权。诚实成员在签名前原子记录输入锁与额度预留 | 收款方可以立即构造后继请求；后继仍须通过所有者授权、路由、输入、Intent、费用和资源检查。持有证书本身不登记公共赔付义务 |
| 后继成功公开消费尚未创建的认证输出 | 委员会在同一原子转换中记录输入消费、直接发行组织的义务、缺口和后继输出 | 来源可以补交；公共截止期和费用托管等状态约束后续赔付。被拒绝的后继不产生部分生效的义务 |
| 来源落实或赔付决定公开执行 | 来源执行关闭缺口；仍未落实的到期义务由发行组织备付支付。已执行后继不重复入账 | 赔付后来源成功执行会偿还原备付账户，不创建第二份用户输出。表示修复另行推进；截止期到达本身不是固定时间内完成的承诺 |

## 额度不足时如何停止

成员按请求指定的资源和 Worker 切片检查 `Available >= Cap`。首次批准的事务中，任一资源不够即返回 `ErrLimited`；该次事务不提交输入锁、额度或批准，也不返回签名。此前已经成功的其他成员批准不因这次失败而取消。已存在、未被失效的批准可幂等重发签名，不是新开一笔额度。

收集者只有得到三个匹配且有效的成员签名才返回证书；钱包验证完整证书后才能记录认证到账。因而停止发生在不能取得法定人数批准时，不必等到公共备付余额为零。这是签发路径的资源守卫，不是跨收集者的统一接单闸门，也不保证每次请求都最终获证。

正常跟块核销只恢复本成员有凭据的原始扣减；已成功公开执行的同配置冲突付款可证明特定未获证候选不可能形成有效 QC，才允许窄范围失效回收。超时、收集者失联、未查询到完整 QC 或仅因 Intent 公开落败均不授权释放输入锁或已认证责任。

## 谁承担风险

缺失来源的直接发行组织承担已登记义务的 CAL 本金。费用由用户最终 FUEL 输入或经授权的费用账户承担；费用赞助方不必是承担本金损失的组织。费用 Subject 策略不等于 CAL 担保准入。

当前实现没有统一的 Subject 级 CAL 准入，也没有跨收集者未完成请求数上限。依赖受控工作负载的持续进展结论必须保留其部署前提；开放部署允许恶意请求造成备付损失与额度滞留。

固定、无新增补资的 grant 下，每个公开前缀的净未偿赔付满足 `S_g <= Q_g <= B_g`。这不是生命周期累计赔付毛额的上界，也不是始终有额度接新单的保证。合法补资从独立未受保护账户转入并增加授权，可以缓解容量不足，但不解除冲突锁，也会增加新的风险敞口。

# 当前系统设计

> **wire 4 实现基线 · 2026-09-25 · 非形式规范**
>
> 本文整合当前快速支付流程及已知边界，供阅读代码和后续论文建模使用。它不是已经冻结的形式模型，也不宣称已经完成安全证明。整理依据为代码基线 `918acd3`、现行实现说明和 E1–E8 报告。

## 1. 目标与范围

系统使收款人取得尚未公共结算的 CAL 输出及其 TXCer 后，能够继续付款。用户不必逐对建立支付通道或维护通道路由流动性。研究重点是支付便捷性、快速可用性与担保兑现；吞吐量是实现的支撑指标。

当前原型使用固定组织与委员会配置。一个组织有四名独立验证成员，三份匹配批准构成认证；委员会也使用固定四节点配置。组织故障假设与委员会故障假设分别讨论，不能把两者合并成一个“三票就一定安全”的结论。实验网络预置可信配置，不代表已实现开放网络自动发现、动态治理或无配置接入。

CAL 用于本金、组织备付和赔付；FUEL 用于生命周期费用。用户自付最终 FUEL 是已实现路径，组织代付是可选路径，旧实验采用哪一种由报告明确说明。成员与钱包保存方式由运行配置决定；内存/NoSync 实验仍有原子状态更新，但不提供掉电后不丢状态的保证。

## 2. 参与方与信任边界

| 参与方 | 责任 |
| --- | --- |
| 付款钱包 | 选择输入、确定收款描述、费用与资源上限，签署交易 |
| 收款钱包 | 验证输出正文、TXCer 绑定与组织认证，原子接收；随后可以构造后继付款 |
| 网关/收集器 | 转发交易、收集匹配批准、交付凭证，安排有界后台任务；不是资金裁决者 |
| 组织成员 | 独立验证授权、输入、消费路由和资源；记录占用后签票，按块更新本地状态 |
| 委员会 | 确定命令顺序，裁决消费、资金、费用、直接责任与赔付；正常公开区块和执行结果 |
| 后台中继与跟块器 | 传播完整材料、补交公共交易、验证公开事实并在本地应用，不另发私有核销证明 |

跨组织验证使用可信组织配置对应的签名规则。缓存只能省去已验证静态材料的重复工作，不能免除当前消费、余额和预算检查。消费路由 `SpendOrg` 指定当前输出的消费裁决组织；这是防止用户向互不相交的组织重复取证所需的约束，不是资产进出域或双边支付通道。

## 3. 协议对象

| 对象 | 含义与去向 |
| --- | --- |
| `Output` | 金额、资产、所有者和消费路由等输出正文 |
| `FastTx` | 不可变付款内容、所有者授权，以及允许修订的输入资金引用 |
| `OutputCertificate` / TXCer | 将具体输出与交易、规则、预算向量及组织三票绑定；不是独立一份货币 |
| `DirectRequest` | 提交给组织成员的交易与直接输入材料 |
| `DirectPayment`，tag 405 | 组织内部 INSTALL/保存材料，含本次新输出 TXCer |
| `DirectSubmission`，tag 406 | 公共交易、额度向量、组织消费授权 `SpendQC`、必要输入 TXCer；不包含本次新输出证书对象 |
| `DirectObligation` | 当前缺失输入的唯一直接责任，绑定原输出、发行组织、金额与消费位置 |
| `RepairInput` | 委员会确认的到期赔付及受限输入修订命令 |
| `ReserveIncrease`，tag 420 | 实际 CAL 转入及同一授权的增量，属于可选实验管理操作 |

输出身份由稳定交易身份与输出索引派生。证书认证必须与输出正文对应，不能只验证一个与金额、所有者脱离的签名。公共提交保留组织消费授权，不是“取消组织认证”；它只是分离本次新输出凭证与公共执行所需材料。

## 4. 完整付款流程

1. **准备。** 钱包使用已最终 UTXO，或使用尚未最终输出并附上其直接 TXCer。用户自付费用时，另引用自己已最终成立的 FUEL 输入。每一输入都需要本次付款的所有者授权。
2. **请求签发。** 网关向组织成员并行分发同一请求。成员独立核对组织和规则配置、金额、凭证绑定、消费路由、输入唯一占用与本次资源向量。
3. **原子批准。** 成员在同一事务中记录输入锁、CAL/工作额度及适用的费用占用，成功后返回批准。重试复用同一事实，不能重复扣占用；局部批准不能冒充完整凭证。
4. **快速接收。** 取得三份匹配签名后，网关交付输出和 TXCer。收款钱包验证并完成原子接收，即到达快速可用终点，可以用该输出构造后继交易。
5. **后台推进。** 完整材料保存、INSTALL 与公共投递按现有有界任务机制推进；快速接收不等待 INSTALL 回执。正常由网关首投，成员在有限延迟后备用补投。HTTP 接收成功不等于公共结算成功。
6. **委员会执行。** 委员会按确定顺序原子处理输入、资金、责任、费用和输出，再提交区块状态。前置缺失但直接担保有效、且满足准入时，不以等待完整祖先链作为入块前提。
7. **自行跟块。** 钱包、网关和成员验证普通区块及执行结果，分别更新币、停止重投和回收确实可释放的额度。失败执行或重复空结果不产生第二次业务效果。

同组织与跨组织遵循相同付款语义。同组织可复用本地静态验证结果，跨组织需要可信的对方配置及实际通信；不能由同机实验推导任意网络下跨组织零成本。

旧设计保留“散户只用最终输入直接提交委员会”的业务方向；不能由快速路径 E1–E8 推定现有 wire 4 的散户迁移、全部兼容接口已完整验收。将其纳入论文模型前需单独核对实现范围。

## 5. 直接责任与迟到来源

委员会接纳消费时，在同一状态事务内区分：来源已成立则正常消费；来源未成立但直接 TXCer 有效则登记唯一消费和直接责任，继续建立本交易输出；已被其他交易消费或准入无效则拒绝整笔交易。防双花和资金准入不能留到事后再做。

责任跟随所用 TXCer 的原发行组织。当前交易输出成立后，可以解除此前消费这些输出的直接等待；该交易自己的缺失输入责任仍独立保留。不携带祖先金额谱系，不沿根责任追踪全部历史。

| 事件 | 责任与资金结果 |
| --- | --- |
| 前置正常到达 | 对尚未赔付的直接责任完成来源履行；已被子交易消费的输出不再次变为可花 |
| 到期赔付 | `OPEN → REPAIRED`；从原组织账户真实扣 CAL，补齐指定历史输入来源，不增加后继钱包余额 |
| 正常履行 | `OPEN → SOURCE_FULFILLED`；按事实解除允许释放的占用 |
| 赔付后合法前置迟到 | 不追偿、不恢复已赔本金；按独立迟到实例处理原所有者的真实输出 |
| 重复消息/重复修复 | 复用责任及修复身份；不能再次扣款、创建赔付或回收同一份额度 |

当前状态区分 `SpendKey=(OutputID, Incarnation)`。TXCer 只支持通常的实例 0；赔付后前置合法成立才创建实例 1，该实例必须按最终输出使用。原消费记录与赔付防重状态不删除。迟到来源仍要验证并真实消耗其父输入，不因为“迟到”而免检。

实验默认担保期限为 30 秒，绑定创世规则。缺口以接受高度的后续区块时间锚定，最终到期裁决使用已提交区块时间，重试不延长期限。后台请求可以唤醒空闲委员会；本机时钟不是资金裁决依据。该参数不是所有部署的固定保证。

## 6. CAL、费用与工作权限

成员按本次全部 CAL 输出金额（含找零）占用直接担保权限。即使输入已经最终成立，本次输出仍可能提前被消费，因此不能沿用旧版“普通转手 CAL 占用为零”。成员权限有重叠，不能把四名成员额度相加当成真实备付；Worker 的私有份额则在该成员内部排他分配。

用户自付 FUEL 不占组织 FUEL/Policy 授权。委员会消费用户最终费用输入，将最大费用放入托管，超出部分找零；按实际工作收费，必要收尾后退回未使用预留。找零和退款都是最终 FUEL 输出，不签发快速 TXCer。组织代付分支单独计入相应资源。

额度恢复以原签署事实和累计已应用进度为准。仅实际占用过的成员恢复差额；未成证局部批准不得因超时擅自清锁；实际赔付和费用不能当作未损失资金返还。公共付款完成、责任关闭、费用收尾和物理历史修订是不同阶段。

E2 动态补资从有限外部账户实际转入 CAL，并增加原 Grant 的容量；没有重置原锁和批准，也没有凭空增发。控制器采用声明的实验需求与成员水位，不是已经实现未知用户流量预测。其具体公式、命令与限制见[补资细节](../reference/implementation-adaptive-reserve-v4.md)。

## 7. 受限历史输入修订

交易将不可变付款授权与可变资金来源分开。合法赔付允许把指定输入从原输出来源替换为等额、同资产的专用担保扣款来源；用户输出、所有者、金额及稳定身份不变。

变色龙哈希维持交易/区块承诺，委员会的已确认 `RepairInput` 授权具体修改。仅满足哈希等式不够；必须验证修订位置、版本、原新正文摘要、扣款事实与受影响分片。新高度执行扣款，不能回写旧高度账户余额。

Comet 适配保留原始执行材料用于重放和同步，再按已确认修订物化历史正文。真实 BlockStore/Part 修改与应用资金提交分属不同存储边界，由待办衔接；不能把“物理字节改好了”当成资金已再次执行。独立轻客户端验证最新历史修订的完整接口仍属未完成边界。

密码学实现采用独立用途的门限材料和可信离线初始化；未实现 DKG，不承诺 Go 大整数运算恒时。具体修订构造保存在[历史详细设计](../archive/design/utxo-direct-liability-amendment-v1.2.md)与[Comet 适配说明](../../third_party/cometbft/README.md)，旧文中专用证明接口不属于当前正常付款路径。

## 8. 原型边界与后续建模

本轮整理不改变代码。形式模型应从本基线及字段细节抽取，并逐项核对当前状态转移，而不是把历史设计中的计划能力视为已经实现。

- 固定组织配置、签名和哈希安全、诚实节点不遗忘已签状态等假设必须明确。
- E2/E4 的局部批准残留说明安全不等于无条件活性；完整证据与实际诚实补投者也是进度条件。
- E3 验证所测责任与修订场景，不代替一般拜占庭证明；E8 保留历史内存增长限制。
- 不把内存/NoSync、单机网络延迟注入或不等价 Lightning 对照扩大为生产恢复、WAN 共识或全面优越性结论。
- 资金守恒、预算覆盖、跨组织唯一消费和修订一致性均为待正式论证事项。

## 1. 工程与进程

项目使用 Go，模块为 `utxo`，Go 版本由根目录 `go.mod` 固定。委员会依赖 CometBFT v0.38.26 的受限适配，构建前运行 `third_party/cometbft/overlay.py`，生成被忽略的 `.scratch/comet-src`。补丁源必须保留，生成的上游副本可重建。

默认双组织实验网包含四委员、八成员和两网关，共十四个服务进程。单组织性能轮使用九个服务。钱包可以运行在实验驱动进程中，E7 另有独立收款路径；这些部署不能混为相同网络模型。

## 2. 数据与调用边界

`DirectRequest` 进入成员批准路径；成员从规范字节解码和验证，不能信任调用方传入的预解析对象。三票形成输出凭证后，内部 `DirectPayment` 用于保存/INSTALL，公共 `DirectSubmission` 用于委员会接纳和区块执行。

公共提交仍含 `SpendQC` 和资源向量。静态验证可以缓存成功结果，但缓存键绑定完整原始报文及配置范围，不能只用修订后保持不变的 TxID；输入消费、余额、授权和责任终态需要每次读取当前状态。

费用来源分别处理用户最终 FUEL 与组织代付。执行结果中的公开费用输出供所有跟块方处理，不是委员会向特定用户推送私有消息。当前用户费用输出 tag 为 411，无费用输出结果仍可为 410；`comet_v3` 是编译开关名，不代表当前协议退回 wire 3。

字段级说明集中在 [reference](../reference/README.md)。逐项对象名称和编码以代码为准；如果代码与说明冲突，应记录差异再决定模型，不默认把旧文档覆盖到实现。

## 3. 并行与原子边界

| 工作 | 可并行部分 | 必须保留的顺序 |
| --- | --- | --- |
| 成员批准 | 网络分发、静态验证、独立请求准备 | 同一成员事务检查最新消费/额度、原子占用，成功后签票 |
| 快速交付 | 与网关保存、INSTALL、公共投递重叠 | 钱包验证绑定与认证、原子接收后才报告可用 |
| 后台投递 | Submit 和成员 INSTALL 使用独立有界任务 | 事实/动作防重；公共终态胜过迟到保存与重试 |
| 委员会 | 接纳预检、静态证据验证与缓存 | 共识命令顺序、最新资金裁决、块末提交 |
| 跟块 | 事务外解析与认证 | 事务内按顺序应用状态并推进游标 |
| 历史修订 | 份额准备、物理修订待办 | 新高度确认扣款与修订命令，按版本应用，不再次扣款 |

网关正常首投和成员备用不是选主协议。备用期限有限，重复 INSTALL 或一次 HTTP 接收不能永久推迟补投。已经公共完成的事实不会被迟到保存或 INSTALL 重新建立为待办。

## 4. 存储与共识适配

存储选择影响实验的耐久性和性能，不改变必须执行的业务检查。内存模式仍维护输入锁、预算和去重状态；NoSync 仍执行数据库事务，只是不等待同步耐久落盘。内存快照用于停机审计，不是可恢复数据库。

Comet 的应用数据库、BlockStore、WAL 和签名状态文件各有边界；不能把应用内存模式描述为“整个系统完全没有持久化”。根 README 和各实验报告分别列出配置。默认与性能实验也不是同一个配置。

原版 CometBFT 的投票轮次和法定人数保持，承诺、分片及历史修订经过适配，因此不与未修改网络直接兼容。公共读取使用原始执行版本，修订在后续已确认事实中处理；账本执行顺序与历史正文当前版本不能混用。

## 5. 跟块与完成语义

读块方访问普通 `/block`、`/block_results`、`/commit`。高度 H 的执行结果通过后续高度的结果根获得认证，所以必要的后续块仍存在；空闲不持续出空块不等于不需要结果认证块。

钱包依据成功输出更新币和移除不再需要的 TXCer；成员结合本地批准与已应用累计量回收权限；网关删除已完成待办。只有实验观察器查询成员进度，不把成员观察接口当作委员会给出的核销证明。

快速接收、公共提交、结果可验证、钱包观察、成员收尾、物理修订完成必须分别计量。单个父迟到事件可能触发更早交易的费用退款，身份绑定原付费交易，不能由触发时刻重新生成。

# 最新公共提交版本：100 笔分阶段测量

2026-09-19；代码 `3cacd61`；Mac Studio M4 Max，14 个本机节点（4 委员、2 个组织各 4 成员及 1 网关）。本轮只测量，没有改业务代码或参数。

100 笔独立最终 UTXO 跨组织付款，64 个闭环 worker；每轮新创世，10/10 ms 传播配置。组织认证、同步持久化、钱包验签保存均保留。正常付款不再向委员会提交新输出 TXCer 对象。二进制 SHA-256 已与前一轮核对。

## 口径

所有时间从付款钱包实际发起 HTTP 请求起算，交易构造和实验初始化在计时之外。P50 为原始时间戳差值的中位数，P95 按排序后 floor((n−1)×0.95) 取值；与压测摘要的下分位 P50 相差最多约 0.05 ms。本页的分段数字均来自埋点轮。

**并行路径不能相加，中位数也不能相加得到端到端时间。** 钱包收到 TXCer、网关保存、INSTALL 和公共 Submit 并行推进。除特别说明，表内 n=100；同块交易共享提案、共识、Commit 和跟块时刻，相应分位数是按交易加权，不能当成 100 个独立区块样本。本轮业务块只有 4 个。

“实际提交”指委员0的应用 Commit 返回；“钱包观察”和“成员完成观察”还包括普通区块验证、本地更新以及客户端轮询，没有委员会逐笔通知。64 个 worker 必须等各自闭环后才发下一笔，不能用 100/总耗时推断持续 TPS 上限。

## 当前判断

1. **原先的网关投递等待已经不是主要瓶颈。** 材料齐备→Submit 中位 8.18 ms，委员会接纳中位 2.10 ms，没有成员同时补投造成重复提交。
2. **若优化真实上链时间，应先看委员会连续高度的推进及共识持久化。** 本轮接纳后等待提案约 301 ms，提案后共识到执行约 309 ms；逐笔检查和规则执行分别只有约 0.62 / 0.78 ms。大块仍会累积这些逐笔成本，不能说它们与 TPS 无关。
3. **若优化快速到账，应看成员与钱包的存储等待。** 网关取证约 103 ms、钱包验证保存约 86 ms；不能把窗口大或关掉同步当作未经验证的修复。
4. 最后一笔发出后还有 0.845 s 才全部实际提交，说明短批存在尾部排空；本轮后半批延迟没有持续升高，但闭环 100 笔不足以证明长期无积压。

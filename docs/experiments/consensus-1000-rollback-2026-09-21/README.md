# 回退版本：1000 TPS 共识测试

日期：2026-09-21。Mac Studio，四个本机独立委员会进程，单个 HTTP 入口，不经过网关、组织成员或钱包快速到账路径。

## 结果

目标 1000 TPS，连续发送约 180 秒，共 180000 笔。所有交易均接纳并成功执行，四委员最终状态一致、Pending=0。

| 指标 | 结果 |
|---|---:|
| 实际发送速率 | 999.97 TPS |
| 成功接纳／成功执行 | 180000／180000 |
| 接纳失败／执行失败 | 0／0 |
| 首笔实际发送到末笔成功提交被观察到 | 180.338 秒 |
| 按上述整批时间计算的成功提交速率 | 998.13 TPS |
| 末笔发送后排空观测时间 | 0.333 秒 |
| 非空业务块／最大单块交易数 | 297／711 |
| 最终委员状态一致／未完成项 | 是／0 |

下表每行是一个连续 30 秒窗口。未完成量是该时点已发送但尚未观察到成功提交的数量，包括正常在途交易和查询观测延迟，不等同于 Comet mempool 的直接读数。

| 窗口 | 成功提交 TPS | 窗口末未完成量 |
|---|---:|---:|
| 0–30 秒 | 988.43 | 343 |
| 30–60 秒 | 991.13 | 609 |
| 60–90 秒 | 996.47 | 714 |
| 90–120 秒 | 1000.93 | 686 |
| 120–150 秒 | 994.00 | 866 |
| 150–180 秒 | 1011.00 | 536 |

本轮三个分钟内没有观察到未完成量持续增长，停发后很快排空。该结论限于本机四委员、当前实验存储模式和本轮负载，不代表无限时长或完整快速转账系统的容量上限。

## 配置与数据

- 已回退的共识代码：mempool 10000，验证缓存 8192 条／32 MiB，direct TimeoutCommit 500 ms；未包含扩大缓存、100 ms 或并行提案预验证候选。
- Comet blockstore/state/evidence 使用实验 MemDB。应用 bbolt、WAL、FilePV 维持原设置。flush/gossip 为 10 ms。
- 180000 笔输入均为创世已最终可用、互不依赖的 UTXO。两个所有者各提供 90000 笔输入；真实钱包及组织签名在计时前离线生成。没有循环使用尚未确认的输出。
- 细粒度埋点关闭。通过 health 与 block_results 观察提交，成功以执行 Code=0 和四委员最终账务审计核对；观测时间不等于精确 App.Commit 时间。
- 大型独立输入集的创世 JSON 约 134 MiB，第一次启动因超过 64 MiB 配置读取上限而失败，未开始发送交易。仅在实验构建中用 Go overlay 将启动配置读取上限放宽到 256 MiB；正式源码和共识运行路径未改变。启动失败日志与 overlay 均保留。

Mac 仓库的 `docs/experiments/consensus-1000-rollback-2026-09-21/` 保存 summary.json、build.json、运行脚本、配置读取 overlay、输入语料，以及 rollback1000-180s-run 下的 send.json、blocks.json、resources.json 和 audit.json。实验已停止，临时节点数据库已清理。

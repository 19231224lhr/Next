# E5 方案讨论摘要

日期：2026-09-24。对象：[评审两版支付系统](https://chatgpt.com/c/6aa8b2d7-b6f8-83ec-8e23-ea9f3b634e90)。本记录归纳方案及实施期间的交流，不是第三方独立复现实验；实际结果见[E5报告](README.md)。

## 第一轮：选定对照方法

发送了当前 `re/cb341ec` 的网关交付、后台 INSTALL、成员存储分类和跟块清理路径，以及拟定实验矩阵。比较“修改网关交付开关”和“测试代理暂扣下游响应”两种方案。

GPT 建议代理方案，保留真实网关 Flush 后才 Offer/Persist 的执行顺序；两组都完整读取并关闭上游响应，只对 B 暂扣给钱包的响应。接受此建议：它减少业务修改，也使比较集中在额外交付条件。但它不能模拟真实网关 handler 等待造成的槽位占用或最高容量。

B 的条件为三个不同成员实际保存完整材料，或同一付款经验证的公共成功先满足。已 Observed 的 INSTALL 空操作不能算材料副本；当前普通成功返回也不是签名复制证明。只增加实验分类观测，不能再发第二套 INSTALL。

认可 200/1000 计划 TPS、每轮 30 秒、各三次，以及 100 跳真实续花各三次。暂不注入安装延迟，不扫最高 TPS。要求报告公共先满足比例、发送背压、实际工作量和未确认输入比例，不预设收益。

## 第二轮：核对事件与身份边界

补充了共享块流在钱包 READY 前独立运行、本地 Commit 后通知、有界记录和预热容量，以及校准、超时和重试规则。GPT 认为可以定稿，并补充：

1. 公共完成必须匹配同一 Network/TxID、Fact 及经过认证的实际成功效果，不能以高度、202 或重复命令空成功替代。
2. Network+TxID 只是查找键；原签名请求及 Funding/Auth 等材料也要绑定。不同有效 QC 签名子集不要求字节一致。早到事件先认证再用于放行。
3. 单次 HTTP 取消不能清除逻辑付款的已完成位和首次时间；重试沿用已有记录。B 增加的重试和后台尝试必须统计，不能全部称为纯 INSTALL 等待。

这些意见已纳入[正式方案](e5-delivery-gate-ablation-design-2026-09-24.md)。最终范围为“同一后台实现下的交付门槛消融”，不声称完整两阶段协议等价、断电耐久性或相对外部系统性能优势。

## 实施复核：区分装置开销与条件等待

补充实际代理结构、存储分类和小规模审计结果后，GPT认可继续，要求从“代理已经具备A交付条件”计算B额外等待，并另外记录条件满足后的释放调度。不能从P50/P95直接减去校准开销；A/B必须保持同样独立的门槛观察。

这些时间点已经实现。1000档预跑B的门槛满足到释放P50仅0.009 ms、P95仅0.017 ms，说明该轮主要等待发生在门槛尚未被观测满足之前，而不是长时间持锁或漏唤醒。

## 预跑负结果：不通过增加并发掩盖少发

1000档预跑B实际发出20,232/30,000笔，已发全部完成，其余未发；原驱动误把未发也纳入排空而多等60秒。向GPT提供分时间段发送量、代理等待、计时边界和代码逻辑后，双方同意只修实验统计和排空：保持64发送worker与原交付规则不变，完整重跑正式矩阵，旧轮留作预跑。

GPT提醒，固定客户端并发下B约674笔/秒不能称为系统或INSTALL容量上限，也不能把不同实际负载下的延迟差全部解释成纯复制成本。审计只允许排除明确未发且没有任何完成记录的样本；已发失败、未知或未READY仍必须追踪，全账本和残余占用不得绕过。正式实现增加了相应测试与公共付款总数核对。

## 结果复核与合并

完整结果再次交由GPT评审后，认可其支持当前交付策略的取舍，并收紧三个表述：1000档包含客户端背压和实际INSTALL工作量变化；30.4%是三轮整链末跳READY中位数之比，不是TPS增幅；594次后继消费准确表述为“钱包尚未观察到最终确认时使用TXCer续花”，未关联父交易实际Commit时刻前，不宣称父交易尚未公共提交。README与正式报告已同步这一口径，原始数据保持不变。E5代码、报告和证据统一纳入`re`实验分支。

# 网关 HTTP/1 等待修复

2026-09-20，Mac Studio M4 Max，14 个本机节点。本次只修复网关回包后仍在 handler 中等待保存、阻挡同一连接后续请求的问题。

## 实现

完整凭证响应 Flush 后，沿用已有早期投递入口；随后由最多 **128 个后台保存任务**接管原来的 `PersistDirect`。有空位才启动 goroutine，满额则在当前 handler 中同步保存。正常请求不再等待这次磁盘提交后才归还 HTTP/1 连接。并发保存仍进入原有 Group 批量事务，没有改为一个逐笔同步保存的单 worker。

保存任务使用自己持有的完整交易材料，不依赖请求 context、请求体或 ResponseWriter。关闭时先关闭接纳、等待已有 handler，再等待后台保存，最后才关闭数据库；这也覆盖 HTTP Shutdown 超时的情况。保存错误保留交易标识。已有 `Observed` 终态检查和 outbox 幂等规则不变。

成员仍持久化后签票，钱包仍验证并同步保存后才计为快速到账。内存接管不是持久化收据；网关在保存前崩溃，仍需已有完整付款材料的持有者重新提交。本次没有引入新的耐崩溃保证。

生产改动仅位于 `cmd/gateway/direct.go` 和 `cmd/gateway/main.go`。当前 wire4 使用的 `/v3/transactions` 路径已修改，旧版 `/v1` 路径不变。

## 正式对照：48,000 笔

每轮 12,000 笔、目标 200 笔/秒、256 个快速到账名额、总未完成上限 2048；相同 48,002 输出创世、每轮新数据库及一笔预热。顺序为旧版 A1 → 新版 B1 → 新版 B2 → 旧版 A2。只有网关二进制变化。委员会 10/10 ms 传播、成员 GOMAXPROCS=16/GOGC=200、成员进度查询间隔均保持原值。

正式轮关闭逐请求及节点 timeline 埋点；两版使用同一压测程序，保留全量发送、到账和钱包阶段计时。请求预构造及保存不计入发送窗口。**快速到账从付款钱包开始 HTTP 发送，到收款钱包验证、同步保存 TXCer 完成为止。**

## 未改善的部分

完整闭环包含约 60 秒固定发送窗口，不能把 61 秒解读为单笔延迟，亦不能用这轮宣称极限 TPS 提高。新旧版均未触及 2048 总未完成上限；B1 曾三次触及快速到账名额限制，其他三轮为零。发送滞后 P95 依次为 2.93、3.23、0.91、2.78 ms。

新版后台未完成峰值更高，最老未完成采样最大值约 6.79–7.22 秒，旧版为 5.31–5.77 秒。两轮成员进度查询总数 **256,572 → 439,334（增加约 71.2%）**。各轮最终均排空，但本次没有证明后台负担下降或长期积压消失。查询暂时错误仍保留于原始报告，不能把付款全成功说成所有观察请求均成功。

后续应单独处理同步提交和观察查询的成本；本补丁没有关闭 sync、删验签、修改共识或顺带调整查询频率。

## 连接诊断与有界保存验证

另以新数据库分别跑旧版、新版各 4,000 笔诊断，固定种子随机约 1/5 请求记录前台路径。通过客户端本地 TCP 地址与网关 RemoteAddr 关联同一连接的前后请求；仅统计两端事件齐全的样本：旧版 796 条，新版 792 条。

| 请求已写出 → 网关 handler 开始 | 旧版 | 新版 |
|---|---:|---:|
| 平均 | 28.98 ms | 1.69 ms |
| 中位 | 28.91 ms | 0.05 ms |
| P95 | 67.45 ms | 10.56 ms |

取得连接 P95 两版均为 0.004 ms。旧版慢连接等待的 98.35% 与同一连接前个 handler 尚未结束的区间重合。回归测试进一步直接卡住前一笔保存：旧代码第二个同连接请求超时，新代码能在存储仍阻塞时返回有效凭证。这提供了源码、受控故障测试和实际连接时间关联三类证据。

新版这一诊断轮的 timeline 环形缓存遗漏了部分保存事件，仅捕获 3,944/4,000 条保存完成。因此**不能把时间线中的未配对开始事件当成真实未完成任务，也不能采用由不完整事件重建的任务峰值**。连接阶段只使用端点齐全的样本，正式轮全量到账记录不受此问题影响。

随后再独立跑 4,000 笔诊断，用仅存在于 Go overlay 的原子累计计数，在关机 drain 完成后输出总计：包括预热共 **4,001 个后台保存全部完成，最终 0 个在途，峰值 68/128，满额兜底 0 次**。最长一次保存任务生命周期为 338.73 ms。所有七轮网关日志均无保存失败。原子计数未进入正式生产代码。

诊断轮交易数和埋点开销与正式轮不同，其到账数据不混入 ABBA 收益；当前结果也不证明任意发送速率下都不会排队。128 后台槽满时，会有意恢复到 handler 内同步保存。

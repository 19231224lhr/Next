# 完整快速转账系统：目标 500 TPS（2026-09-21）

结论：当前配置未通过本轮 500 TPS 持续测试。正式负载在 7.886 秒因成员入口限流提前终止；不能当成 3 分钟成功，也不能用终止时的闭环平均值宣称系统容量上限。

## 配置与口径

- Mac Studio，14 个进程：4 委员、2 组织各 4 成员和 1 网关；org0 付款给 org1 钱包。独立已最终 UTXO，不包含连续转手压力。
- 使用回退后的当前工作树代码，交易池 10000。Comet 区块/状态/证据使用实验 MemDB；应用、成员、网关、钱包仍保留现有同步 bbolt 保存；所有验签保留。
- 成员 GOMAXPROCS=16、GOGC=200；关闭诊断埋点。快速到账并发 256，总未完成上限 2048。
- 计划 500 TPS × 180 秒 = 90000 笔。测试专用 Go overlay 仅放宽笔数上限与大创世配置读取上限，增加计时前准备进度输出；没有改业务代码。
- 90000 笔请求生成与同步保存均在计时前。正式时间从钱包 HTTP 发出到收款钱包验签、保存 TXCer；后台观察独立继续。
- 初次脚本把成员纯文本健康响应当 JSON，导致启动检查超时；未发交易。修正检查、重建空实验库后才进行下述正式负载，失败日志保留。

## 提前终止原因与边界

网关日志明确记录 `valid quorum unavailable`，附带两项 `member HTTP 429: LIMITED`。代码中成员前台处理名额为 128，名额已满立即返回 429。网关需要 3/4 签名，因而向钱包返回 503。压测器在首笔错误后取消整轮上下文，其他在途请求/观察随之取消。

3934 笔发送中，3801 笔取得快速凭证，另有 1 笔 503 和 132 笔 HTTP 上下文取消。报表的 `failed=87852` 包括 86066 笔根本没发出的请求与 1786 笔未完成观察，绝不是 87852 笔链上失败。`completed_per_second=272.37` 仅为提前取消前的观察闭环平均值，不是最高 TPS。

已取得快速凭证的 3801 笔后来全部成功上链；四委员状态一致，资金与原始占用记账审计通过，outbox Pending=0。部分取消请求可能已留下成员局部批准，Pending=0 不代表这些局部批准全部解除。

本轮同时观测到大量后台查询：20807 次，约 2638 次/秒。前台与后台入口使用独立名额；不能直接说进度查询抢占了前台名额。它们是否通过 CPU、GC、存储争用间接拖慢签发，需要另行定位。也不能只凭 429 判断应盲目扩大并发上限。

下一步应针对成员前台请求的名额占用时长、等待写事务、GC/调度和未及时退出的请求做短测诊断，找到入口堆满的实际原因。当前证据没有证明共识容量低于 500 TPS。

# 成员延迟备用：实现、减负效果与故障验证

2026-09-19，Mac Studio。基于 [第一步网关调度改造](../gateway-relay100-2026-09-19/README.md) 的 C 版本，公共投递与 INSTALL 各限 4 个执行位置。此次只改变成员补投策略，不更改委员会、钱包、协议对象、验签或资金规则。

## 行为

网关保存后立即提交。成员第一次 INSTALL 时，在原写事务里记录 `NextSubmitUnixNS = 当前时间 + 2 秒 + 成员编号 × 250 ms`，作为实验默认值。四成员的首投资格依次在约 2、2.25、2.5、2.75 秒后生效，实际发出还受扫描与网络调度影响。

重复 INSTALL 和重启保留已有期限；未到期的成员任务不再进入解码、验签与更新路径。到期仍未观察到可信成功区块，成员独立提交同一份封装。接收成功或失败之后仍按既有 2 秒节奏重试，直到已验证成功区块删除 outbox。没有新增主节点、选举、数据库字段或一次额外的期限写盘；现有任务也不会因升级被重新延长宽限期。

`internal/member/direct.go` 只在新 outbox 中初始化期限；`internal/gateway/direct.go` 在成员路径提前检查是否到期。网关公共提交保持立即执行，重试时间仍持久保存。纯重试时间内存化尚未实施。

## 正常对照：重复工作明显减少，总时间近似

每轮新创世状态、100 笔已最终 UTXO、并发 64、14 个进程，10/10 ms 传播；实际验签和同步持久化开启。A 为第一步 C 版本、成员立即备用投递；B 为本次延迟备用。网关、委员会、压测程序二进制完全相同，仅替换成员。执行顺序见 `series.sh`。

| 带埋点的 100 笔 | A1 | B | A2 |
| --- | ---: | ---: | ---: |
| 总 Submit 调用 | 372 | **100** | 378 |
| 成员重试更新请求 | 634 | **0** | 720 |
| 保存物理提交返回→网关首次实际 Submit，中位 | 236.45 ms | 173.58 ms | 143.98 ms |
| 全部后台完成 | 3.449 s | 3.311 s | 3.515 s |

B 的 100 次提交全部来自网关；成员跟块后直接移除待办。相对两次 A 的平均 375 次，提交调用减少约 73.3%。更新请求不等于物理写事务，不能把 634/720 全部称为 fsync。

| 关闭埋点 | A1 | B1 | A2 | B2 | A3 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全部后台完成，秒 | 3.391 | 3.449 | 3.517 | 3.542 | 3.714 |
| 快速到账 P50，ms | 224.77 | 226.86 | 155.83 | 207.17 | 204.66 |
| 快速到账 P95，ms | 250.98 | 257.16 | 191.02 | 208.08 | 237.01 |

A 三轮平均 3.541 秒，B 两轮平均 3.496 秒，仅相差约 1.3%，小于样本波动，不认定为明显提速。前台尾延迟也未被证明改善。带埋点的 B 仍有约 173.58 ms 投递等待和 45.60 ms 的 Submit 返回后重试更新耗时；这些都没有通过本次改动消失。

这轮确认的是实际重复工作减少，不能据此声称持续 TPS 提升或积压彻底解决。原有另一个实验网保持运行，机器非完全隔离；各轮无测试/编译与正式压测同时运行。交易生成不在快速到账计时内，起点仍为付款钱包发出 HTTP，终点为收款钱包验证并持久保存。整轮时间包含跟块及成员状态观察，不能当作单笔纯执行耗时。

## 故障：网关所有公共提交被拒绝

另建实验网，16 笔、并发 8。仅给网关使用一份网络配置副本，所有命令 POST 经过返回 503 的本地代理；GET 读块正常转发。成员和钱包直接访问真实委员会。该注入验证“网关无法投递”，不是整机宕机或网络分区全矩阵。

- 网关 32 次提交全部被拒绝，路径均为 `/v1/commands`。
- 成员合计提交 44 次，覆盖全部 16 笔；交易全部完成，整轮 5.990 秒。不存在网关成功提交来掩盖备用路径的情况。
- 相对于 `install_store_start`，各成员最早首投分别为 2006.52、2267.20、2507.21、2759.12 ms，符合错开期限。
- 快速到账 P50/P95 为 80.73/114.69 ms；钱包观察上链 P50 为 2803.60 ms。这是小规模故障样本，不能和 100 笔正常负载直接比较性能。

8 轮正常实验共 800 笔，加上 16 笔故障实验，全部成功。停止后审计均验证待办排空、四委员会状态一致、无资金缺口、费用与原扣额度守恒，旧逐笔证明记录未重新出现。

## 测试、复算与材料

先在旧实现看到两个预期失败：没有首投延迟、未到期成员仍解码。实现后通过。回归测试覆盖安装后期限持久化、重启/重复安装不延长、无网关时到期补投、只有接收回复但未上链时继续以相同字节重试，以及第一步的投递解耦、漏通知补扫和公共完成与迟到任务竞争。

Mac 上最终运行并通过：

```text
go test -race ./internal/member ./internal/gateway ./cmd/gateway
go test -tags=comet_v3 ./...
```

执行 `python3 analyze.py .` 重建 `relay-step2-comparison.json`。脚本逐轮校验成功数、待办排空、四委员状态、资金缺口；故障数据额外校验所有网关尝试均被拒绝、成员覆盖所有付款且没有提前首投。

`group-relay2-*/reports/` 包含完整样本、时间线、审计和故障拒绝记录。执行脚本、运行日志、测试输出、二进制 SHA-256 同目录保存；不包含节点私钥或数据库。本轮所有新实验节点已停止，原实验网未改动。

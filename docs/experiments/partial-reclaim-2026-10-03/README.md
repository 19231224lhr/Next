# 局部批准额度回收：定点验证与短回归

本轮修复一个已复现的成员资源占用缺口。原基线为 `c3b20ac`，代码提交为 `bf71c4d`，生产改动仅在成员批准、跟块和来源恢复路径，分支为 `fix/partial-approval-reclamation`。公共执行、TXCer 编码、共识和历史修复协议不变。

## 问题与修复

M0 为 T 批准并锁定输入 X，占用 100 CAL；M1/M2/M3 对消费同一 X 的 T′ 形成真实三签，并由真实委员会执行器执行。旧代码在跟块时覆盖 Candidate，但没有归还 T 的预留。修复前，组织付费、用户付费、仅 FUEL 输入冲突、赢家 INSTALL 先到四种测试均失败于 `old partial approval still occupies resource 1`，Reserved 为 100。

新规则在认证公共成功执行的跟块事务中，核对同配置、精确输入实例、不同事实/交易及原 Approval，无完整证据或经济进展矛盾后归还每项 `Cap-Applied`。`Invalidated`、首个 `SupersededBy`、独立 `InvalidatedHeight` 和原 Slice 与消费记录、游标一起提交。批准记录和其余输入锁保留，失效事实不能重新签署、INSTALL 或创建来源恢复任务。

固定四成员、三签及最多一恶意成员前提下，赢家与旧候选不可能同时拥有冲突 QC。因此回收的候选不属于资金覆盖证明中的有效证书集合。独立输入、相同 Intent 的两份 QC 不满足此条件，其责任与预留继续保留；超时、单独 INSTALL 和 HTTP 失败都不授权回收。

## 定点证据

见 [测试输出](targeted-tests.log)、[外部回归](../../../internal/member/partial_reclaim_test.go)及[内部状态守卫](../../../internal/member/partial_reclaim_internal_test.go)。

- 将每个成员 CAL 份额限制为 100：旧批准耗尽容量，新付款先因额度不足被拒绝；回收后 M0 与另外两成员能批准后继，第四成员不参与。
- 普通/用户 FUEL 输入、组织付费/用户付费、赢家 INSTALL 先到均通过；INSTALL 本身不回收。
- 同候选多输入、同块两个赢家、重复块、关库重开均只归还一次；不可变 Approval 字节相同，旧请求永久拒签。
- 仅 FUEL 输入冲突后，旧普通输入锁仍保留。故意用测试密钥构造模型之外的冲突 QC，迟到 INSTALL 仍不能复活终态。
- 已观察、Installed、outbox、Settled、Pending、Paid、Recovered、费用效果、缺批准、错误输入、同 TxID、异配置、已有第三事实消费及后项余额下溢，均拒绝且整笔跟块事务回滚。
- 失败公共结果不回收；跨组织独立输入同 Intent 的两张真实 QC，在赢家跟块后仍保留失败来源的额度及输入锁。
- 失效记录的正常结算、赔付效果与来源恢复入口均拒绝，状态不变。Schema 7 无法打开 Schema 8 成员库；本轮采用全新实验目录，不做迁移。

不新增候选集合和排序：输入遍历顺序确定，同一 Overlay 中的 Invalidated 标志完成去重。审计仍使用原 `AppliedDebits` 公式；`Outcome.Approved` 表示历史批准存在，须与新 `Invalidated` 字段一起解读。

## Mac Studio 短回归

九服务、同机、真实四委员会共识；委员会、成员、网关及块存储落盘，成员同步提交；用户自付 FUEL，钱包沿用驱动的 NoSync 配置。运行器见 [run.py](run.py)，源码与二进制指纹、配置和原始审计位于 [results.tgz](results.tgz)。逐文件核对实测源码与本地源码一致。独立目录为 `/Users/richz/lab/man/utxo-partial-reclaim-20261003`。

| 回归 | 结果 |
|---|---|
| 100 TPS，1,000 笔 | 全完成；首末实际发送跨度 9.990 s；完整闭环 10.879 s |
| 收款钱包验证并记录 TXCer | 从实际发送计，P50 157.718 ms，P95 293.306 ms |

| 两组公共/后台审计 | 四委员会同高状态一致、零缺口、付款全部关闭、outbox 排空 |

本轮是功能回归，不是新吞吐上限或性能不变性实验；没有与原版本做同配置 A/B。100 TPS 负载是同步成员存储配置，不能与早期内存模式的毫秒数直接比较。普通与链回归没有刻意触发攻击分支；修复证据来自上述定点正反例。主稿已有连续支付、混合负载与读取数据仍归冻结构建 `721800c`。

# 共识关键路径与传播间隔实验

基线为 a5987b0 的实际二进制，Mac 成员维持 GOMAXPROCS=16 / GOGC=200。
用户已授权基于证据直接进行小优化并验证。本轮使用既有配置入口，不修改
FilePV、WAL 持久边界、法定人数、交易规则或跟块验证。

调查已确认：接纳后等待通常与上一高度处理重合；提案准备后还经过提案传播、
两轮投票和同步落盘。63 笔业务执行约 5 ms，不能靠省略业务验签解释约 300 ms。

候选一：先做发送刷新 / gossip 间隔 10/10、1/10、10/1、1/1 ms 的因子对照，
所有其他程序、数据规模、持久化和共识参数保持相同。已有配置由委员启动包装脚本覆盖，
不叠加新代码。保存正式关闭埋点结果，并另外测开埋点的阶段时间。没有稳定收益就保留原值。

候选二：空闲唤醒时短时合批可能减少 1+63 的首块碎片，但会增加固有等待，
暂不与候选一混合。提前传播本机票会触及重放边界，目前也不实施。

步骤：
1. 在独立新创世目录交错运行四组配置，100 笔 / 64 闭环并发；每次执行资金、费用、
   四委员状态一致及 14 节点待办排空审计。
2. 对有收益的配置进行额外交错确认及诊断比较，统计接纳到提案、提案到执行、实际提交、
   单笔快速到账、全轮闭环及块大小。分位数不相加；交易加权分位数不是独立块样本。
3. 以较长、有明确发送速率的负载检查发送延迟、完成速率、队列随时间变化和进程CPU。
   不把短时 100 笔结果称为 TPS 上限。
4. 仅采用重复验证有收益的本机实验参数，保留未采用结果及 GPT 评审，恢复原实验链数据。

已有常驻链在实验期间正常停机，实验结束恢复原 100 笔 / 高度 7 的数据；不删除历史报告。

## 执行后的收敛

- 完成八轮 100/64 无埋点传播间隔对照、两轮 100/64 阶段诊断。
- 新发现：256/256 较大区块实际触发 P2P 限速。增加保持默认不变的可选带宽配置，
  用同二进制的 256/256 trace 配对及 4,000/256 无埋点 ABBA 单独验证。
- 两项候选均未建立稳定的整体收益，保留 10/10 ms 和默认带宽，不实施空闲合批或提前传播投票。
- 原定 9,000 笔固定速率长测在发送前因实验 JSON 超过读取上限而启动失败；修复实验编码后，
  完成上述四轮较大负载。因候选没有整体收益，不继续做采用参数所需的长稳态确认。
  本轮不声称确定 TPS 上限，也不声称完成 150/s 长稳态测试。
- 完整结果、偏差和后续方向见 README.md。

# E2 实验结果外部讨论记录

来源：[评审两版支付系统](https://chatgpt.com/c/6aa8b2d7-b6f8-83ec-8e23-ea9f3b634e90)，2026-09-23。以下是基于所提供代码与实测数据的讨论意见，不作为实验数据或独立正确性证明。

## 首对低 CAL 结果讨论

**合适，建议继续默认关闭，作为“低预算、单入口有序取证”的实验选项，而不是替代正常并发快速路径。**

这组直接支持：**闭环单位86→3203，期末部分批准65→0，本地临时占用清空。**这是从fresh状态减少新增批准碎片、改善完成能力，不是能够回收并行模式已经留下的无QC锁，也不是一般活性保证。“持续推进”应由现有时间曲线支持，不能只由最终完成数推出。

延迟解释正确：parallel只统计少数成功请求，存在明显成功样本选择；serial将额度等待和重试计入，不能据两组分位数评价纯取证速度。**serial仍只完成3203／6000，未承接全部计划负载。**

责任比例也应同时展示分子：实际触发缺失责任的单位从63增至1527，但占成功单位的比例下降。这说明完成量与责任暴露构成同时变化，**不能只凭比例下降宣称资金效率提高**。

按计划完成其他配对即可。这一对照展示的是“减少碎片占用、以队头等待换取更多完成”的取舍；尚无理由默认启用，更无需为此新增取消、优先队列或多网关机制。

## 原始矩阵解释

**整体解释准确。论文应突出三种不同边界，而不是把低档统一称为“资金不足”或“系统死锁”。**定稿前主要收紧以下四点。

### 1. 区分三类结果

**低CAL／低E：**公共责任已关闭，但不同Fact的局部批准占住成员权限，导致无法继续凑齐证书。这支持“当前并发签发、无自动取消条件下的活性边界”，不代表真实本金耗尽，也不证明委员会处理慢。

**低FUEL：**真实费用支出持续消耗授权，加上未成证预留；不是纯粹的可回收临时占用，更不能因为真实账户仍有余额就认为还能签发。

**中CAL、D=3s：**预算等待与128窗口共同形成背压；已启动1438单位最终全部完成、无部分残余，所以不是永久停滞。4562是驱动未启动单位，不是委员会执行失败。

### 2. 费用与责任统计不能只覆盖闭环单位

建议每组保留同一个漏斗：**offered→启动→父／子READY→成功Public→单位闭环→残余批准**。

例如，低FUEL费用`694942＝7393×94`，而3656个闭环单位只对应7312笔配对付款。按该组每笔94的口径，其他已公共成功但未组成完整单位的付款也必须列入，不能用“闭环单位×两跳费用”替代总账。

`88/224`和`551/1438`应明确标为**完成单位中的责任触发比例**，并列实际登记责任金额和完成率。预算等待使父先到，减少了真正受担保的子交易；这不能解释成更高资金效率或相同风险敞口下的改善。

### 3. 候选只能用新的配对轮归因

原r3父直连成员，新候选父经过网关，因此**gate效果只能比较新配对中的gate-off／gate-on**，不能直接把候选与r3的差额全部归给有序取证。

若候选减少局部批准残留，仍须同时展示新增队头等待、完成量和实际责任比例。结论限定为**fresh、单网关统一入口、合法负载下的保守准入改善**；不是多网关一般活性证明，也不治愈真实费用授权耗尽。当前配对尚未结束，不提前写“已修复”。

### 4. 单次正式轮与小序列的证明范围

每配置一次独立运行，可以报告完整时间序列和最终账目，**不能称为可重复稳定结果或统计显著差异**；交易样本多不等于独立实验多。

正常／修复费用等式、三次同封装重复提交和真实历史修订审计，支持这些指定路径的正确性与幂等性，不扩大为完整安全证明。磁盘Comet控制小序列与纯内存主矩阵分别标注。

**论文最有价值的结论是：公共责任解除、本地签署权限释放和真实费用消耗并非同一件事；有限预算下，局部批准碎片化与后台关闭延迟会产生不同的可用性后果。**当前结果已足以展示这一点，无需为使低档全绿而改取消、解锁或补资规则。

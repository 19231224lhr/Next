# 共识优化逐项对照：缓存、块间等待、提案预验证

日期：2026-09-21。实验机：Mac Studio。只测试四委员共识，不走担保组织与钱包快速到账流程。

## 结论

三个候选均未显示稳定的整批吞吐收益，全部不纳入当前源码。缓存仍为 8192 条／32 MiB，交易池仍为 10000，direct TimeoutCommit 仍为 500 ms；原有串行 ProcessProposal 保留。本轮不是一次已证明的 TPS 提升。

## 条件与计时

- 每轮 12000 笔独立的、创世已最终可用的 UTXO 输入；同一批真实签名交易，四委员每轮从相同创世状态和空验证缓存启动。
- 输入目标 2000 TPS，实际发送窗口约 6 秒；并发上限 128。
- Comet blockstore/state/evidence 使用 MemDB，应用 bbolt、WAL、FilePV 保持原设置。实际配置的 P2P 收发上限各为 51200000 B/s，flush/gossip 均为 10 ms。
- 普通测速关闭埋点；每个候选独立 A/B/A/B。计时统一为首笔实际发送到最后业务块成功提交被观察到，包含健康轮询的观测误差。成功数由 block_results 的 Code=0 和四委员账务审计核对。
- 下表是普通测速的两轮全成功对照，单位为秒。均为每轮 12000/12000 成功，四委员状态一致。它们是短突发与排空实验，不代表持续 2000 TPS 能力。

|---|---|---|---|---|
| 验证缓存 8192/32 MiB → 16384/64 MiB | 9.843、9.751 | 9.732、10.091 | 9.797 → 9.911 | 不采用 |

缓存候选另有一轮 cap-b2 出现一次 HTTP EOF：11999/12000 接纳，11999 笔全部成功提交，四委员账务一致，总观测时间 9.469 秒。该轮完整保存，随后补跑 cap-b3；不能将其标为全成功或隐藏。将这次结果也纳入缓存候选均值，差异仍很小，没有稳定提速证据。

## 诊断证据

完整逐笔埋点明显改变了工作负载：缓存原配置的诊断轮耗时 29.657 秒，候选轮 13.736 秒。该差异不能当成关闭埋点后的性能收益。后来用实验 overlay 关闭逐笔 settlement 埋点，仅保留共识阶段和每 256 次检查的累计缓存计数。代码主线没有新增此诊断开关。采样末值最多滞后 255 次检查。

轻量采样显示，原配置入口委员的完整验证未命中计数为 12000；虽然累计淘汰 3808 条，但未见入口委员反复验证同一批已淘汰交易。扩大缓存消除了这些淘汰，却未在普通测速中降低完成时间。其他委员存在少量并发冷验证重复，不能直接都归因于容量淘汰。

当前 500 ms 的确存在块间剩余等待：多个高度记录约 360–390 ms。旧文档中 100 ms 配置下“几乎没有正剩余等待”的历史结论不能套用到当前配置。但直接降为 100 ms 后产生了更多块，整体收益未稳定出现。

cap-light-a2 的高度 7 含 3902 笔交易：

- 委员 0 收到完整提案后，ProcessProposal 约 5.28 ms，但到 FinalizeBlock 开始共约 1520.77 ms。
- 其他委员收齐完整提案比委员 0 晚约 1236、1396、1248 ms；其中两名委员随后冷验证还需约 236、287 ms。
- 委员 0 的 FinalizeBlock 约 291.45 ms，应用 Commit 约 68.24 ms。
- cap-light-b 中 2953 笔的块，其他委员提案检查达到约 644–659 ms，说明只看入口委员的缓存命中检查会低估其余节点的工作。

因此，下一步优先核对大块从发送到其他委员收齐的全过程，包括 P2P 发送、接收分发、mempool CheckTx 与共识通道之间是否相互阻塞。现有证据定位到了跨节点收齐提案的时间差，尚不能将其全部归因为网络传输或某个具体函数。也不能将上述每节点耗时直接相加为共识关键路径。

## 验证与源码处理

提案并行候选先新增失败测试，确认旧实现不具备四路提案预验证；候选实现后相关包测试及并发/账务一致性竞态测试通过。错误交易仍被原 ProcessProposal 拒绝，状态执行保持原顺序。普通测速不支持保留候选，已把 parallel_check.go 恢复为修改前的精确内容；候选源码与测试作为 .go.txt 保存。恢复后委员会包测试和 go vet 通过。

实验数据位于 Mac 仓库 `docs/experiments/cache-capacity-2026-09-21/`：summary.json、comparison.json、各轮 send.json、blocks.json、audit.json、轻量阶段记录、候选 overlay 和运行脚本。临时节点均已停止，重复试验的节点数据库已清理；报告与同一批输入数据保留。

本轮基线本身与先前“约 962 TPS”短测存在波动，且计时起点不同，不能把新基线数值较高归功于本轮优化。

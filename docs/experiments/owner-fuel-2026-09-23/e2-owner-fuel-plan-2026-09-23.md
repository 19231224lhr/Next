# E2 用户自付 FUEL 复测

目标：按用户确认的业务运行 E2：用户自行支付且 FUEL 充分，组织不承担代付。旧 `e2-budget` 数据只代表 OrgReserve 分支，保留原始结果。

范围：复用协议已有 OwnerFinalUTXO、Fee.Inputs、Refund。费用输入必须是当前组织有权裁决的最终 FUEL UTXO；所有者签名覆盖费用来源、上限及退款去向。费用输入和本金输入在同一成员事务占用，委员会原子消费。自付只保留 CAL、Execution、Bytes 三项组织权限，不创建 FUEL/代付政策占用。输入总额超过上限的找零及最后未用预留均归签署的用户退款地址；由公共区块执行结果携带可验证的实际 FUEL 输出，钱包和成员正常跟块，无逐笔私有通知。

实施顺序：

- [x] 先写失败测试：真实用户扣款与退款、组织 FUEL 零支出/占用、重复提交、费用双花/错资产/错签名/非最终输入、赔付后退款与跟块。
- [x] 最小接通规则、成员原子锁定、INSTALL、委员会托管、公共 FUEL 输出、钱包按块接收；不删除旧代付分支，不调整 CAL 责任或共识。
- [x] 驱动提供显式 owner 模式，为甲乙各预置独立充分 FUEL 输入；组织 FUEL 余额和授权设零，以排除暗中代付。审计每笔实际费源、费用输入消费、找零/退款、余额守恒和零组织支出。
- [x] 单笔正常/赔付/重投控制；新分支上完成 Go 定向及完整测试、race、vet。
- [x] 从创世运行相同 20 两跳单位/秒、300 秒输入、最多 60 秒排空，CAL 和 Execution 的原低中高档及 CAL 中档父延迟 3 秒。每成员一个 Worker，其他工作权限充分。组织 FUEL 低中高耗尽不再作为本轮目标。
- [x] 保持默认并行路径；若低档仍发生部分批准积累，再以同费用来源做默认关闭的顺序入口配对，不把旧代付组与自付组冒充单变量性能对照。
- [x] 保存新结果目录、独立配置/构建指纹/费用审计与完整报告，更新索引。提交记录见分支历史。

工作量口径：自付增加一个最终费用输入，按真实输入数计 Execution；原组织授权档位保持不变并报告此差异，不为了使低档成功重新调预算。实际未确认责任比例、启动数、完成数、未成证占用分别记录。

不做：运行中补资/清锁、Worker 调配、多网关协调、全面重构、删除既有实验。最小方案是在已确定的自付协议中接通缺失的快路径，不能将组织充值或跳过费用检查当作用户付费。

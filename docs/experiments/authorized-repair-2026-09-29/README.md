## 1. 完成了什么

原来的每项缺口仍独立承担责任、扣除真实备付、核销费用；现在同一历史块内的多个来源补丁，可以通过一个 `RepairBatch` 原子提交，累计构造最终正文、共享分片适配材料。原子批中任一项目不合法，整批不产生账务效果。旧 `RepairInput` 与批入口共享义务终态，不能重复赔付。

公共账务与逻辑修订先提交。后台安装器只接收已提交的确切授权快照，可以跳过中间物理版本直接安装较新版本；它不重复扣款，也不跳过公共经济命令。真正原始块仍保存，用于按原始命令历史重放。

输入适配缓存只复用密码学计算结果，使用时重新核对资格和承诺。自动工作器有界扫描、分组和重试，与物化循环分开；不等凑批、不增加正常取证往返，不新增数据库或协调服务。详细参数见设计 §5。

## 2. 正确性与兼容性

| 已测路径 | 核对结果 |
| --- | --- |
| 40+60 两个缺失输入合并，再产生后继付款 | 修复仅改变来源表示；后继原字节和完整 BlockID 不变，无需重签 |
| 同交易 1/2/4/8 输入修复 | 逐项与合批的账户、义务、费用及到期队列经济投影一致 |
| 同一公共历史重放 | 包含批命令的原始序列重放，每高度 AppHash 一致 |
| 共享账户只够前一项、中途余额不足 | 整批拒绝，无部分扣款、结果或调用方状态泄漏 |
| 父已关闭、过期 Base、伪造分片 opening | 拒绝修复 |
| 完全重复批、关闭后重新组批、旧单项／新批双向交错 | 不再次扣款；相同成功批返回无新增效果 |
| 用户自付 FUEL、退款、迟到签署者 | 复用原跟块核销逻辑，通过回归 |
| 32 项效果、64 个费用输出的认证结果 | 成员、钱包和网关跟块成功；重复块不再次处理 |
| 物理 0→2、旧授权快照迟到 | 直达安装，旧快照不回退，原始块保留 |
| 全局 A1→B1→A2 队列 | 实际只有 2 次安装批写入；A 直达 A2，B 不遗漏 |
| 无法构造的队首、扫描尾项、租期与重投 | 游标跨过坏项；提示表有界；原字节重投不续租，公共完成后停止 |

这些是实现回归，不是全实现机械化证明。经济等价限定在相同初始状态、公共时间和项目集合、无中途父到达等外部事件的对照；它不要求逐项历史与批历史的 Revision、Task、AppHash 相同。相反，重放检查比较的是**同一条**公共历史。

## 3. 局部成本对照

Windows amd64、Go 1.27.1，真实 3-of-4 门限适配和经济规则，使用固定测试 RSA 密钥。每档运行 5 次。单项与批方案从相同状态出发；缺失输入位于同一交易、同一历史块且改动落在一个分片。下表为实际编码字节与实际分片适配请求数，每次均相同。

| 缺口数 | 公共修复命令：单项→合批 | 分片适配：单项→合批 | 命令编码总字节：单项→合批 |
| ---: | ---: | ---: | ---: |
| 1 | 1→1 | 1→1 | 3,751→680 |
| 2 | 2→1 | 2→1 | 10,978→976 |
| 4 | 4→1 | 4→1 | 35,860→1,568 |
| 8 | 8→1 | 8→1 | 127,336→2,752 |
| 8 个独立历史、每个 1 项 | 8→8 | 8→8 | 30,008→5,440 |

最后一行是每轮运行 8 个独立单块 fixture 的负对照，不是同一运行中不同高度的网络压测。它确认跨块不能合批；`k=1` 的字节减少来自紧凑命令编码。因此，8 项案例约 97.84% 的字节下降同时包含**紧凑编码和共享材料**，不能全部归因于调度。

分片适配 8→1 不表示所有密码运算 8→1：每个输入仍需独立适配和核验，每项义务仍实际扣款。表中不是总 RPC/P2P 流量，也不是磁盘字节量。原始日志中的毫秒数只作局部诊断，构造与附加检查计时窗口不同，未据此计算端到端加速比。

## 4. Mac Studio 真实网络回归

环境为 M4 Max、16 核 CPU、64 GB；Go 1.27.1；四委员、两个组织各四成员及一个网关，同机共 14 个节点。新创世，委员会应用 bbolt 与磁盘 BlockStore，保持验签及修复门限计算；Flush/Gossip 各 10 ms。正常压测钱包启用既有 NoSync 实验选项。此次沿用 `demo-v4` 的组织代付 fixture；用户自付费用另由上表跟块回归覆盖。

步骤：并发提交四个扣住父来源的两跳案例，等待真实到期赔付；随后发布迟到父；继续输入 100 TPS、10 秒、1,000 笔普通快速付款；停止节点做离线审计。

最终源码回归的[逐委员批记录](smoke-final-results/batches.txt)确认：四个节点提交同一个 `BatchID`，历史高度 1、Base 0、**4 项修复、1 条 1,568 字节命令**。不是把四次独立单项修复计作合批。四条缺口来自同块不同付款，也补充了局部同交易 fixture 之外的集成路径。

上述结果证明新批命令实际贯通取证、共识、物化及各角色跟块，且之后仍可完成正常付款；没有进行与旧版同配置成对吞吐实验，不能声称正常吞吐提高或尾延迟完全无影响。本次节点已停止。

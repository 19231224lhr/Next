# C3 补强：来源恢复、独立赔付与历史表示修复

2026-10-02 · `feat/review-source-recovery` · 旧版基线 `0e7bae5`。

**本轮把第三项贡献的两处关键能力落实到代码：公开后继提供的证据可以帮助原成员补交缺失来源；赔付与回款可以在门限适配不可用时继续执行。** 历史表示随后修复，保持后继引用及既有共识身份。

[机制设计](../../design/evidence-driven-source-repair.md) · [逐轮数据](analysis.json) · [功能 CSV](functional.csv) · [普通路径 CSV](cost.csv)

## 1. 实现内容

| 部分 | 本轮实现 | 验证方式 |
| --- | --- | --- |
| S1：公开证据补交 | 原批准保留直接输入证书；公开后继暴露父 QC 后，用原正文、准入向量与 QC 重建同一付款，复用 outbox | 原发布者不补交、不 INSTALL；三次独立网络实验自动恢复 |
| S2：经济／表示分离 | 公共 `CompensationDecision` 是唯一赔付入口；表示命令不再扣款、返费用或释放额度 | 全部适配服务暂停期间，赔付和迟到来源回款照常完成；恢复后才修复历史 |
| S3：规范表示收敛验证 | 比较同一决定集合的逐项、合批、逆序分组修复 | 真实门限 RSA、1/2/4/8 个输入、跨两个实际分片；最终正文与分片 opening 相同 |

S3 本轮保留已有 Base/Previous 和公共表示命令，没有把“相同最终表示”扩大为“无需公共授权即可任意物化”。此前合批与直达物化能力继续保留。

## 2. 实验配置与计时

- Mac Studio M4 Max，所有服务同机：4 委员、2 个组织各 4 成员与 1 网关，共 14 个服务进程。
- 每轮重新创世，450 个初始输出；原有默认磁盘实验配置，成员默认非同步写模式，委员会保留磁盘存储；普通付款压测钱包使用 `-wallet-no-sync`，两跳故障演示钱包使用默认模式。
- 传播配置两边均为 flush/gossip 10 ms。`demo-v4` 与 `bench-v4` 使用显式授权的组织代付 FUEL，保留签名和所有金额／消费校验。此处费用口径在最终版本补测时按实际驱动代码校正，历史测量数字不变；用户自付 FUEL 的实验另见对应报告。
- 功能三种处理各三轮，共 9 个独立实验。普通路径旧版／新版各三轮，顺序 AB、BA、AB，每轮输入 100 TPS、300 笔，快速并发 64、总未完成上限 256。
- 时间均从**子付款钱包实际 HTTP 发送**起算；快速到账以钱包完成证书验证和本地接收为终点。来源、赔付、历史物化时间是客户端观察值，包含轮询，不能当作内部 Commit 时刻。
- 同一轮完整闭环包含全部 300 笔的公共确认及成员跟块。发送窗口约 2.990 秒；完整闭环不是单笔付款时间，也不是最大 TPS。

## 3. 功能结果

### 3.1 原发布者不补交，能否恢复来源？

故障注入在原交易取得完整 QC 后阻止原发布者提交及 INSTALL。原签名成员持有自己的批准材料，没有完整 QC；子交易使用父 TXCer 并成功进入公共块。S1 开启时，原组织成员从该块取得缺失的 QC，重建原付款并补交。驱动的 `-recover-source` 分支**没有任何原付款 Submit 调用**。

| 重复 | 子付款快速到账 | 子付款上链观察 | 原来源自主成立观察 | 两次公共观察的差值 | 赔付 |
| --- | ---: | ---: | ---: | ---: | --- |
| 1 | 13.94 ms | 1,414.46 ms | 2,014.23 ms | 599.77 ms | 无 |
| 2 | 13.94 ms | 1,989.60 ms | 2,565.08 ms | 575.49 ms | 无 |
| 3 | 13.91 ms | 1,439.90 ms | 2,039.40 ms | 599.50 ms | 无 |

三轮审计均为 1 项 Fulfilled、0 项赔付，原组织备付未支出。**2 秒左右是后台补齐来源的观察时间；收款可续花已经在约 14 ms 完成。** 表中的差值不是从精确曝光 Commit 起算的协议延迟界。

关闭 S1 的三轮对照使用相同扣留方式和成员材料，来源没有自动成立，均在到期后进入赔付。此时驱动才主动补交迟到来源，验证原赔付组织收到回款。该对照隔离的是“是否执行公开证据补交”，不是与更强的周期扫描恢复算法作性能比较。

### 3.2 全部适配服务不可用，是否阻塞资金闭合？

三轮额外实验关闭 S1，并用同一标记暂停四个委员的输入／分片适配 HTTP 服务；共识、公共决定和正常付款处理继续运行。

| 处理 | 赔付观察，三轮 | 四委员暂停期间的状态 | 最终物化观察，三轮 |
| --- | --- | --- | --- |
| 正常适配服务 | 35.839 / 35.888 / 35.864 s | 不注入暂停 | 36.994 / 37.021 / 37.019 s |
| 四个适配服务全部暂停 | 35.837 / 35.814 / 35.891 s | 原义务均 Recovered；修复均未提交、未物化 | 42.748 / 42.736 / 42.798 s |

约 35.8 秒包括设定的 30 秒义务期限、公共时钟推进、后台调度与观察，不是密码学修复耗时。暂停组在赔付后补交迟到来源，**直到四委员都确认回款、修复仍未发生**，脚本才解除暂停。最终 24 份委员观测（6 轮×4）均确认修复提交、物化、正文改变与身份稳定。

六轮各实际支出 100 CAL，迟到来源各回收 100 CAL，最终备付恢复；未新增用户输出。暂停结束后表示修复不再次扣款或回款。`paused-observations.json` 保存解除暂停之前的四节点状态。

网络状态端点的 `IdentityStable` 检查 Hash/DataHash/TxID；完整 BlockID/PartSetHeader 的验证由物化检查及真实 Comet 集成测试补充，不能将端点布尔值单独当作全部密码学证明。

### 3.3 审计与普通付款回归

9 个功能实验均通过四委员状态哈希一致、Gap=0、Payments=Closed、全部 outbox 排空检查。恢复组和关闭恢复组各附带三轮 300 笔正常付款，共 **1,800 笔**完成。

旧版／新版独立成本对照又完成 **1,800 笔**。两组共 **3,600 笔正常付款**，另有功能场景 **18 笔父／子付款**，不将两种样本混作一个性能实验。

## 4. 普通路径开销对照

| 版本／轮次 | 快速 P50 | 快速 P95 | 公共观察 P50 | 完整闭环 |
| --- | ---: | ---: | ---: | ---: |
| 旧版 1 | 1.112 ms | 27.441 ms | 1,151.02 ms | 3.871 s |
| 新版 1 | 1.071 ms | 30.530 ms | 1,127.87 ms | 4.000 s |
| 旧版 2 | 1.096 ms | 17.951 ms | 1,101.11 ms | 3.815 s |
| 新版 2 | 1.073 ms | 22.084 ms | 1,103.89 ms | 3.845 s |
| 旧版 3 | 1.052 ms | 39.945 ms | 1,076.01 ms | 3.805 s |
| 新版 3 | 1.045 ms | 33.744 ms | 1,052.33 ms | 3.791 s |

按三轮各自统计量取中位数：快速 P50 **1.096→1.071 ms**，快速 P95 **27.441→30.530 ms**，完整闭环 **3.815→3.845 s**。所有付款发送并完成，未完成数为零，无限额阻塞。

这组短测没有显示明显的中位延迟增加，保留了尾延迟与闭环的波动。它不证明“零开销”或提高最大 TPS；普通最终 UTXO 不携带输入证书，也不能代表大量未最终输入的 `DirectParents` 存储成本。原有高吞吐成绩仍按各自冻结版本引用。

## 5. 回归测试与安全边界

Windows 与 Mac 均通过 `go test -tags comet_v3 ./...`、`go vet -tags comet_v3 ./...`；Mac 另外通过成员、修复与委员运行时的 race 检测。日志保存在本目录。

- 公共决定：未到期、错误网络／槽位／金额、备付不足被拒绝；同一决定重复无经济效果；来源先到与决定先到两个顺序均覆盖。
- 来源恢复：跨组织、多层来源、重复暴露、已观察／已有 outbox 不重建；正常验证器拒绝不匹配材料。
- 表示修复：没有成功决定不得修复；赔付后回款仍可修复；表示前后成员 Progress 与 Worker slices 不重复恢复。
- 身份与重放：真实门限适配保持完整共识身份、后继正文及预签后继引用；原始历史逐高度重放保持应用状态；逐项与不同分组的最终正文、分片 opening 相同。

S3 的有限测试支持所测参数和决定集合的收敛；一般性结论仍依赖正确的 RSA 参数生成、消息域和规范编码。没有取消门限适配服务，也没有让普通观察者自行计算陷门 opening。

## 6. 代码版本与复现

[source-manifest.json](source-manifest.json) 保存基线提交与两次上传源包哈希。9 轮功能实验使用初始实现快照；最终版增加错误位置的早期拒绝，并把到期扫描单轮上限从 8 调至 32。6 轮普通路径对照、全项目和 race 测试使用最终快照。最终源包逐文件核对与当前代码一致。

当前实验需要统一升级、重新创世，不能混用旧 414 结果与新的经济／表示结果。复现命令须在独立工作目录运行，避免覆盖已有实验目录：

```sh
# 准备当前代码及项目原有修改后 Comet 依赖，另在 baseline/ 放置 0e7bae5。

python3 docs/experiments/c3-source-repair-2026-10-02/run_cost.py --root "$PWD" > c3-cost-progress.log 2>&1
go test -tags comet_v3 ./...

```

`run_cost.py` 等待功能实验完成再构建、运行；两套实验不得同时占用端口。归档的 `c3-results/`、`cost-results/` 包括逐笔报告和全部审计结果，较大的逐笔 JSON 使用无损 `.json.gz` 保存。在仓库执行 `python docs/experiments/c3-source-repair-2026-10-02/analyze.py` 可直接读取压缩数据，重新核验并生成 JSON/CSV。

## 7. 对第三项贡献的支撑

本轮实证回答了两个具体需求：**交付失败留下的可恢复来源，不必一律等到赔付；到期责任的经济关闭，不必等待历史修复密码学服务。** 既有身份保持修复负责之后的账本表示，而非重复执行付款。

实现期间与 Claude 进行了两轮代码边界讨论，采纳了经济入口独立、表示零效果、错误位置早期拒绝以及保留公共修订链的建议。已有游标跨失败条目推进，不再另加一套冷却调度状态；原批准材料暂沿既有保留策略，未扩展历史裁剪。

若将“优于其他恢复方法”写成论文主张，还应加入同等信息条件的周期扫描基线；若主张“赔付可用性优于旧耦合版”，应补旧版在相同适配暂停下的成对测量。本报告给出当前机制的功能、故障隔离与普通路径成本证据，不把未执行的对照写成实验结论。

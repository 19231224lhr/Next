# 日志有限合并写验证

目标：验证已确认的日志批内合并写方向，保留状态顺序、字节格式、错误处理和原 Flush/Sync 边界，不改为异步确认。

方案：仅在独立候选的 GoLevelDB journal Writer 外包标准库 256 KiB bufio.Writer。Flush 排出缓冲，Sync 先 Flush 再调用原 Sync，Close 排出剩余数据并关闭底层。已有 journal.Flush 会触发其 Flush；每次数据库 Write 返回前仍按原规则把日志交给文件系统。

不改变 bbolt、共识、网关/成员逻辑，不增加恢复机制。相比修改 journal 编码器，这个包装只影响日志文件写入且复用标准库；全面异步化不在本轮范围。

1. 先测试合并次数、日志字节一致性、Flush/Sync/Close 错误顺序和有限缓冲，确认无包装时合并断言失败。
2. 在私有 LevelDB 副本实现包装，运行针对测试、委员会 race 测试和关闭重开校验。
3. 同条件 A–B–B–A：每轮新创世、200/s × 4,000 笔，关闭细分埋点。保留全量到账、闭环、派发延迟、积压及费用审计。
4. 若没有一致的整体收益，保留实验候选与结果，恢复原正式版本；若有收益，再以诊断对照确认实际减少的是写入工作，而非移动等待。

本次只做小范围优化验证；没有自动发布、提交或推送 Git。

**100 笔全部成功，最后一笔实际提交在开始发送后 2.891 秒，最后一笔被观察到成员处理完成在 3.141 秒。** 快速到账中位 170.99 ms；从各笔付款发送到该笔委员会实际提交，中位 1176.76 ms。

## 条件与计时口径

- 新创世状态，100 笔独立、已最终 UTXO 的跨组织付款，闭环并发 64；每个执行槽观察本笔后台完成后，才发送下一笔。交易构造、签名和待发请求保存预先完成，不计入发送后的到账时间。
- 本机 14 个进程：4 委员会、2 组织各 4 成员、2 网关。所有进程在同一 Mac，跨进程时间差使用这台机器的系统时钟。
- 同步持久化、全部业务验签保留；开启原有诊断埋点。传播 flush/gossip 为 10/10 ms，委员会配置中的 commit 为 100 ms。网关 Submit/INSTALL 分别 4 个并发位置；成员首次备用期限为 2 秒加编号偏移。
- 原有另一套实验网保持运行；本轮没有同时编译或跑单元测试。此结果是带埋点的单轮短批次测量，不能代表长期最大 TPS，也不能仅凭本轮相对之前的波动宣布又有性能提升。
- P50 为通常的中位数；P95 沿用压测程序的 `floor((n-1)*0.95)` 取样规则。程序原摘要的 P50 使用下中位数，所以与这里个别数值有小幅差异。
- 每项阶段先对同一笔交易求时间差，再对 100 笔求分位数。阶段分位数不能直接相加。INSTALL、钱包保存和网关后台保存互有并行；块级操作由同块交易共享，不能当成 100 次独立执行。

这是阶段时间，不是纯 CPU 用时；例如等待提案包含区块轮次与交易到达时机，提案到 Finalize 包含传播、投票和处理等待，Commit 包含存储及调度。仅靠这些总段不能进一步认定其内部根因。

网关保存的细分：开始保存到进入事务回调中位 27.18 ms，回调进入到物理事务返回 46.95 ms。保存完成到开始调度中位 185.95 ms，说明 186.21 ms 大部分发生在取得投递执行位置之前。

与此前讨论的旧口径直接对照，`outbox_persist_done → relay_enter` 本轮为 **186.16 ms**，此前为 **733.02 ms**，这个样本差值约 74.6%。不过旧标记是调用返回后的日志，可能被线程调度延迟；后续优先使用物理事务返回到实际 Submit 的口径。当前与上一次已完成成员备用优化的带埋点样本（173.58 ms）接近，不能认定此轮又改善了。

INSTALL 已经独立于公共投递。有些目标任务在公共块完成后被跳过，另有少量同目标重试，所以不能用 400 减去 RPC 数直接当成缺失证据。按现有实现，成员可依完整公共块处理，终态由跟块确认。本轮所有实际签过的交易均已完成，队列已排空。

40.88 ms 的重试状态更新仍占着 Submit 执行位置，属于后续可定位的工作；本轮未改成内存节流，也没有据此声称剩余 186 ms 能全部消除。

## 先前误解的反例：仅在删除组织授权时成立

新 TXCer 的三票不仅证明输出获得担保，也证明输入指定的组织批准本次消费。成员的未上链输入锁并不在委员会公共状态中。去掉本笔组织认证后，仅验证所有者签名、路由字段、余额和费用预授权，无法识别组织已经批准的另一笔冲突消费。

实际规则测试构造同一所有者的以下交易（不同 TxID / Intent）：

1. 原输入 100 CAL，组织为自转交易 A 签发合法 TXCer。
2. 同一用户构造未获组织批准的冲突交易 U，花费相同原输入，转回自己。
3. 当前验证器拒绝没有三票的 U。测试随后直接构造包内私有的 `VerifiedDirectPayment`，仅用于模拟删除这一验证门槛；这不是现有公开接口可利用的漏洞。
4. U 在这种反事实条件下先上链。使用 A 输出与其合法 TXCer 的子交易 C 也能上链。
5. A 到达时因原输入已花而失败。到期赔付扣除组织 100 CAL，用户持有 U 与 C 两份未消费的最终输出，共 200 CAL。

CAL 总量依然守恒，因为差额来自组织账户。这是未经组织批准的消费导致组织损失，并非同一链上输入被记账两次。已有代付授权只能授权费用，不能替代本笔本金消费授权。

测试使用现有执行与赔付规则；未改写真实区块或运行恶意网络。本轮不需要变更 CometBFT 来验证这一记账后果。

## 已按用户澄清实施的修订

保留本笔组织消费授权及其验证；不添加在线组织查询或新的签署轮次。公开对象没有本笔新 TXCer 字段。此前编码已经只传输一次三票与额度向量，输出摘要从交易正文重建，因此本次没有删除一份重复完整输出正文，也不声称省掉组织三签。

独立精简正常交易的登记：

- 不为本笔刚上链的输出预先创建 `directCoverage` / `directPromise` 再立即解除。
- 仍验证所有预算授权的身份及上限；费用、组织本地签票占用和跟块核销保持。
- 仅在输入确实缺失且有合法 TXCer 时创建对应责任。若某笔输出早已被后继交易登记，则其父交易到达时正常解除；已赔付金额不能退回。
- 保持无担保记录的正常付款、子先父后、多输出分别消费、超时赔付、迟到原交易、重复投递、四委员重放及本地额度核销的回归测试。

这部分改变公共状态摘要，已更新规则标识，使用新实验网络评估，不混用新旧执行规则。不能预先承诺 TPS 提升。

需要纠正此前结论：交易所有权证明不足以替代输入路由组织的消费裁决；“本笔认证只用于新输出担保和费用”是不完整的判断。

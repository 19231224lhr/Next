# 已就绪的本地提案与分片合并 WAL 同步

2026-09-20，Mac Studio M4 Max / 64 GB，Go 1.27.1，固定 CometBFT 0.38.26 补丁。

## 结论

完成本地提案/分片的有界合批。确实减少了需要执行的磁盘同步，六组无埋点对照中，100 笔完整闭环平均 **2.110 → 2.008 秒，缩短 4.8%**。但快速凭证到账的每轮 P50/P95 均值分别上升约 12/16 ms；本轮只能确认后台收益，不能声称所有延迟改善或稳定突破 2 秒。

本轮保留实现与原基线供后续实验比较，未替换常驻旧版实验网络。还未验证固定到达率下的持续 TPS、长时间磁盘增长或跨机网络性能。

后续已完成[前台延迟调查](../foreground-diagnosis-2026-09-20/README.md)：用原二进制补跑突发和固定速率对照。原样本退化保留，新的 20/s 固定负载下未复现上升；目前未确立合批造成稳定前台退化的因果关系。

## 修改范围与边界

- A 为上一轮已跳过干净 WAL 重复 Sync 的 `.run/wal-skip-bin`，不是最初未优化版本。
- B 为 `.run/proposal-batch-bin`，仅重新编译委员会；组织、网关、钱包及 payctl 与 A 相同。各轮 `metadata.json` 保存实际二进制 SHA-256。
- Comet 消费本地内部队列时，仅在当前高度、轮次的 Propose 阶段，把**已经就绪**的提案及分片先连续写入 WAL，再同步一次，然后按原顺序处理。队列没有下一条就立即推进，不等待凑批。
- 上限为 16 条消息、512 KiB 分片正文。使用实际缺片数限定读取范围；如果第一条就是分片，也计入缺片预算。完成块只能位于批尾，避免重排处理过程中产生的状态记录。重复/无效分片也消耗预算，只会缩短批次。
- 遇到投票、其他轮次、非本地消息或容量边界，停止合批。一条已预取的边界消息在批次处理完后，沿原单条路径持久化并执行，不重新排队。
- 写入或同步失败时，不执行任何批内消息。WAL 可能已经持久化合法前缀，恢复仍逐条重放；这不是拥有原子回滚语义的事务。
- 法定人数、验签、FilePV 签署状态持久化、投票、超时、EndHeight 原有路径均保留。

补丁来源为 `third_party/cometbft/consensus/proposal_batch.go` 和 `overlay.py`；只增加一项可选内存诊断事件 `batched proposal WAL`，不开诊断时不记录。已将代码片段及状态转换边界交给 GPT 独立评审，见 `gpt-review.json`。

## 无埋点对照

每轮从相同配置的全新创世状态启动 14 个本机进程：4 委员、2 组织各 4 成员、2 网关。100 笔独立最终 UTXO 跨组织付款，64 个闭环并发槽；sync 和全部验签保留，flush/gossip 均为 10 ms。每个并发槽会等本笔跟块和成员核销观察结束才发下一笔，因此不是固定发送速率实验。

顺序为 `A1 B1 A2 B2 A3 B3`，之后反向补测 `B4 A4 B5 A5 B6 A6`。所有结果均计入，无预热，不排除慢轮。

| 组 | A 完整闭环 / s | B 完整闭环 / s |
|---|---:|---:|
| 1 | 2.226 | 1.940 |
| 2 | 2.083 | 2.020 |
| 3 | 2.088 | 2.102 |
| 4 | 2.067 | 2.037 |
| 5 | 2.161 | 1.919 |
| 6 | 2.034 | 2.031 |
| 均值 | **2.110** | **2.008** |

| 指标 | A 六轮均值 | B 六轮均值 |
|---|---:|---:|
| 快速凭证到账 P50 / ms | 134.59 | 146.34 |
| 快速凭证到账 P95 / ms | 154.08 | 170.45 |
| 钱包确认已上链 P50 / ms | 1029.75 | 979.05 |
| 全部原签署成员完成核销观察 P50 / ms | 1091.44 | 1043.95 |
| 第一笔发送到最后一笔发送 / s | 1.111 | 1.060 |
| 最后一笔发送到整轮结束 / s | 0.998 | 0.949 |

P50/P95 一栏是**各轮分位数的算术平均**，不是合并 600 笔后的分位数。快速到账从付款钱包发送交易到收款钱包验证、保存完整 TXCer；钱包上链观察包含获取、验证区块和本地保存；成员观察包含成员跟块及压测程序查询，不是委员会向成员推送证明。完整闭环从本轮第一笔钱包发送起算，到所有交易的上述观察结束，不代表单笔交易延迟。

五组 B 更快，一组稍慢；B 有四轮仍超过 2 秒。前台代码没有修改，但与委员会共用主机、CPU 和磁盘；共享资源调度变化可能影响前台，**目前没有证据确定这就是前台退化的原因**。下一步宜单独测固定速率下的前台延迟、排队及资源占用，不能仅凭后台变快将此次视为全面性能提升。

## 正确性与故障验证

- 先执行失败测试确认原路径逐条同步（`red-test.log`），实现后变绿。
- 边界测试：已经收到部分分片、重复分片、投票边界、不同轮次、非 Propose 状态、消息与字节上限。
- 错误测试：批内第 1/2/3 条写失败和 Sync 失败时，批内消息不提前应用。
- 真实 WAL 编解码与持久 FilePV 重启重放：合法部分前缀、同步失败后完整前缀、同步后未处理、已处理提案后退出，以及首次签署 prevote 后重放复用相同签名。合批不假定失败意味着磁盘没有任何记录。
- 整个 Comet consensus 测试包、涉及 WAL/Replay/新补丁的 race 测试、项目全量测试、项目 vet 均通过，原始日志保留。
- 14 轮共 1,400 笔全部成功；每轮 4 委员状态哈希一致、14 节点待办排空、100 笔均关闭。CAL/FUEL 总额、报酬 8,400、销毁 1,000、缺口 0 均通过审计。
- 额外故障实验在已停止的 B3 网络原状态继续，不重置签署状态：暂停 committee3，其余 3 个委员完成另 8 笔交易；恢复 committee3 后四节点追平，审计 108 笔全部关闭、缺口 0、报酬 9,072、销毁 1,080，所有 outbox 为空。这是暂停/恢复验证，不是新节点状态同步或拜占庭攻击测试；不计入性能对照。
- 实验结束恢复原常驻实验网络。新增正确性与性能实验合计 **1,408 笔**，不包含单元测试构造的数据。

## 等待对照的重试口径

当前连续实验使用用户 FUEL 的 `faultSend` 路径。其失败尝试后等待 50 ms，可能来自传输、HTTP 状态或读取错误，原日志没有保存逐次错误分类。因此 300 个 wait 付款、414 次尝试不能全归因为“成员跟块落后”。114 次额外尝试引入合计 5.7 s 的请求级固定休眠下界，三个运行各自为 40/38/36 次额外尝试；失败尝试服务时间另计。不能直接从三个端到端时长扣除某个统一比例来制造“剔除重试的结果”。

正文的 13.70 倍仅为该固定配置下两种完整客户端模式的中位数比值，保留等待、取数、重试和本地处理。细分跟块时间来自实际新计时点；没有最早证据可得、纯共识时延或普遍加速比主张。

## 指纹对象与入口

[构建一致性复核](build-identity-check.json) 确认连续链、P、R 三组节点二进制、客户端及展开后的 Comet 源码相同。清单中含测试文件，309 不是生产文件数。`member` 是设置 GOMAXPROCS=16、GOGC=200 后 exec `member-real` 的 shell 包装。

版本桥的 SHA256 对象为 Git blob（LF）；实验 build.json 对象为实际构建工作树字节。Windows CRLF 与 Git LF 会造成字节摘要不同，不能据此认定逻辑改变。全部被跟踪的 overlay Git blob 摘要也单独记录。

## 冻结源码注释勘误

Comet overlay 的 `LoadOriginalBlock` 注释仍将经济扣款高度写成 RepairInput；当前实际执行在 CompensationDecision。函数读取原始材料的逻辑未受此注释影响。为保持冻结构建指纹，本轮记录勘误，不修改被测生产文件。

# CAL 增量授权与 E2 水位控制

2026-09-23，`e2-adaptive-reserve`。在用户自付 FUEL 路径上增加可选的 CAL 补资控制，不改变快速三票认证、责任终态或费用规则。正常付款仍并行处理，控制器不进入快速签发关键路径。

## 公共补资命令

`protocol.ReserveIncrease` 使用 tag **420**，签名覆盖 Network、Organization、Grant ID、ResourceKey、Previous（原授权总额）、Amount（本次正增量）及 Subject。Subject 必须等于已有授权的管理主体，身份和授权版本保持不变。只有 CAL 可使用此命令。

实验在创世时预置有限的组织外补资账户，其身份为 `ReserveFundingAccount(network, subject)`。委员会在同一状态事务中完成：

1. 验证签名、网络、原授权身份、管理主体与 Previous。
2. 从补资账户扣 Amount，组织 CAL 账户等额增加。
3. 原 Grant.Amount 增加，保存命令 ID 防重标记。

金额不足、溢出、零增量和并发旧值冲突拒绝；相同命令重放无重复入账。本命令不创建用户 UTXO，不变更已签请求，不解除原输入锁。首版每次增量都实际转入资金，适用于初始余额完全授权的 E2；不包含提款、授权缩减或未授权余额的分配策略。

这是实验中的少量管理命令，暂不单独收取 FUEL；付款费用仍完整计收，报告将补资命令与付款数量分开。补资账户的钱已计入创世资金总量，转入不是增发。

## 成员自行跟块

成功公共命令随正常区块到达成员，没有新增委员会逐笔通知。每个成员增加的签署容量为：

`delta = floor(2 × newGrant / 3) − floor(2 × oldGrant / 3)`

将这个差额分给成员已有 Worker；各 Worker 只增加 Available，Reserved、原批准、输入锁和 Generation 不重置。重复应用同一累计总额无效果，跳过中间增量则报错，由正常顺序跟块保证衔接。当前 E2 每成员只有一个 Worker，不据此评价热点调配。

钱包和网关没有这条管理命令的付款效果，不需要处理它。原签名请求引用同一个 Grant ID/Version，因此补资后可使用原始交易字节继续取证。测试覆盖已耗尽容量后的原请求重试以及原占用保留。

## 可选实验控制器

`payctl budget-v4 -reserve-max N` 启用后台控制；默认值为零，保持原实验行为。每 200ms 采样四个成员已经生效的可用 CAL 权限，取最小值 `A_min`。仅一笔授权变更在途，直到四成员均已应用才继续决策；网络重试复用同一命令。

```
H_low    = rho × h + b
H_target = 1.25 × H_low
当 A_min < H_low：
delta_G  = round_up_100(1.5 × (H_target − A_min))
```

结果受总授权上限截断。实现使用整数安全运算与上取整。参数及读数有 JSONL 日志，HTTP 接收不是生效终点。

本轮 `rho` 来自预先声明的实验输入流：20 两跳单位/秒、每笔 100 CAL，对应最多 4,000 CAL/秒签署需求；阶跃当时才更新该值，输入停止后归零。**尚未实现生产网关的入口需求估计器**，不能称为从未知用户流量中预测负载。用户数和已完成 TPS 不直接进入控制公式。

`b=200 CAL + 尚未成证的唯一请求数×100 CAL`。请求按 TxID 记一次，重试不增加计数；后半项可能与部分批准已扣占用重叠，是保守余量，不是新的账务扣款。`h=800ms` 是根据预跑选择并冻结的规划窗口，不是保证上界。

未成证请求年龄超过 30 秒停止自动追加；补资十秒仍未在全员生效报错。达到资金上限后保留正常背压，不能以清锁或无限补资改善结果。FUEL、Execution、Bytes 不由此控制器增加。

## 复现与结论边界

先使用新创世与统一二进制。`-prepare-reserve -reserve-max N` 在节点启动前一次性预置资金源；重复初始化拒绝。正式对照脚本负责准备、启动、采样、有限排空和离线审计。

见[冻结实验口径](experiments/adaptive-reserve-2026-09-23/preregister.md)和[复现脚本](experiments/adaptive-reserve-2026-09-23/reproduce.py)。不覆盖旧 E2 数据或性能基线。

动态组的组织备付少于固定组，不等于整个实验投入资本更少：例如 3,600 组织备付加 10,800 专用补资资金，仍是 14,400 总资本。报告分别列出组织余额时间积分、专用源资金、累计转入、完成量及部分批准。该功能验证 CAL 容量调节，不解决低工作权限、无限故障或长期不释放的全部活性问题。
